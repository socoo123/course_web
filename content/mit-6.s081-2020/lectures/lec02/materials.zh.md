# 第 2 讲 · C 与 GDB 书面课程资料

## §1 C：从变量走到内存

### §1.1 赋值是否复制对象？（C p.1–2）

先区分“名字的绑定改变”和“原对象的内容改变”。讲义用两个 Python 例子作对照：整数 `one = 1`，随后 `two = one; two += 1`，最终分别是 1、2；列表 `abc` 和 `abcdef` 指向同一个列表，`abcdef += [...]` 原地扩展它，两个名字看到的列表都变长。

这不是说 C 变量都具有 Python 的行为，而是引出同一个问题：**你复制的是数据，还是访问数据的地址？** 在 C 中，把一个指针赋给另一个指针，不会自动复制其指向的对象。后面的 `pointers.c` 会用多个指针修改同一数组。

### §1.2 三种常见存储期（C p.3）

| 讲义中的分类 | 常见对象 | 何时失效 | 典型错误 |
|---|---|---|---|
| 静态存储 | 文件作用域对象、带 `static` 的局部对象 | 程序结束 | 把共享的长期状态误当成每次调用独立的数据 |
| 栈上的自动对象 | 普通局部变量、局部数组 | 离开相应作用域 | 返回局部数组的地址，稍后仍访问它 |
| 动态分配对象 | `malloc` 分配的区域 | `free` 后 | 忘记释放导致泄漏；释放后继续访问 |

**编者校正：** 存储期与可见范围是两件事。函数内的 `static` 局部对象长期存在，却不因此能被整个程序直接按名字访问；文件作用域的 `static` 对象也不是跨文件公开的。普通自动对象通常放在栈上，但 C 语言不要求每个局部变量都有一个实际栈槽，编译器可能使用寄存器或消去对象。

### §1.3 地址、解引用与指针声明（C p.4–5）

`int x = 5; int *x_addr = &x;` 建立了一个指向 `x` 的指针。`&x` 取得地址；执行 `*x_addr = 6` 修改的是 `x`；再读取 `*x_addr` 得到 6。声明里的 `*` 表示变量的类型，表达式里的 `*` 才表示解引用。

- `int *x_addr` 与 `int* x_addr` 是同一个声明。
- `int *arr2[20]` 声明的是“20 个 `int *` 元素组成的数组”。
- `void *` 可以承载对象指针，使用它访问具体对象时，需要适当的类型信息。
- 指针本身也可以是对象，因此能再取其地址，形成指向指针的指针。

**编者校正：** p.4 把指针说成“64 位整数”，这是理解本课 RV64 地址的直观模型，不是通用 C 类型规则。指针与整数是不同类型；指针宽度、可用转换由实现决定。也不是任意变量都能在源码中合法取地址，例如位域不能直接取地址。p.5 的“数组其实就是指针”要按 §1.6 的数组到指针转换理解。

### §1.4 返回局部数组为什么出错？（C p.6）

讲义的 `makeABC` 在函数里建立 `char y[3] = {'a', 'b', 'c'}`，然后 `return y`。返回时传出了首元素地址，却没有延长数组的存储期；离开函数后，调用者不能再通过这个地址访问原数组。

还有一个独立问题：三个元素没有包含结尾 `\0`，即便对象仍存活，也不能把它直接当作 C 字符串交给 `%s`。这两个问题分别是**对象生命周期**和**字符串终止约定**。笔记 §2 用不同的接口设计推导怎样解决它们。

### §1.5 指针加法按元素大小移动（C p.7–8）

讲义对比两组地址计算：

| 指针 | 初值 | 执行 `++` | 再执行 `+= 4` |
|---|---|---|---|
| `char *c` | `0x100002` | `0x100003` | `0x100007` |
| `int *i`，假设 `sizeof(int) == 4` | `0x100002` | `0x100006` | `0x100016` |

最后一列是在上一列基础上继续计算。第二行先增加 4 字节，再增加 16 字节；`0x10` 是十六进制的 16。

**编者校正：** 这张表只展示步长，原例中的 `0x100002` 不满足常见的 4 字节 `int` 对齐要求，不能拿它当作合法解引用示例。有效的指针运算还受对象边界限制：通常只能在同一数组内部及其尾后一位之间移动；尾后一位可作循环终止标记，不能解引用。转成别的类型并不扩大对象范围。

### §1.6 数组、下标与边界（C p.9–11）

数组是在内存中连续排列的同类型元素。讲义用 `arr[2] = 50`、`*(arr + 2) = 50`、`2[arr] = 50` 展示下标规则：`E1[E2]` 等价于 `*((E1) + (E2))`。因此第三种写法在这个例子中合法，但日常代码不应以难读为目标。

**编者校正：** p.9 将数组名在常见表达式中的转换结果写成了数组本身的类型，应区分如下：

| 声明 | 对象的实际类型 | 常见表达式中转换成 |
|---|---|---|
| `char myString[40]` | `char[40]` | `char *` |
| `char *myArrayOfStrings[20]` | `char *[20]` | `char **` |
| `int counting[5]` | `int[5]` | `int *` |

例如对数组直接使用 `sizeof`，得到整个数组的字节大小；取 `&counting`，得到指向整个数组的指针，而不是 `int *`。数组不是一个可随意重新赋值的指针变量。

p.11 提醒 C 不自动进行普通数组下标的运行时边界检查，程序员要跟踪长度。越界访问是未定义行为，不是语言允许访问“邻居变量”的特性；可能崩溃，也可能悄悄改坏数据，不能根据一次成功运行认定合法。

### §1.7 按位运算与标志（C p.12–14）

以下按讲义使用二进制记数，省略的高位暂不显示：

| 运算 | 例子 | 作用 |
|---|---|---|
| `&` | `10001 & 10000 = 10000` | 只保留两边都是 1 的位 |
| `\|` | `10001 \| 10000 = 10001` | 任意一边为 1 就保留 |
| `^` | `10001 ^ 10000 = 00001` | 两边不同的位置为 1 |
| `~` | 五位视图中 `~10000 = 01111` | 对每一位取反 |
| `<<` | `1 << 4 = 10000`，十进制 16 | 向高位移动 |
| `>>` | `10101 >> 3 = 10` | 向低位移动 |

**编者校正：** `~` 实际作用于整型提升后的完整类型宽度，不会只翻转你写出来的五位。需要五位结果时必须再用五位掩码截取。位操作通常优先使用无符号类型；移位量必须小于该类型位宽，负数或过大的移位量无定义，带符号溢出等情况也不能按无限精度整数计算。

p.14 先定义 `flag0 = 0, flag1 = 1, flag2 = 2` 为**位号**，再组合第 0、2 位：`(1 << flag0) | (1 << flag2)` 得到二进制 `101`。

**原页笔误：** 接下来的 `if (flags & flag1)` 却把 `flag1` 当成了二进制 `010` 的掩码。按前面的定义，`flag1` 的数值实际是 1。检验第 1 位应写成：

```c
if (flags & (1U << flag1)) {
  /* 第 flag1 位已置位 */
}
```

位号与掩码不能混用。笔记 §4 用一组自测把“设置、清除、检查”连起来。

### §1.8 类型转换与 kfree（C p.15–16）

C 的显式转换写成 `(目标类型)表达式`。讲义列出 `void *` 到 `char *`，以及整数表达式或指针到 `uint64` 的转换。

在 `kernel/kalloc.c` 中，`kfree(void *pa)` 释放一页物理内存。讲义摘出下面的条件：地址必须按 `PGSIZE` 对齐，不能低于内核结束位置 `end`，也不能达到或超过 `PHYSTOP`，否则 `panic("kfree")`。

这里转换为 `uint64`，是为了按数值检查地址对齐和上界；转为 `char *` 后与 `end` 比较，使用本内核所依赖的地址布局约定。`extern char end[]` 对应的是链接脚本定义的内核结束符号。

**编者说明：** 这属于 xv6 在特定编译器、RV64 与内存布局上的系统代码，不是“任意 C 指针都可以当整数随便操作”的证明。固定 2020 快照中的检查与 slides 一致。通过这些检查也不意味着能检测重复释放等所有错误。有关分配器与页表的完整机制留给相应后续讲次。

### §1.9 头文件、定义与 extern（C p.17）

讲义建议 `.h` 放接口声明，`.c` 放实现定义；通常不要 `#include` 一个 `.c` 文件。头文件可能间接或重复被包含，include guard 可避免重复引入相同定义。

**编者校正：** `extern` 不是把某个名字“自动广播到所有文件”。其他翻译单元仍需要看到声明，链接时还必须找到相应定义。`extern int total;` 一般是声明，而不是分配第二份 `total`；普通函数声明通常已具有外部链接，不必一律加 `extern`。文件作用域 `static` 则可把对象或函数限制为本翻译单元内部链接。

## §2 GDB：控制执行并检查现场

这份讲义有 16 个逻辑页，分步揭示的幻灯片被保存为 **44 个 PDF 页**。下面合并同一逻辑页的增量内容。页码同时给出逻辑页和 PDF 页，便于回查。

### §2.1 旧版启动示例与栈表（逻辑 1–4；PDF p.1–10）

讲义封面标注 **6.828 Fall 2018，2018-09-12**。开头的作业解析是 x86 启动示例：`bootasm.S` 把 `%esp` 设为 `start`，随后 `call bootmain`；`bootmain` 从 ELF 头取得入口，将其转成无参数、无返回值的函数指针，再调用 `entry()`。

在这个 x86 示例里，`call bootmain` 先把返回地址压栈。`bootmain` 的函数序言保存 `%ebp`，把 `%esp` 复制到 `%ebp`，再保存 `%edi`、`%esi`、`%ebx`，最后 `sub $0x1c,%esp` 为局部数据留空间；调用 `entry()` 又压入一个返回地址。

原页 p.10 的表格是到达 `0x0010000c` 时的快照，按地址从高到低排列：

| 地址 | 原页的值 | 原页解释 |
|---|---|---|
| `0x7c00` | `0x8ec031fa` | **不是栈内容**，原图用红字强调 |
| `0x7bfc` | `0x00007c4d` | `bootmain()` 的返回地址 |
| `0x7bf8` | `0x00000000` | 旧 `%ebp` |
| `0x7bf4` | `0x00000000` | 旧 `%edi` |
| `0x7bf0` | `0x00000000` | 旧 `%esi` |
| `0x7bec` | `0x00000000` | 旧 `%ebx` |
| `0x7be8` 到 `0x7bd0`，每 4 字节一项 | 均显示为 0 | `sub $0x1c,%esp` 留出的 28 字节 |
| `0x7bcc` | `0x00007db7` | `entry()` 的返回地址 |

原页已实际查看，上表重排其内容。它说明栈里的数值必须结合指令及调用过程解释，不能看到一个地址就断言是返回地址。

**版本边界：** 这些固定地址、寄存器和 `bootasm.S` 属于旧 x86 环境，不是 2020 RISC-V xv6 的启动步骤。RISC-V 调用一般把返回地址放入 `ra`，不会由一条 x86 式 `call` 自动把返回地址压栈；函数是否保存 `ra` 取决于生成的代码。RISC-V 栈帧另见第 5 讲。

### §2.2 把 GDB 连到模拟器（逻辑 5；PDF p.11–12）

原讲义依靠实验目录里的 `.gdbinit` 设置 QEMU 连接，要求从实验或 xv6 目录启动 GDB；如果 GDB 拒绝自动加载，需允许相应初始化文件。2018 命令写作 `make qemu[-nox]-gdb`，不调试时用 `make qemu[-nox]`。

**2020 适配：** 已核对本课固定参考快照的 Makefile：对应目标是 `make qemu-gdb`，普通运行是 `make qemu`，这里没有 `qemu-nox-gdb` 目标。`qemu-gdb` 使用 QEMU 的 `-S` 暂停 CPU，等待调试器继续；另一个终端从同一 xv6 根目录启动支持 RISC-V 的 GDB。`.gdbinit` 从 `.gdbinit.tmpl-riscv` 生成，设置 `riscv:rv64`、远程连接与 `symbol-file kernel/kernel`。

模板写 `127.0.0.1:1234`，Makefile 会替换成依据用户 ID 计算的端口；不要脱离生成文件硬填 1234。若出现 auto-load 拒绝，按 GDB 的诊断为这份可信的 `.gdbinit` 添加确切路径。工具链安装与公共环境说明见[公共资料](#/c/mit-6.s081-2020)。本页没有执行这些命令。

### §2.3 帮助、缩写与单步（逻辑 6–7；PDF p.13–18）

不知道参数时使用 `help 命令名`。无歧义的前缀可作为缩写，例如 `c`、`co`、`cont` 都可表示 `continue`；还存在明确的别名，如 `s` 对应 `step`、`si` 对应 `stepi`。

| 命令 | 前进的单位 | 遇到函数调用 |
|---|---|---|
| `step` / `s` | 源代码行 | 尝试进入被调用函数 |
| `next` / `n` | 源代码行 | 运行完调用，在调用者继续 |
| `stepi` / `si` | 机器指令 | 跟随指令进入调用 |
| `nexti` / `ni` | 机器指令 | 越过调用，停在调用之后 |

这些单步命令可带数字指定重复次数，例如 `si 4`。空回车通常重复上条命令。编者补充：一行 C 可以对应很多指令，优化也会使源码行和机器执行顺序不完全一致；遇到断点或异常时，命令可能提前停止，`next` 并不表示被调用函数没有执行。

### §2.4 继续、返回与到达位置（逻辑 8；PDF p.19–21）

- `continue`：继续执行，直到断点等停止事件；也可用 Ctrl-C 中断。
- `finish`：运行到当前栈帧所对应的函数返回。
- `advance 位置`：朝指定位置运行，正常到达那里时停止。

编者补充：`advance` 不是无视调用边界强行跳转；如果当前帧先返回，它也会停下。它与 `set $pc = ...` 之类直接修改执行位置的操作不同。

### §2.5 断点与条件断点（逻辑 9–10；PDF p.22–26）

`break 位置` 设置断点。位置可以是函数名、`文件:行号`，或前面带星号的指令地址，如原例 `*0x7c00`、`mon_backtrace`、`monitor.c:71`。这里的名字和地址是旧版例子，应在自己的程序中换成实际符号。

使用 `delete` 删除断点，`disable` 暂时停用，`enable` 再启用。`break 位置 if 条件` 只在条件满足时停下；也可对已有断点使用 `condition 编号 条件`，讲义简写为 `cond`。

条件断点适合反复执行的代码：例如只在某个 PID、下标或输入值出现时暂停，不必每次手动略过正常情况。断点位置上的语句通常尚未执行，读变量时要分清“执行前”和“执行后”。

### §2.6 观察点：找到谁修改了数据（逻辑 11；PDF p.27–31）

`watch 表达式` 在表达式的值改变时停止。`rwatch 表达式` 则关注读取。与“到达哪一行”相比，观察点直接回答“数据在哪里改变”。

**原讲义的语法需要校正：** 原页把 `watch -l <address>` 解释为监视给定地址，还提出 `wa var` 与 `wa -l &var` 的区别。GNU GDB 手册说明：`-location`（`-l`）会求表达式的结果，取得该结果的地址，并按其类型宽度监视对应内存；表达式没有可取的地址时会报错。因此不要把 `watch -l &var` 当成普遍可用写法。

可靠的表达方式是：

```text
watch var                 # 监视变量表达式，保留其作用域语义
watch -l var              # 固定监视 var 当前所在的存储位置
watch -l *p               # 固定监视 p 当前指向的对象
watch *(int *)0x12345678   # 按 int 类型监视指定地址；需换成实际有效地址
```

`watch p` 关注指针变量自身的值，`watch *p` 关注它指向的值，二者不是一回事。`-l *p` 固定的是设置时的位置，后续 `p` 改指向不会让它跟着换对象。读观察点需要目标的硬件/远程调试支持；普通观察点也可能因硬件资源限制退回较慢的软件方式。这里的校正来自额外核对的 GDB 手册，不是虚构的课堂问答。

### §2.7 按字节看，还是按类型看？（逻辑 12；PDF p.32–34）

`x` 读取内存并按指定格式显示，例如 `x/x` 用十六进制、`x/i` 反汇编。`print` 求一个 C 表达式，并利用其类型显示结果。

原例比较 `p *((struct elfhdr *)0x10000)` 与 `x/13x 0x10000`：前者按 ELF 头的字段组织输出，比逐个看十六进制数更易读。它要求符号信息中有相应结构体定义，且地址确实指向这种对象。

编者补充：`x/数量格式单位 地址` 可以同时指定观察尺度，例如 `x/16bx p` 表示 16 个字节、十六进制显示；`x/4wx p` 表示 4 个 4 字节单元。格式改变只是改变解释与显示方式，没有转换或重写内存内容。

### §2.8 寄存器、栈帧与调用链（逻辑 13；PDF p.35–38）

- `info registers`：查看寄存器。
- `info frame`：查看当前栈帧的信息。
- `list 位置`：查看相应源码。
- `backtrace`（`bt`）：查看调用链。

讲义提到 `backtrace` 对“lab 1”有用，这指 2018 课程语境，不能据此把本课 2020 util 实验改成栈回溯实验。调试时，源码、寄存器和调用链是相互补充的证据；缺符号或栈已损坏时，显示结果可能不完整。

### §2.9 界面、修改变量与切换符号（逻辑 14–16；PDF p.39–44）

GDB 提供文本界面 TUI，可在同一窗口显示源码、反汇编或寄存器，用 `layout 名称` 切换布局。`set` 可在暂停时改变变量值，用于探索一个假设，但不会修改源码。

调试内核之外的程序时，要加载匹配的符号。讲义给的是 JOS 路径 `symbol-file obj/user/<name>` 和 `symbol-file obj/kern/kernel`，不是本课 xv6 路径。本课内核符号来自 `kernel/kernel`；用户程序符号要对应具体编译产物，如 `user/_echo`。**加载符号只帮助 GDB 解释地址，不会自动让目标切换进程、地址空间或执行该程序。**

最后三张增量页的结论是：使用 `help` 和手册；这些命令只是 GDB 功能的一小部分，值得专门花时间练习。面向一个具体错误的调试路线见笔记 §5。

## §3 pointers.c：逐阶段读代码

这份示例包含宿主机标准库头文件 `<stdio.h>`、`<stdlib.h>`，不是直接按 xv6 用户头文件编写的程序。它的目的在于展示指针与字节布局，也故意含有不安全用法。以下行号来自保存的原始 47 行文件。

### §3.1 声明与第一次打印（L1–12）

函数 `f` 建立 `int a[4]`，用 `malloc(16)` 取得动态区域并交给 `b`，另声明尚未初始化的 `int *c` 和循环变量 `i`。第一条 `printf` 打印三个地址。

在常见 `sizeof(int) == 4` 的环境里，16 字节可装四个 `int`，但更清楚的分配表达式是按元素数乘以 `sizeof *b`。`malloc` 失败返回空指针，严谨程序还应检查。**原文件在赋值之前就读取 `c`，这不是可依赖的“随机地址演示”，已经存在未定义行为。** 标准 C 的 `%p` 参数应为 `void *`；本例也没有显式做相应转换。

因此，不能宣称原程序从头执行后具有一套标准 C 保证的输出。下面只把初始化后的语句分段分析；数值表不是本次实际运行日志。

### §3.2 指针别名和下标（L14–25）

令 `c = a`，循环把数组设成 `{100, 101, 102, 103}`。`c[0] = 200` 修改的是 `a[0]`，并没有第二个数组；第 2 次打印在这个局部推演中应看到 `{200, 101, 102, 103}`。

随后 `c[1] = 300`、`*(c + 2) = 301`、`3[c] = 302` 分别修改第 1、2、3 号元素。第 3 次打印对应 `{200, 300, 301, 302}`。三种写法都通过同一个基地址定位元素；第三种写法只是交换了下标运算两边的位置。

### §3.3 指针自己移动，数组没有移动（L27–30）

`c = c + 1` 使 `c` 指向 `a[1]`。`*c = 400` 随后写入 `a[1]`，局部结果为 `{200, 400, 301, 302}`。改变的是指针变量的值，数组对象仍处在原来的位置。

### §3.4 强制按一个字节移动（L32–35）

`c = (int *)((char *)c + 1)` 先把 `c` 当作字节指针，加 1 字节，再转回 `int *`。它相对 `a` 的首地址到了偏移 5 字节处，而不是第 2 个或第 3 个 `int` 的起点。

接下来的 `*c = 500` 可能未对齐，也不再指向正常的 `int` 数组元素，属于不能依赖的 C 行为。硬件是否支持这种访问、编译器如何处理，都不能由 cast 保证。

为了看清作者想暴露的现象，可以**有条件地**做一次字节模型推演：假设 4 字节 `int`、小端序，并假设机器实际发出了从偏移 5 开始的连续 4 字节写入。400 是 `0x00000190`，301 是 `0x0000012d`，500 是 `0x000001f4`：

```text
              a[1] 的四字节       a[2] 的四字节
写前          90 01 00 00         2d 01 00 00
写入位置         f4 01 00         00
写后          90 f4 01 00         00 01 00 00
```

按这组额外假设重新解释，`a[1]` 成为 `0x0001f490`（128144），`a[2]` 成为 256，另外两项仍是 200、302。**这不是语言保证的第五行输出，也不是在 RISC-V 上实测的结果。** 示例的教学重点是：一个类型转换不能把错位的地址修成合法对象。

### §3.5 两种加 1 与函数结束（L37–47）

- `b = (int *)a + 1`：按 `int` 步长，常见环境中相对 `a` 前进 4 字节。
- `c = (int *)((char *)a + 1)`：先按 `char` 步长，相对 `a` 前进 1 字节；转回后的对齐仍可能不成立。

最后一条打印想对比这三个地址。原来保存在 `b` 中的 `malloc` 返回值被覆盖，又没有其他地方保留它，也没有 `free`，于是产生泄漏。不能用 `free(b)` 补救，因为此时 `b` 已经指向栈数组内部。`f` 返回后数组 `a` 的生命周期结束，`main` 返回 0。
