# 实验：为 xv6 实现写时复制 fork

虚拟内存提供了一层间接性：内核可以把页表项（PTE）标为无效或只读，让内存访问触发缺页异常，从而拦截访问；也可以修改 PTE，改变一个地址所指向的内容。计算机系统中有一句话：任何系统问题，都可以通过增加一层间接性来解决。懒分配实验已经给出了一个例子；本实验探索另一个例子——写时复制 fork。

## 开始实验

切换到 `cow` 分支：

```bash
$ git fetch
$ git checkout cow
$ make clean
```

## 问题在哪里？

xv6 的 `fork()` 系统调用会把父进程的全部用户空间内存复制给子进程。如果父进程很大，复制可能花很长时间。更糟的是，这些工作常常大部分都被浪费了：例如，子进程在 `fork()` 后调用 `exec()`，就会丢弃复制来的内存，而且很可能从未用过其中的大部分内容。

另一方面，如果父子都使用某个页，而且其中一方或双方会写入它，那么副本确实是必需的。

## 解决办法

写时复制（copy-on-write，COW）`fork()` 的目标，是把为子进程分配、复制物理页的工作，推迟到真正需要副本的时候；有些副本可能永远不需要创建。

COW `fork()` 只为子进程创建页表，让用户内存的 PTE 指向父进程已有的物理页，并把父子双方的用户 PTE 都标为不可写。任何一方尝试写入这样的 COW 页时，CPU 都会触发缺页异常。内核的缺页处理程序识别出这种情况，为发生异常的进程分配一个物理页，把原页内容复制到新页，再修改该进程的相应 PTE，使其指向新页，并把 PTE 标为可写。缺页处理程序返回后，用户进程就能写入自己的页副本。

COW `fork()` 也让用户物理页的释放稍微复杂了一些。同一个物理页可能被多个进程的页表引用，只有最后一个引用消失时才能释放。

## 实现写时复制（困难）

**任务：在 xv6 内核中实现写时复制 fork。修改后的内核能成功运行 `cowtest` 和 `usertests` 两个程序，才算完成。**

课程提供了 xv6 程序 `cowtest`，源码位于 `user/cowtest.c`，用于测试你的实现。它会运行多项测试；在未修改的 xv6 上，连第一项都会失败。最初会看到：

```text
$ cowtest
simple: fork() failed
$
```

`simple` 测试先分配超过可用物理内存一半的内存，然后调用 `fork()`。因为剩余物理内存不足以完整复制父进程的内存给子进程，fork 会失败。

完成后，内核应通过 `cowtest` 和 `usertests` 中的全部测试。官方给出的输出如下：

```text
$ cowtest
simple: ok
simple: ok
three: zombie!
ok
three: zombie!
ok
three: zombie!
ok
file: ok
ALL COW TESTS PASSED
$ usertests
...
ALL TESTS PASSED
$
```

> **编者注：**这是官方页面的示例输出，不是本站运行结果。原页的成功示例本来就包含三次 `three: zombie!`；这里按原样保留，不把该字符串单独当作失败判据。

### 官方建议的四步方案

1. **修改 `uvmcopy()`。**把父进程的物理页映射到子进程，不再为每个页分配新副本。清除父子双方 PTE 中的 `PTE_W`。
2. **修改 `usertrap()`，识别缺页异常。**当异常发生在 COW 页上时，使用 `kalloc()` 分配新页，把旧页复制过去，再将新页安装到 PTE 中，并设置 `PTE_W`。
3. **保证物理页在最后一个 PTE 引用消失时释放，不能提前释放。**一种好方法是为每个物理页维护“引用计数”，记录有多少用户页表引用它。`kalloc()` 分配页时把计数设为 1；fork 让子进程共享该页时增加计数；任何进程从页表移除该页时减少计数。只有计数为 0，`kfree()` 才应把页放回空闲链表。可以使用定长整数数组保存计数，但你需要自己设计下标与数组大小。例如，可以用物理地址除以 4096 作为下标；原文随后举例说，数组元素数可等于 `kalloc.c` 中 `kinit()` 放入空闲链表的所有页的最高物理地址。
4. **修改 `copyout()`。**遇到 COW 页时，采用与缺页处理相同的方案。

> **编者校注：**第 3 步末尾忠实保留了原文的容量举例，但它混用了“物理字节地址”和“页号下标”的量纲。若下标为 `pa / 4096`，容量只需覆盖最大可能页号（最大下标再加 1）；若先减去物理内存基址，则容量与下标也要采用同一偏移口径。不要照着最高物理字节地址分配同样多的整数。

### 官方提示

- 懒分配实验可能已经让你熟悉了许多 COW 需要用到的 xv6 内核代码。不过，**不要以自己的 lazy allocation 解答为起点**；请按开头的命令，从一份干净的 xv6 实验分支开始。
- 为每个 PTE 记录“这是不是 COW 映射”可能很有帮助。可以使用 RISC-V PTE 中的 RSW（reserved for software，保留给软件使用）位。
- `usertests` 会探索 `cowtest` 没有覆盖的场景，所以别忘了检查两者的所有测试都通过。
- `kernel/riscv.h` 的末尾有一些有用的页表标志宏和定义。
- 如果发生 COW 缺页异常时没有空闲内存，应终止该进程。
