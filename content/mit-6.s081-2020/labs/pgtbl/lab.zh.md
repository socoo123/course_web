# 页表实验

本实验通过观察和修改页表，简化把数据从用户空间复制到内核空间的函数。

## 开始之前

先阅读 [xv6 教材第 3 章全文](#/c/mit-6.s081-2020/lec/lec04?v=materials)，以及下面的文件：

- `kernel/memlayout.h`：内存布局。
- `kernel/vm.c`：大部分虚拟内存代码。
- `kernel/kalloc.c`：物理内存的分配与释放。

> 编者校注：官方页前两个路径写作 `kern/…`，这里按实际 xv6 目录改为 `kernel/…`。

在实验仓库切换到 `pgtbl` 分支：

```sh
git fetch
git checkout pgtbl
make clean
```

实验仓库与工具链见[公共资料](#/c/mit-6.s081-2020)。本实验依次完成以下三项任务：

| 任务 | 官方难度 | 验收要求 |
|---|---|---|
| 打印页表（Print a page table） | easy | 通过 `make grade` 的 `pte printout` 测试 |
| 每进程一张内核页表（A kernel page table per process） | hard | `usertests` 正确运行 |
| 简化 `copyin/copyinstr` | hard | `usertests` 正确运行，且 `make grade` 全部通过 |

## 任务一：打印页表

为理解 RISC-V 页表，并帮助后续调试，编写打印页表内容的函数。

### 要求与输出格式

定义 `vmprint()`，接收一个 `pagetable_t` 参数，按下面的格式打印该页表。在 `kernel/exec.c` 的 `return argc` 之前插入：

```c
if(p->pid==1) vmprint(p->pagetable);
```

这会打印第一个进程的页表。通过 `make grade` 中的 `pte printout` 测试，即可获得这一任务的全部分数。

启动 xv6 时，应看到类似输出；它描述第一个进程刚完成对 `init` 的 `exec()` 时的页表：

```text
page table 0x0000000087f6e000
..0: pte 0x0000000021fda801 pa 0x0000000087f6a000
.. ..0: pte 0x0000000021fda401 pa 0x0000000087f69000
.. .. ..0: pte 0x0000000021fdac1f pa 0x0000000087f6b000
.. .. ..1: pte 0x0000000021fda00f pa 0x0000000087f68000
.. .. ..2: pte 0x0000000021fd9c1f pa 0x0000000087f67000
..255: pte 0x0000000021fdb401 pa 0x0000000087f6d000
.. ..511: pte 0x0000000021fdb001 pa 0x0000000087f6c000
.. .. ..510: pte 0x0000000021fdd807 pa 0x0000000087f76000
.. .. ..511: pte 0x0000000020001c0b pa 0x0000000080007000
```

第一行显示传给 `vmprint` 的参数。之后，每个有效 PTE 占一行，包括指向更深层页表页的 PTE。每行用重复的 `..` 表示树中的深度，层间空格按样例保留；接着显示该 PTE 在当前页表页内的索引、完整 PTE 位值，以及从 PTE 提取的物理地址。

不要打印无效 PTE。样例中，顶层只有索引 0 和 255 有效；索引 0 指向的下一层只有索引 0 有效；再下一层有索引 0、1、2 三项。

你的物理地址可以与样例不同，但项数以及对应的虚拟地址应相同。上面的输出是官方样例，不是本站运行结果。

### 官方提示

- 可以把 `vmprint()` 放在 `kernel/vm.c`。
- 使用 `kernel/riscv.h` 末尾的宏。
- `freewalk` 的实现可供借鉴。
- 在 `kernel/defs.h` 中声明 `vmprint`，以便从 `exec.c` 调用。
- `printf` 使用 `%p`，按样例打印完整的 64 位十六进制 PTE 和地址。

### 需要回答的问题

结合教材图 3.4 解释 `vmprint` 的输出：第 0 页包含什么？第 2 页包含什么？进程在用户态运行时，能否读写第 1 页映射的内存？

## 任务二：每个进程一张内核页表

xv6 原本只有一张内核页表，在内核执行时使用。其直接映射区域中，内核虚拟地址 `x` 映射到物理地址 `x`。此外，每个进程有自己的用户页表，用户内存从虚拟地址 0 开始。因为内核页表没有这些用户映射，用户地址在内核地址空间中不能直接使用。

因此，当内核需要使用系统调用传入的用户指针，例如 `write()` 的缓冲区指针，必须先把它翻译成物理地址。本任务和下一任务的目标，是使内核能够直接解引用用户指针。

> 编者校注：直接映射并不覆盖所有内核虚拟地址；trampoline 和高地址内核栈是例外，见教材 §3.2。用户页表也有供陷阱机制使用的高地址特殊映射，不能把“用户页表”理解为每一项都允许用户访问。

### 要求

修改内核，使每个进程在内核中执行时使用自己的内核页表副本：

1. 修改 `struct proc`，为每个进程保存一张内核页表。
2. 修改调度器，使它切换进程时也切换内核页表。
3. 在这一步，每进程内核页表的映射应与原全局内核页表相同。

`usertests` 正确运行即通过这一部分。

先理解本实验开头指定的教材和代码，再修改虚拟内存代码。页表设置错误可能因为缺少映射而触发异常，也可能使读写落到错误物理页，甚至从错误的物理页取指执行。

### 官方提示

- 在 `struct proc` 中增加保存进程内核页表的字段。
- 一个合理的构造方法是改写 `kvminit` 的逻辑：创建并返回一张新页表，而不是修改全局 `kernel_pagetable`。从 `allocproc` 调用它。
- 每张进程内核页表必须映射该进程的内核栈。原 xv6 在 `procinit` 中建立所有内核栈；需要把其中一部分或全部工作移到 `allocproc`。
- 修改 `scheduler()`，把进程的内核页表装入当前核的 `satp`；可参考 `kvminithart`。调用 `w_satp()` 后，不要忘记 `sfence_vma()`。
- 没有进程运行时，`scheduler()` 应使用全局 `kernel_pagetable`。
- 在 `freeproc` 中释放进程的内核页表。
- 需要一种释放页表的方法：释放页表本身，但不同时释放叶项所指向的物理内存页。
- 可以借助 `vmprint` 调试。
- 允许修改 xv6 函数或增加函数，通常至少要改 `kernel/vm.c` 和 `kernel/proc.c`。**不得修改以下文件：**
  - `kernel/vmcopyin.c`
  - `kernel/stats.c`
  - `user/usertests.c`
  - `user/stats.c`
- 缺少映射往往导致内核缺页异常，错误信息中会出现 `sepc=0x00000000XXXXXXXX`。在 `kernel/kernel.asm` 中搜索 `XXXXXXXX`，可定位出错指令。

## 任务三：简化 copyin/copyinstr

原 `copyin` 通过软件遍历进程页表，把用户指针翻译成内核能够直接解引用的物理地址，然后读取相应内存。本任务要把用户地址的映射加入上一任务创建的进程内核页表，让 `copyin` 和处理字符串的 `copyinstr` 直接使用用户虚拟地址。

### 要求

- 把 `kernel/vm.c` 中 `copyin` 的函数体替换为对 `copyin_new` 的调用；`copyin_new` 定义在实验分支的 `kernel/vmcopyin.c`。
- 对 `copyinstr` 做相同修改，改为调用 `copyinstr_new`。
- 向每个进程的内核页表加入用户地址映射，使上述两个新函数能够工作。
- `usertests` 必须正确运行，`make grade` 的所有测试必须通过。

### 用户地址的上界

这一方案依赖用户虚拟地址范围不与内核指令、数据和设备所用的虚拟地址范围重叠。用户空间从 0 开始，而内核所需的地址位于更高处，因此能够把两类映射放进同一张内核页表。

代价是用户进程的最大大小受内核最低所用虚拟地址限制。官方页指出，xv6 启动后这一地址是 PLIC 寄存器的 **`0x0c000000`**（原文写作 `0xC000000`）。参看 `kernel/vm.c` 的 `kvminit()`、`kernel/memlayout.h` 和教材图 3.4。必须修改 xv6，防止用户进程增长到越过 PLIC 地址的范围。

> 编者校注：这是虚拟地址布局限制，不是 `PHYSTOP` 或 `MAXVA`。所有普通用户映射的地址都必须低于 PLIC；不要在 `0x0c000000` 本身建立用户页映射。固定教学参考快照另有 CLINT 映射，版本差异与核对办法见[实验指导](#/c/mit-6.s081-2020/lab/pgtbl?v=guide)「PLIC 上界与参考快照差异」。

### 官方提示

- 先让 `copyin()` 调用 `copyin_new` 并正常工作，再处理 `copyinstr`。
- 内核每次改变某个进程的用户映射，也要同步修改该进程的内核页表；修改点包括 `fork()`、`exec()`、`sbrk()`。
- 不要漏掉 `userinit`：第一个进程的用户映射也必须加入它的内核页表。
- 思考内核页表中用户地址的 PTE 应具备什么权限。官方提示指出：设置了 `PTE_U` 的页不能在内核态直接访问。
- 不要忘记前述 PLIC 限制。

> 编者校注：这里的 `PTE_U` 提示针对本实验 xv6 的访问配置。RISC-V 的 supervisor 数据访问还受 `sstatus.SUM` 控制，不能泛化为所有配置下都绝对禁止。实验要处理内核页表中的映射权限，而不是把原用户页表的 `PTE_U` 去掉。

### 与真实系统的联系

官方页说明，Linux 采用过相似技术。此前许多内核让每个进程在用户态和内核态共用一张同时含用户、内核映射的页表，以减少两种模式切换时更换页表的开销。原页接着把这一布局与 Meltdown、Spectre 一类侧信道问题联系起来。

> 编者校注：这是一段历史背景，不表示 Meltdown 与 Spectre 的成因相同，也不表示页表隔离能消除所有 Spectre 攻击。本实验仍区分用户页表和每进程内核页表。

## 选做挑战

1. 使用大页（super-pages），减少页表中的 PTE 数量。
2. 扩展实现，使用户程序能够尽可能大，也就是消除“用户程序必须小于 PLIC 地址”的限制。
3. 取消用户进程第一个页面的映射，让空指针解引用触发异常。需要把用户代码段的起点从 0 改到例如 4096 的位置。
