# 文件系统实验

本实验为 xv6 文件系统加入**大文件**与**符号链接**支持。

## 开始之前

写代码前，请阅读 xv6 教材第 8 章「文件系统」，并研究相应代码。

获取本实验的 xv6 源码并切换到 `fs` 分支：

```sh
$ git fetch
$ git checkout fs
$ make clean
```

## 大文件（Large files，难度 moderate）

本任务要提高 xv6 单个文件的最大长度。原来的文件最多包含 268 个块，即 `268 * BSIZE` 字节；xv6 的 `BSIZE` 是 1024。限制来自 inode 的地址结构：12 个**直接块号**，加上 1 个**一级间接块号**。后者指向一个能容纳 256 个块号的块，因此一共能寻址 `12 + 256 = 268` 个数据块。

`bigfile` 命令会创建它所能创建的最长文件，并报告长度：

```text
$ bigfile
..
wrote 268 blocks
bigfile: file is too small
$
```

测试失败，是因为 `bigfile` 期望创建含 65803 个块的文件，而未修改的 xv6 只支持 268 个块。

你要修改文件系统代码，使每个 inode 支持一个**二级间接块**（doubly-indirect block）。该块存放 256 个一级间接块的地址，每个一级间接块又能存放 256 个数据块的地址。这样，一个文件最多包含：

$$
256\times256+256+11=65803\text{ 个数据块}。
$$

这里是 11 而不是 12，因为要拿出一个原来的直接块号槽位，存放二级间接块的地址。

### 准备工作（Preliminaries）

`mkfs` 程序创建 xv6 的文件系统磁盘镜像，并决定文件系统的总块数。该大小由 `kernel/param.h` 中的 `FSSIZE` 控制。本实验仓库中的 `FSSIZE` 已设为 **200000 个块**。构建时，`mkfs/mkfs` 应输出：

```text
nmeta 70 (boot, super, log blocks 30 inode blocks 13, bitmap blocks 25) blocks 199930 total 200000
```

这行描述 `mkfs/mkfs` 建出的文件系统：70 个元数据块（用于描述文件系统的块）以及 199930 个数据区域块，共计 200000 个块。

实验中任何时候需要从头重建文件系统，都可以运行 `make clean`，强制 `make` 重新生成 `fs.img`。

### 要研究的代码（What to Look At）

磁盘 inode 的格式由 `fs.h` 中的 `struct dinode` 定义。重点关注 `NDIRECT`、`NINDIRECT`、`MAXFILE`，以及 `struct dinode` 的 `addrs[]` 成员。教材图 8.3 展示了标准 xv6 inode 的结构。

在磁盘上寻找文件数据的代码位于 `fs.c` 的 `bmap()`。阅读并理解它：读文件和写文件都会调用 `bmap()`；写文件时，`bmap()` 按需分配新的块来存放文件内容，也会在必要时分配间接块来存放块地址。

`bmap()` 涉及两种块号：

- 参数 `bn` 是**逻辑块号**：以文件开头为起点，表示文件内部的第几个块。
- `ip->addrs[]` 中的块号、传给 `bread()` 的块号，是**磁盘块号**。

可以把 `bmap()` 理解为将文件逻辑块号映射成磁盘块号的函数。

### 你的任务（Your Job）

修改 `bmap()`，在直接块和一级间接块之外，实现二级间接块。为新地址腾出位置，直接块必须由 12 个减少到 11 个；**不允许改变磁盘 inode 的大小**。

`ip->addrs[]` 的布局必须是：

1. 前 11 个元素指向直接数据块。
2. 第 12 个元素指向一级间接块，与原来一级间接块的作用相同。
3. 第 13 个元素指向新增的二级间接块。

当 `bigfile` 能写入 **65803 个块**，并且 `usertests` 成功运行时，本任务才算完成：

```text
$ bigfile
..................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................
wrote 65803 blocks
done; ok
$ usertests
...
ALL TESTS PASSED
$
```

`bigfile` 运行至少需要一分半钟。

### 官方提示

1. 确保理解 `bmap()`。画出 `ip->addrs[]`、一级间接块、二级间接块及其指向的一级间接块、数据块之间的关系。弄清楚为什么二级间接块会把文件最大长度增加 `256 * 256` 个块——严格说是再减 1，因为直接块数减少了一个。
2. 思考如何利用逻辑块号，索引二级间接块以及它指向的一级间接块。
3. 如果改变 `NDIRECT`，很可能还需要改变 `file.h` 中 `struct inode` 的 `addrs[]` 声明。确保 `struct inode` 和 `struct dinode` 的 `addrs[]` 元素数量相同。
4. 改变 `NDIRECT` 后，一定要创建新的 `fs.img`，因为 `mkfs` 也使用 `NDIRECT` 构建文件系统。
5. 如果文件系统因崩溃等原因进入损坏状态，请删除 `fs.img`，让 `make` 创建干净的新镜像。**在宿主 Unix 系统中删除，不是在 xv6 中删除。**
6. 每次 `bread()` 得到的块，都不要忘记调用对应的 `brelse()`。
7. 像原来的 `bmap()` 一样，只在需要时分配一级、二级间接块。
8. 确保 `itrunc` 释放文件的全部块，包括二级间接结构中的块。

## 符号链接（Symbolic links，难度 moderate）

本任务为 xv6 增加符号链接，也称软链接。它用**路径名**指向目标文件；打开符号链接时，内核沿链接找到目标文件。符号链接类似硬链接，但硬链接只能指向同一磁盘上的文件，符号链接可以跨磁盘设备。虽然 xv6 不支持多个设备，完成这个系统调用仍然很适合用来理解路径名查找。

### 你的任务（Your job）

实现系统调用：

```c
symlink(char *target, char *path)
```

它在 `path` 处创建一个新的符号链接，指向由 `target` 命名的文件。进一步的接口信息可查看 `symlink` 的 man 手册页。

把 `symlinktest` 加入 `Makefile` 并运行。只有得到下面的结果，且 `usertests` 也成功，才算完成：

```text
$ symlinktest
Start: test symlinks
test symlinks: ok
Start: test concurrent symlinks
test concurrent symlinks: ok
$ usertests
...
ALL TESTS PASSED
$
```

### 官方提示

1. 先为 `symlink` 创建新的系统调用号，在 `user/usys.pl`、`user/user.h` 中添加入口，并在 `kernel/sysfile.c` 中实现一个空的 `sys_symlink`。
2. 在 `kernel/stat.h` 中增加文件类型 `T_SYMLINK`，表示符号链接。
3. 在 `kernel/fcntl.h` 中增加 `open` 可用的新标志 `O_NOFOLLOW`。传给 `open` 的标志使用按位或组合，所以新标志不能与已有标志重叠。完成这些定义并将测试加入 `Makefile` 后，就能编译 `user/symlinktest.c`。
4. 实现 `symlink(target, path)`：在 `path` 创建指向 `target` 的新符号链接。**即使 `target` 不存在，创建也可以成功。** 需要选择保存目标路径的位置，例如 inode 的数据块。与 `link`、`unlink` 类似，成功返回 0，失败返回 -1。
5. 修改 `open`，处理路径所指对象为符号链接的情况。如果文件不存在，`open` 必须失败。如果传入了 `O_NOFOLLOW`，则打开符号链接本身，而不沿它查找目标。
6. 若目标也是符号链接，必须继续沿链接查找，直到遇到非符号链接文件。若形成环，必须返回错误。可以采用近似办法：跟随深度达到某个阈值（例如 10）时返回错误。
7. 其他系统调用（例如 `link` 和 `unlink`）**不能跟随符号链接**，它们操作的是符号链接本身。
8. 本实验不要求处理指向目录的符号链接。
