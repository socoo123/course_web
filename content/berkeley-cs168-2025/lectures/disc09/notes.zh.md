# 从配置到跨网段交付

先画出两层账本：IP 标识最终通信端点，MAC 标识当前链路上的交付对象。主线复习：[L19 ARP、DHCP、NAT](#/c/berkeley-cs168-2025/lec/lec19?v=notes)、[L7 编址](#/c/berkeley-cs168-2025/lec/lec07?v=notes)、[L2 端到端原则](#/c/berkeley-cs168-2025/lec/lec02?v=notes)。以下用“题页／解页”定位官方 PDF；先在原卷作答，再展开推导。

## 1. 协议职责辨析

### 1.1–1.2：NAT 与端口复用

定位：题 p.1；解 p.1。思考：共享地址需要谁记住连接映射？

<details><summary>展开 1.1、1.2</summary>

- **1.1：False。** 地址共享可以工作，不等于遵循严格端到端设计。NAT 在网络中间维护连接相关状态并改写地址／端口；外部主机不能仅凭内网端点地址直接建立任意连接。
- **1.2：True。** 同一公网 IP 后，不同内部连接可以对应不同公网端口。返回包必须结合传输协议及映射键查回内部端点；“端口属于应用”与“NAT 用端口区分映射”并不冲突。

</details>

### 1.3–1.5：自身配置与邻居解析

定位：题 p.1；解 p.1。

<details><summary>展开 1.3、1.4、1.5</summary>

- **1.3：DHCP，选 a。** 在本题动态配置场景中租用 IP，而非把 DNS 的名字查询当作地址分配。
- **1.4：None，选 e。** 主机从本地网卡／系统配置知道自己的 MAC；不需要向网络询问它自己是谁。MAC 也不必永远是不可修改的出厂值。
- **1.5：ARP，选 c。** 已知同一广播域中目标 IPv4 地址，查询它的 MAC。跨子网时查询的是下一跳路由器，不是远端目的主机。

</details>

### 1.6–1.8：分层与 DHCP 信息边界

定位：1.6 题 pp.1–2、解 p.1；1.7–1.8 题 p.2、解 p.2。

<details><summary>展开 1.6、1.7、1.8</summary>

- **1.6：应用层，选 e。** DHCP 承载于 UDP/IP；它配置网络层，不代表它自己属于网络层。
- **1.7：链路层，选 b。** 沿用课程分层，ARP 直接以链路帧承载、在本地链路解析地址。也有资料称它位于二／三层边界；不应因此改成本题的 IP 网络层选项。
- **1.8：官方选 b、e、g。** 对应自身 IP、默认网关 IP、子网掩码。MAC 不由这套 DHCP 配置得出，网关 MAC 仍需 ARP。

**选项歧义：** 官方未选 d“另一主机的 IP”。若把它理解为任意其他节点地址，DHCP 确实能通过选项提供 DNS 服务器 IP，且网关本身也是其他节点。官方答案采用“不能查询任意目标主机 IP”的窄义；不能推广成“DHCP 从不携带其他主机 IP”。

</details>

## 2. A 到 C：逐跳保持什么，改变什么？

已目视核对题 p.3／解 p.2 的拓扑。左网是 `1.2.3.0/24`，A 为 `1.2.3.4`，右网为 `10.20.30.0/24`，C 为 `10.20.30.10`。R 的 if2 接左网、if3 接右网；if1 仅标作其他端口，不能虚构它的地址。图中 B、D 与两个 DHCP 服务不在本次数据路径上。

### 2.1：配置交互顺序

定位：题 p.3；解 pp.2–3。先区分“客户端选择租约”与“服务器确认租约”。

<details><summary>展开 DHCP 四步账本</summary>

| 顺序 | 消息 | 发送方 | 本题答案的传递方式 |
| --- | --- | --- | --- |
| 1 | Discover | A／客户端 | 广播 |
| 2 | Offer | DHCP-1／服务器 | 广播 |
| 3 | Request | A／客户端 | 广播 |
| 4 | ACK | DHCP-1／服务器 | 广播 |

Request 的广播也让其他提供租约的服务器知道客户端选了谁。这里忠实采用官方的初次入网、四步全广播简化；实际 DHCP 的 Offer/ACK 可依标志、客户端状态等使用单播，续租 Request 也不必广播。因此不能背成协议永远四步广播。

</details>

### 2.2：先做掩码运算

定位：题 p.3；解 p.3。

<details><summary>展开子网判断</summary>

`255.255.255.0` 与 A 地址按位 AND 得到 `1.2.3.0`，与 C 地址 AND 得到 `10.20.30.0`。结果不同，A 将 IP 包交默认网关 `1.2.3.1`。比较的不是两个地址字符串是否相似，也不是 C 的 MAC。

</details>

### 2.3–2.4：解析第一跳

定位：题 p.4；解 p.3。

<details><summary>展开请求目标与广播范围</summary>

- **2.3：** A 询问 `1.2.3.1` 对应的 MAC，R 的 if2 返回 `a1:b1:c1:d1:e1:f1`。ARP 请求给出 IP，回复建立 IP→MAC 绑定，而不是“请求某个已知 MAC 的 IP”。
- **2.4：** 请求在左侧广播域广播；R 已从请求中知道 A 的 MAC，所以回复给 A 单播。路由器不会把左网 ARP 广播直接扩散到 C 所在的右网。

</details>

### 2.5：第一帧的四个地址

定位：题 p.4；解 p.3。

<details><summary>展开 A→R 地址账本</summary>

| 字段 | 值 | 原因 |
| --- | --- | --- |
| 源 IP | `1.2.3.4` | 原发送者 A |
| 目的 IP | `10.20.30.10` | 最终接收者 C |
| 源 MAC | `a1:a2:a3:a4:a5:a6` | A 的接口 |
| 目的 MAC | `a1:b1:c1:d1:e1:f1` | 当前下一跳 if2 |

不要把目的 IP 改成 `1.2.3.1`：默认网关只是负责继续转发，不是应用接收端。

原图地址勘注：A 和 R/if2 的 MAC 都以 `a1` 开头，最低位 I/G=1，按真实以太网语义是组地址，不能作为这里的普通单播接口源地址。本题沿用它们作为图中对象标签以对照官方答案，不应把这些值直接用于真实配置。

</details>

### 2.6–2.7：R 的转发决策与右网 ARP

定位：题 p.4；解 p.4。

<details><summary>展开接口选择与剩余报文</summary>

- **2.6：** R 对目的 IP 做最长前缀匹配；题设收敛后的转发表中，`10.20.30.0/24` 对应 port 3／if3。ARP 表不负责选择网络层出口。
- **2.7：** 起始无 ARP 缓存，所以 R 在右网广播询问 `10.20.30.10`；C 单播返回 `ca:cb:cc:cd:ce:cf`；R 再将 IP 包装入面向 C 的新以太网帧发送。请求、回复、数据帧三项都不能漏。此处不额外添加题目未要求的应用响应或 TCP ACK。

</details>

### 2.8：第二帧的四个地址

定位：题 p.5；解 p.4。

<details><summary>展开 R→C 地址账本</summary>

源 IP 仍是 `1.2.3.4`，目的 IP 仍是 `10.20.30.10`；源 MAC 改为 R 的 if3：`a8:b8:c8:d8:e8:f8`，目的 MAC 为 `ca:cb:cc:cd:ce:cf`。R 的 if3 IP 是 `10.20.30.1`，但它不会替换转发包的源 IP。本节没有 NAT；IP 地址保持并不表示整个 IP 首部逐字节保持，TTL 等字段会变化。

</details>

## 3. NAT：从回包反推映射

定位：3.1–3.2 题 p.6；解 p.5。先写出唯一需要的状态：

`192.168.1.10:56789` ↔ `203.0.113.5:60000`

### 3.1：出站改写

<details><summary>展开外侧看到的四元组</summary>

源为 `203.0.113.5:60000`，目的为 `8.8.8.8:443`。因为题中 B 的回包目的已经明确是公网端点 `203.0.113.5:60000`，这就是 A 的内部源端点被映射后的结果。NAT 不把目的服务器的 443 也改成 60000。

</details>

### 3.2：入站反向改写

<details><summary>展开内侧收到的四元组</summary>

源保持 `8.8.8.8:443`，目的恢复为 `192.168.1.10:56789`。映射表使多个内网主机能共享公网地址，同时也成为连接生存所依赖的中间状态。实际改写还必须维护相关校验和，但这不改变本题四个字段的答案。

</details>
