# 距离向量实验指南：把状态变化与消息变化分开

写这个实验最容易犯的错误，是把三个不同对象混成一个：**我当前选择的路由**、**我准备告诉某个邻居的距离**、**我上次已经告诉它的距离**。先把它们区分开，十个阶段才不会变成相互冲突的条件堆叠。

本文提供代码地图、推理示例与排错顺序，不提供函数实现或可提交伪代码。具体限制、全部阶段任务、ZIP hash 和命令见[实验说明](#/c/berkeley-cs168-2025/lab/routing?v=zh)。理论先修是 [L4](#/c/berkeley-cs168-2025/lec/lec04?v=notes)、[L5](#/c/berkeley-cs168-2025/lec/lec05?v=notes)、[L6](#/c/berkeley-cs168-2025/lec/lec06?v=notes)，不是官网遗留编号下的 L6–7。

## 1. 只在自己的路由器里保存必要状态

### 代码阅读地图

| 文件/位置 | 应理解什么 | 不应做什么 |
| --- | --- | --- |
| `dv_router.py` 构造函数 | 互斥断言、启动计时器、创建端口表和转发表；10A 可添加实例历史 | 不删除已有逻辑，不新增 import 或硬编码全局状态 |
| `add_static_route`、`handle_data_packet` | 第一部分：建立直连事实、消费转发表 | 不把数据包当控制消息，不洪泛代替路由 |
| `send_routes` | 第三阶段起逐步增加出口策略、阈值和历史比较 | 不为每种开关组合复制整个发送器 |
| `handle_route_advertisement` | 候选成本、接受规则、寿命、10A 触发 | 不保存题目未要求的整张邻居距离矩阵 |
| `expire_routes` | 删除或 poison；由框架调用 | 不引入真实时钟或独立计时线程 |
| `handle_link_up/down` | 框架已更新端口表；10B 补路由动作 | 不二次删除端口，不把离线端口当收件人 |
| `cs168/dv.py` | `TableEntry` 不可变、表验证、`send_route`、基类回调 | 不改接口和测试；旧注释不等于正确规范 |
| `dv_unit_tests.py` | 测试配置、输入事件、表/消息断言、累计运行入口 | 不改断言、不开测试后门 |
| `sim/api.py` 与 `sim/core.py` | 模拟时间和发送接口由框架绑定 | 不因 API 中出现 `pass` 就自行实现模拟器 |

`Table` 要求键是主机对象，值是 `TableEntry`，条目里的 `dst` 与键相同。一个目的地只有当前选中的条目；**没有自动保存的第二名**。旧路径变差时，不会凭空“回退到曾听说过的另一条路”，须等另一邻居再次提供可接受通告。

路由通告 `RoutePacket.destination` 是被通告的目的地，`RoutePacket.dst` 是消息包自身的目的地址；不要混淆。基类已经把前者拆成 `route_dst` 传给学生方法。

### 三个状态对象

1. 转发表：目的地 → 本地所选出口、总代价、到期时刻。
2. 出口视图：给定目的地与收件端口，根据分割/毒性逆转/阈值得到“本次不发”或一个通告距离。
3. 发送历史：端口与目的地 → 上次**实际发送**的距离。

第一项可以因刷新寿命而改变，但第二项不变。第二项可以因出口策略而与第一项不同。第三项只有实际发出后才有新事实。用这三个句子审查设计，比先写嵌套分支更可靠。

## 2. Stages 1–2：先检查数据面的不变量

- 直连主机成本为该端口链路成本，不是零；`FOREVER` 只表示不过期，不表示链路永远不会断。
- 数据包只按 `packet.dst` 查一次当前选择，发送到表中端口。
- 无条目、总代价为 100、总代价大于 100，都意味着不发送。
- 入端口不决定最优出口。hub 的“所有非入端口”逻辑不能搬过来；水平分割也是控制面的规则，不能当作数据包过滤条件。
- 不能直接给 `entry.latency` 赋值；它是不可变条目。设计任何状态变化时都列出四个字段，避免把 `expire_time` 丢掉。

官方 Stage 2 文字有“链路距离”歧义，实际 `TestForwarding` 的两个不可达距离用例把目的地表项设成不可达后要求零发送。故要检查的是**路由总代价**。测试名：

```text
test_infinity
test_bigger_than_infinity
```

## 3. Stages 3–4：用事件表推导更新，而不是死记最短路

设路由器 R 当前到 H 的条目为：出口 p、总代价 9、到期时刻 40；p 的链路代价 2，另一个端口 q 的链路代价 4。现在模拟时间为 30。

| 收到的消息 | 候选总代价 | 应观察到的状态 |
| --- | --- | --- |
| q 通告 H 距离 5 | 9 | 等价异端口，保持 p 和原到期时刻 |
| q 通告 H 距离 3 | 7 | 更优异端口，换到 q，刷新寿命 |
| p 通告 H 距离 12（以初始状态为起点） | 14 | 当前下一跳变坏，仍接受并刷新寿命 |
| p 通告 H 距离 7（以初始状态为起点） | 9 | 距离相同但来源可信，刷新寿命 |
| 未知目的地 J，经 q 通告 100 | 104 | 接受首次信息，但 J 不可用于数据转发；对外距离最多 100 |

这些行是独立场景，不是连续执行。刷新寿命后为 45，即当前时间 30 加 15，而不是给旧到期时间加 15。

为什么当前下一跳的坏消息必须接受？旧值 9 正是依赖这个邻居的承诺得到的；承诺撤回后，保留旧值不是“择优”，而是保留不存在的路径。为什么异端口的坏消息不能刷新原条目？它不能证明原下一跳仍然拥有路径。

发送与接收的成本边界也要对称：发送自己的总代价；接收方只加**接收链路**一次。不要在发送时为每个接收者加一遍，再让对方继续加。

相关静态测试定位：`TestHandleAdvertisement.test_ties`、`test_update_same_port_shorter/longer`、`test_update_alternate_port_shorter/longer`；不同端口等价不替换，同端口变坏仍替换。框架测试使用小数链路成本，不能假设代价总是整数。

## 4. Stage 5：时间是模拟状态，不是等待动作

`api.current_time()` 在模拟器中被绑定到事件时间。单测在 `_set_up` 中替换这个接口，并让 `time.time()` 直接抛错；因此“睡一会儿等过期”既不必要，也会破坏确定性。

思考三条记录：A 到期 49，B 到期 55，C 到期 `FOREVER`。在时间 50 扫描，应只影响 A。读取字典视图时同时删除可能造成迭代错误：设计时先决定怎样安全地确定待改变的键，而不是修改模拟器或捕获异常掩盖错误。

到期边界必须单独注明：骨架 `has_expired` 写的是 `current_time() > expire_time`；已有阶段用例没有断言恰好等于时的行为。不要把“测试了 110 > 109”夸大成“官方验证了所有等号边界”。此外，`cs168/dv.py` 顶层导入过 `current_time`，而单测 patch 的是 `sim.api.current_time`；学生代码应遵循题面明确要求使用 `api.current_time()`，不要依赖导入绑定的辅助属性绕过受控时钟。

基类 `handle_timer` 已经执行“过期 → 全量通告”。后面 Stage 10 不应在 `expire_routes` 中随意增加一次全量发送，否则同一次定时事件会重复发送，`test_expire_no_duplicate*` 就是在检查这种问题。

## 5. Stages 6–8：出口视图与本地可达性不是一回事

设 R 到 H 的有效距离为 11，当前出口 p，另一个出口 q：

| 模式 | 对 p 的通告 | 对 q 的通告 | R 本地到 H 的距离 |
| --- | --- | --- | --- |
| 两种规则都关 | 11 | 11 | 11 |
| Split horizon | 不发送 | 11 | 11 |
| Poison reverse | 100 | 11 | 11 |

这是“同一条路由，对不同收件人表达不同内容”。水平分割的省略不是值 0；毒性逆转的 100 不能写回本地表。`force=True` 只绕过增量抑制，不绕过水平分割、毒性逆转或距离上限。

若内部总代价增长到 106，对所有允许发送的出口通告最多 100，同时数据面丢弃到 H 的包。对外封顶和对内判不可达共同构成不变量；仅做前者仍会把数据送进坏路径。

两节点相互依赖可以靠 split horizon / poison reverse 缓解，更长环仍可能计数上升。将无穷设为有限阈值是在限制坏信息的增长，不是重新获得完整拓扑知识。不要把实验写成 Dijkstra，也不要引入 TTL 控制来冒充正确路由更新。

## 6. Stage 9：poison 是要传播的一条负面事实

比较三种动作：

- **删除**：本机不知道 H，没有条目可供周期发送。
- **过期 poison**：本机保留 H 不可达的条目，距值 100，保留原出口，设置新的有限寿命。
- **Poison reverse**：本机仍可能到达 H，只是对一个邻居说不要经我走；只作用于通告视图。

时间 80 发现 H 的路由已过期、`POISON_EXPIRED=True`，新 poison 的到期点应是 95，而不是旧到期点再加 15，也不是 `FOREVER`。Stage 9 的测试还检查下一个定时周期继续发 poison，以及收到可用路径后停止对其他端口宣称不可达。

官网允许、但不评分的“最终删除长期 poison”不应妨碍必需的周期传播。先确保过期模式关闭时仍保持 Stage 5 的删除行为，再讨论可选优化；不要自行扩展协议状态机改变题目的可观察行为。

## 7. Stage 10：把增量定义在接收者看到的消息上

### 四个容易误判的案例

**案例 A：只刷新到期时间。** 同一下一跳重复通告相同距离。表的新到期时间应更新，但各端口将听见的距离没变，因此增量发送应为空。

**案例 B：路径变短，毒性逆转没变。** 原来经 p、总代价 11；现在仍经 p、总代价 8。q 会从 11 听到 8；p 上次已经听到 100，本次还是 100，不能重复发 poison。`test_shortest_route_shorter_poison` 覆盖这种差别。

**案例 C：出口改变而距离不变。** 同一下一跳先宣布变坏后，另一端口给出可接受路径，可能回到旧数值但出口不同。毒性逆转的接收者变了，不能仅用目的地的全局“距离是否改变”判定。即使 q 已收到某值，也不能代替 p 的历史。

**案例 D：历史尚未建立。** 测试有直接设置转发表的场景。一次触发发送不只是“刚更新的目的地”，还应考虑从没向相应端口发送过的其他条目。增量定义是与实际发送历史比较，不是与最近编辑名单比较。

历史应存最后真正发出的值：包括封顶后的 100、毒性逆转的 100、强制周期发送的值、新端口全量同步的值。被 split horizon 抑制的条目没有发生发送，不应记成“发过正常距离”。时间戳不属于距离通告消息内容。

### 三个参数组合的意义

| 调用意图 | 范围 | 是否按历史过滤 |
| --- | --- | --- |
| 周期刷新，`force=True` | 所有当前端口 | 否，但仍遵守出口策略 |
| 表变化触发，`force=False` | 所有当前端口 | 是 |
| 新邻居同步，指定 `single_port` 且全量 | 仅新端口 | 否，避免旧历史妨碍同步 |

`single_port=0` 仍是指定了一个端口。端口编号不是布尔开关。同一端口编号以后重连时，也不能把新邻居误当成已经同步过的旧邻居；全量单端口同步应真正完成同步。历史只服务于抑制重复，不能阻止恢复连接后的必要信息。

### 链路事件与触发去重

断链时先依赖骨架移除端口，之后只处理选用该端口的路由。若 poison 模式关，删除，不制造额外不可达消息；若开，替换受影响条目，再做一次增量传播。已经通过上次断链发过的 poison，不应在下一条无关断链中又被当成新变化重复发。检查多轮事件的测试名：

```text
test_link_down_advertise_poison_incremental_multiple
```

某端口断开却没有任何路由依赖它，不该产生一轮无意义广播。正常目的地也不应因为别的目的地失效而重发。反之，`force=True` 的周期刷新仍会把正常路由和 poison 的完整出口视图都发出去。

触发更新减少响应延迟，周期更新提供修复与刷新。二者是互补，不是二选一。不要修改定时器频率来掩盖遗漏的触发逻辑，也不要在多个 helper 里分别广播造成重复。

## 8. 按失败形态定位，不按分数猜补丁

| 观察到的差异 | 优先检查 |
| --- | --- |
| 距离比预期多一段链路 | 发送端与接收端是否都加了成本 |
| 当前端口变坏时表不变 | 是否把严格更优条件错误应用到所有来源 |
| 等价异端口延长了寿命 | 是否在接受判断之前就更新到期时间 |
| 含 100 的表项仍转发 | 是否只判断 `>`，或只判断物理链路距离 |
| 在 poison reverse 下本机不能正常转发 | 是否把出口视图写回转发表 |
| Stage 10 出现多余 poison | 是否比较了内部距离，而不是发给该端口的值 |
| 周期后紧接增量还发整表 | 强制发送是否更新了历史 |
| 新链路广播到所有端口 | `single_port` 是否真正限制收件人 |
| 断链后向离线端口发送 | 是否保留并正确使用框架端口删除逻辑 |
| 一次定时事件出现重复通告 | 过期函数与基类是否各发了一遍 |

测试 harness 默认不允许同一端口、同一目的地的重复通告，即使两条距离相同也会失败；少数旧阶段显式允许重复，不代表最终要求允许。读输出时区分 `EXTRANEOUS`、`MISSING`、`INCORRECT`：多发与漏发和代价错误是不同问题。

学生在自己的环境中可从解压包的 `simulator` 目录执行：

```sh
python3 dv_unit_tests.py 5
python3 dv_unit_tests.py 10 -v
```

第一个运行 0–5，第二个运行 0–10 并提高详细程度；不是只选择某一个测试方法。所有阶段最终每组 10%，没有隐藏测试。这里没有执行这些命令，也没有声明 starter 能在现代 Python 上直接运行；官方环境仍是 Python 3.8。

## 9. 自测：能解释这些，才适合写下一阶段

<details>
<summary>为什么永久静态路由在断开主机链路后仍可能被删除？</summary>

`FOREVER` 只让过期扫描不删除它，不能覆盖显式链路失败事件。10B 必须处理所有选用断开端口的条目，包括原来寿命无限的直连条目。
</details>

<details>
<summary>邻居通告 100，而链路成本是 3，内部得到 103 是不是已经出错？</summary>

不是。接收规则计算总代价；数据面将所有不小于 100 的值判为不可达，对外通告则压到 100。错误是将 103 当成比“无穷”更远但仍可转发的有效路径。
</details>

<details>
<summary>发送历史能否只用目的地主机做键？</summary>

不能。一个端口可能听到正常值，当前下一跳端口听到 poison，水平分割端口甚至什么都没听过。历史必须保留收件端口维度。
</details>

<details>
<summary>为什么“每次更新表都广播整表”不是合格的 Stage 10？</summary>

它只有 triggered，没有 incremental。还必须按每个收件人的最后实际通告过滤；纯寿命刷新、无关目的地、没变化的 poison 都不该形成额外消息。
</details>
