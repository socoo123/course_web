四、关键接口结论与桥接要点
1. 控制器是短生命周期客户端，MakeShardCtrler 通过 kvsrv.MakeClerk 访问
   group 0 的单机配置 KV；默认未复制。各数据组使用 Lab4 RSM / Lab3 Raft。
2. InitConfig 只初始化一次，version 0 创建配置键；Query 无参数、只读当前配置；
   ChangeConfigTo 接受完整候选且无返回值；InitController 是 B/C 恢复入口。
   ShardConfig.Join/Leave/JoinBalance/LeaveBalance 是现有本地辅助方法，非旧
   shardmaster RPC。NShards=12，Key2Shard 固定 FNV-1a，初始 Num=1 / Gid1。
3. 外层 Clerk 路由至组，内层 Clerk 找组 leader；维护 rcks/GetClerk/Leader，
   测试器使用它关闭实际最近使用的 leader。配置缓存只提供路由，不提供服务权。
4. Freeze/Install/Delete 都经 RSM，在 DoOp 内与 Get/Put 排序并检查服务状态。
   handler 入口 ownership 预检查不能替代 apply 时检查；冻结后拒绝 Get/Put。
5. Freeze→Install→Delete→发布 current 是推荐序列；允许暂时无人服务，但至多
   一组可服务。冻结状态应含此前所有已执行写入；安装确认后才能删除源数据。
6. 迁移状态要包含 value/version；State 实际是 []byte，需稳定编码副本。
   Num 是分片配置代际，配置 KV 键版本用于 CAS，业务键版本用于条件写；这些
   也不同于 Raft index/term 或 RSM 请求身份。
7. 每分片 Num + 阶段共同约束迁移；不能把同 Num 一律拒绝或一律重新执行。
   重复 Install 不能覆盖目标组已接受的新写；重复 Freeze 不能把已删数据误作
   有效空分片。Delete 释放业务数据但保留必要的防旧 RPC 屏障。
8. FreezeShardReply 为 State/Num/Err；内层 Clerk.FreezeShard 只返回 State/Err，
   必须解释回复代际，不能把任意状态当成本次冻结结果。固定接口没有完整状态机。
9. 控制器先把工作意图保存在独立 KV，再产生迁移副作用；InitController 读取
   current/next 接续已选工作。同号不同目标先由 KV versioned Put 唯一选定，
   然后才能迁移。竞争失败者不能执行自己的候选；多个恢复者可协作同一已选目标。
10. 配置 Put 的 ErrMaybe 不证明胜选或落败，需核对已存内容/Num/记录版本。
    next 选择与 current 发布都需防旧写；两个键不是事务，必须解释中间状态。
11. 跨组重试仍是一条逻辑 Put。旧组已写而丢回复，迁移携带增大的业务版本，
    新组拒绝原版本；外层刷新路由不能将结果误报为确定 ErrVersion。内外层
    保留不确定性且重试参数不变；ErrMaybe 只在 Clerk 层表达。
12. P4 快照新增分片服务状态、Num、恢复/幂等所需阶段；首次 Gid1 默认归属不能
    覆盖 Restore。InstallShard 是跨独立组迁移一片数据的 RSM 业务命令，
    InstallSnapshot 是同组 Raft 前缀恢复；两者不混用。迁移非 Raft 成员变更。
13. 未受影响分片持续服务，不能整组锁住等待另一组 RPC。2PC/2PL 是 5D 跨分片
    事务方向，非 A–C 前提。基础 RSM 与 P3 恢复仅引用现有教程，不再展开实现。

  的 RSM 测试是独立目标。根 Makefile 为提交打包；无通用 5D 目标/测试组。
- make shardkv 不递归测试 shardcfg 子包；单独入口 go test -race ./shardkv1/shardcfg。
- MakeTestLeases、leased leadership、AcquireLock 是测试命名，实际并发入口
  concurCtrler 没有直接 Acquire 调用，不能由名字额外要求实现时间租约/锁 API。
- concurCtrler 运行四条控制器工作流；partitionCtrler 停组促成中断、隔离旧
  控制器、重启组、新控制器 InitController 后立即检查配置，再按 partition
  标志决定是否重连旧控制器。新对象本地内存不能成为恢复依据。
- TestProgressShutdown5A 观察在线组 Get；TestProgressJoin5A 特意读参与迁移组
  内的稳定分片，4 秒工作窗口至少 100 次 Get，外层 8 秒超时。
- TestDeleteBasic5A 开启快照并检查两组快照总量不超过旧量+10000；
  TestShutdown5A 使用 maxraftstate=-1，不能把它单独称为开启快照的重启专项。
  网页的整体快照/重启描述不表示固定测试中每种组合都独立被测。
- TestJoinLeave5B 第一段 time.After(1*NSEC) 实为 2 纳秒，后续才乘 time.Second；
  文档保留停机时不能虚报完成的语义，不从此短窗口放宽实现。
- MakeTestMaxRaft 传 randomkeys=false；OneClientPut 用 ka[0]，不能因测试预建
  多键就声称并发热路径随机覆盖所有分片。SpreadPuts/CheckGet 另行检查多键。
- CheckGet 检查 Value/Version/Err；Porcupine Get 模型只比 Value；Unknown
  输出 assumed OK，不是线性一致性证明。未改测试代码或为缺陷提供完整解答。
