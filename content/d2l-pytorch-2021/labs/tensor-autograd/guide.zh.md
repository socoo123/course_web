# 实现与排查指导

先打开[实验说明](#/c/d2l-pytorch-2021/lab/tensor-autograd?v=zh)，固定输入、输出规格与四个 task id 都以那里为准。本页不重复整份题目，也不提供填好结果的脚本。

本实验由你在本地用Python/PyTorch自行实现，程序、配置和学习记录仅供自己保存与自检；无需Git提交、推送、上交报告或上传本站，也不要求排行榜提交。个人学习与任务进度不作为教程完成条件，不由agent认证或追踪。

> 本地练习使用自己的Python/PyTorch环境。环境、安装命令与实际验证状态统一看[课程公共资料](#/c/d2l-pytorch-2021)。本阶段只用 CPU 和本地小数据，没有 GPU、竞赛、模型训练或外部数据下载门槛。

## 怎样开始，而不是抄完再看

1. 新建自己的普通 Python 脚本，按 task id 分成四段或四个文件。先只构造输入并输出形状、dtype、设备，再加一个操作。
2. 每次运行前先写下预测：形状、一个手算值或应保持不变的量；不清楚时只查当前小节，不扩张成整门先修课。
3. 程序给出不同结果时，缩到最小输入，保留失败记录；解释原因后再修改，不直接换成另一段看似能运行的代码。
4. 将正常完成和预期报错分开。预期失败只捕获对应异常；其他断言失败应使运行失败，而非统一打印“通过”。
5. 浮点比较前先检查 shape，避免比较本身发生广播而误判。随机部分检查计数与统计恒等式，不把偶然误差阈值当作正确性标准。

验收记录宜按“预测 → 实际输出 → 断言 → 解释”组织。能运行只是第一步；能解释自己改变一个输入后什么应该变、什么不该变，才是掌握机制的证据。

## `tensor-autograd-1`：先给轴起名字

### 形状是运算合同

把矩阵的轴标成“样本、特征”，而不只是两个数字。每次操作都问：哪个轴被选择、消去、扩展或交换了？

- 整数索引通常去掉被索引的轴；长度为 1 的切片仍保留该轴。先比较一个样本和“一批中只有一个样本”的表示，再运行。
- reshape 的核心不变量是**元素总数**；它重新解释排列，不等于交换行列。转置的核心是把元素的两个下标交换。不要用 shape 相同证明数值位置相同。
- 广播从最右端对齐：两轴长度相同或有一方为 1 才兼容；缺失的前导轴按长度 1 看待。画两行 shape 即可，不需要真的用 `repeat` 复制数据。

如果 `A+b` 能运行，仍要检查 b 对齐的是“特征”还是“样本”。换一个恰好为方阵的输入可能让错误广播也能执行，因此实验故意先用非方阵。

### 乘法先找收缩轴

对于 $M\in\mathbb R^{n\times d}$、$w\in\mathbb R^d$，$Mw$ 的一个输出是某一行与 w 的点积：先逐项乘，再把 **d 轴**求和。矩阵乘法也是同一逻辑，只是同时有多个输出列。不要把本实验中的具体所有数值先算好再硬编码。

可查的 API：`reshape`、`transpose`/`.T`（这里仅二维）、`torch.matmul`/`@`、`torch.sum`。`*` 是按元素乘法，不会自动代替矩阵乘法。

### 归约后还要广播时，保留什么

对 `shape=(n,d)` 的张量按 `dim=1` 求和，是沿特征轴聚合。先在纸上把被归约的 d 改成 1，再决定是否去掉这个轴。`keepdim=True` 能把“这个数属于哪一个样本”的位置保留下来。

调试顺序：

1. 单独打印除数的形状，不要把求和与相除藏成一整行。
2. 从右到左检查除数与原矩阵的广播。
3. 用结果每行的和验证归一化，而不只看某个元素。
4. 本题每行和均非零；若你自行换成零和行，先定义任务语义，不要悄悄加 epsilon 后宣称结果正确。

## `tensor-autograd-2`：分清 fit 与 transform

### 只做两个阶段，不做一个万能函数

- **fit（拟合）**：只读训练特征，产生数值列均值和类别词表。
- **transform（转换）**：读取冻结后的状态，处理训练或验证输入，不重新估计任何统计量。

不要求用类、流水线框架或第三方预处理库。一个明确的状态字典与两段函数已经足够。函数命名不是验收重点，“验证数据是否能改变训练状态”才是。

先按 id 划分，再拿出 `target`；只有 `rooms`、`area` 参与数值均值。对每个数值列，分母是**训练中该列非缺失的观测个数**，不是训练总行数。填补之后，再报告缺失计数确认没有残留。

教材的极简演示把数值与字符串放在同一表中，本任务为避免不同 pandas 版本对 `mean()` 的行为差异，明确选择数值列。不要依赖“它会自动跳过字符串”的猜测。

### 缺失、未见类别与列对齐

`__MISSING__` 回答“这个字段没有观测”；`__UNKNOWN__` 回答“有观测，但训练词表里没有”。这两件事不能合并。

先冻结词表与两个保留类别的顺序，再映射每一行。可以自己建立类别编码，也可以使用 pandas 的类别类型/one-hot API，但必须保证验证输出列与训练完全同序。单独对两集合调用 `get_dummies` 后拼接，最容易出现某列缺失或含义错位。

转换张量前检查 DataFrame 所有特征列均为数值；显式指定数值 dtype，避免混合类型形成 object 数组。保留 id 到输出行的对应关系，标签不要丢失原顺序。

### 用“干预验证输入”而不是只看结果漂亮

实验要求只改 v0 的一个 area 值。正确流程中，某些验证输出当然会变，但训练拟合状态、训练特征以及 v1 的填补依据不应变。

因此要比较的是：

- 两次运行的训练统计量；
- 两次运行的训练特征；
- 两次运行的 v1 填补值；
- 错误合并拟合路径的统计量。

保留原始 DataFrame，两个对照都从原始缺失数据开始。若先填补，再把填补后的结果当成原始数据重新拟合，就无法观察到真正的均值来源。也不要让原地修改或切片共享使两条对照互相污染；这里为隔离实验使用显式副本是有意的。

## `tensor-autograd-3`：分别追踪图、梯度缓冲和数值

### 先写一个局部导数表

对标量组合函数，将它拆成两步，逐行列“输入 / 输出 / 输出对输入的局部导数”。沿路径相乘；有多条路径通向同一个输入时，把路径贡献相加。

对向量输入的标量损失，暂时把 $x_1,x_2,x_3$ 看作三个独立旋钮。求第一个偏导时，其他旋钮不动。最后把偏导按原输入顺序装回向量。这就解释了为什么梯度和输入同形，而不是只剩一个标量。

不要把前向值与梯度混为一谈：一个回答“当前输出是多少”，另一个回答“改变输入会怎样影响输出”。

### 非标量 backward 的权重是什么

设 $q(x)$ 有多个分量，传入的权重 $w$ 表示你想对哪个标量组合求导：

$$h(x)=\sum_i w_iq_i(x).$$

`q.backward(w)` 算的是这个标量组合对输入的梯度；它不是一次调用就把所有输出对所有输入的偏导矩阵打印出来。若是 `q.sum()`，请自己指出对应权重。两种实现比较时必须使用独立图并清理状态，否则结果差异可能只是累积。

### 三种状态不能混淆

| 对象 | 它记录什么 | 怎样排查 |
|---|---|---|
| 计算图 | 这一次前向操作之间的依赖 | 检查损失是否仍为张量，叶子是否参与这条路径 |
| `.grad` | 历次反传累加到叶子的梯度 | 检查何时为 None，何时清零，何时再次 backward |
| 参数数值 | 当前输入或模型参数值 | backward 本身不会执行参数更新 |

一次普通 backward 会释放后续再次反传可能需要的中间保存值。重复计算同一个公式时，重新执行前向来建立新图；这与 `.grad` 是否清零是两个独立问题。不要用 `retain_graph=True` 解决“我不清楚在复用什么”的问题。

当 `.grad` 尚为 `None` 时直接 `.zero_()` 会失败。已经有梯度时清零其数值，或把 `.grad` 设为 `None` 后让下次反传重新产生梯度，都应明确记录。实验要求观察清零，可优先使用已有梯度上的清零操作，并单独展示初始 `None` 状态。

保存历史梯度时，如果仅写“快照 = x.grad”，两者仍指向同一张量；后面的原地累积或清零会改掉你以为保存的历史。此处独立副本是必要的证据，不是无意义复制。

### detach 对照只改变反向路径

在纸上给中间量到输入的边画一个截断记号。前向仍使用该中间量的当前数值，但求导时把这条支路当成常量；另一条直接依赖输入的路径仍然存在。然后自己重新列局部导数，不要用“代码里都是相同数值”推断梯度相同。

`detach()` 不等于 `clone()`，也不保证新存储。为了保持对照干净，本题不改 detached 张量的内容。反向结果可以用手算核对，但不要把包含 detach 的程序直接拿普通有限差分当作等价验证：重新前向时，那个被视作常量的数值仍可能随输入重算，测到的不是同一种反向约定。

### 常见症状定位

| 症状 | 先检查什么 |
|---|---|
| 整数张量不能设置梯度 | 创建时是否显式用了浮点 dtype |
| 损失没有 grad_fn 或不需要梯度 | 是否提早 `.item()`、detach，或重新从数值创建了张量 |
| 第二次梯度恰好更大 | 是否按设计累积，保存的历史是否被原地修改 |
| 第二次 backward 报图已释放 | 是否重新前向，而不是只把旧损失变量再用一次 |
| 梯度为 None | 观察的是叶子还是中间非叶子；路径是否连通；是否真的执行了 backward |
| 向量输出不能隐式反传 | 是否定义标量归约或提供了同形上游权重 |

## `tensor-autograd-4`：概率先找分母

### 先核对确定观测，再碰随机数

A 部分序列不需要随机生成器。统计每个点数出现次数，先确认六个计数之和等于序列长度。计算经验期望时，“某个值出现得更多”应体现在它的权重更大，而不是对六种不同值直接做等权平均。

条件事件会改变可用样本集合。可以把 B 当作筛选条件，先留下满足 B 的样本，再在这个子集中统计 A。交换条件方向，相当于换了筛选集合，所以分母通常不同。

用事件掩码组合时注意括号和逻辑运算；不要拿 Python 的单个 `and` 代替张量逐元素逻辑与。记录实际分子分母比只输出一个小数更容易排查。

如果条件计数为 0，数据无法支持这个比值。将“未定义”作为输出的一部分，不要让 NaN 悄悄传播，也不要擅自加平滑项把问题改掉。

### 理论分布不是经验频率

理论的 $p_i$ 来自“公平骰子”的设定；经验的 $\hat p_i$ 来自次数除以总数。分别计算理论期望 $\sum_i i p_i$ 和经验期望 $\sum_i i\hat p_i$。二者可以接近，但没有必要逐项完全相等。

抽样 API 要弄清返回物：

- `torch.multinomial` 返回所选类别的**索引**；骰子点数需要按题意映射。
- 教材使用的 `torch.distributions.Multinomial` 返回各类别的**计数向量**。

本题要查看同一序列的多个前缀，使用索引采样更直接；不是要求把教材的绘图与 d2l 依赖全部搬进脚本。只创建一个显式 CPU generator，固定种子后一次生成 600 个样本；查看前缀时不重新设种子、不追加抽样。

### 随机误差不做“越来越小”的硬断言

样本增多不保证每一步误差下降。合适的确定性检查包括：点数在 1–6、计数和等于前缀长度、频率和接近 1、所有已定义条件概率落在 0–1、同环境同种子从头重跑一致。

不合适的检查包括：600 次的每项误差必须小于 60 次、某一面必须恰好出现 100 次、均值必须恰好等于理论期望。若观察到误差变大，先核对逻辑，再保留真实结果；不要为了过关换种子。

## 可以怎样向 AI 求助

合适的问题：“这是我的输入形状与断言失败，指出我哪一个轴理解错了”“帮我检查统计量有没有读验证集”“我手算了两条梯度路径，哪一条漏乘局部导数”。
