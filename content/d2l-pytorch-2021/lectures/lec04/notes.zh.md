# 数据操作与预处理：先看形状，再算数

读完应能回答三件事：一个轴代表什么；两个张量为什么能或不能一起计算；表格如何变成不泄漏验证信息的数值输入。无需先补完整数学课，也不增加论文阅读。

## 1. 先建立一张「形状账本」

想象两套房屋，每套记录面积、房间数、楼龄。编者示例：

$$
X=\begin{bmatrix}60&2&10\\90&3&5\end{bmatrix},\qquad \operatorname{shape}(X)=(2,3).
$$

- 第0轴长度为2：两条样本；第1轴长度为3：三个特征。轴的含义是人为约定，PyTorch不会自动知道“房屋”。
- $x_{ij}$ 表示第 $i$ 行第 $j$ 列的一个数；数学常从1编号，Python从0编号。因此数学的 $x_{12}=2$ 对应 `X[0, 1]`。
- `X.ndim` 是轴数2；`X.shape` 是各轴长度 `(2, 3)`；`X.numel()` 是元素总数6。不要把三者都叫“大小”。

| 对象 | 例子 | 张量形状 | 本讲用途 |
|---|---|---|---|
| 标量 | `torch.tensor(2.0)` | `()` | 一个数 |
| 一维向量 | `torch.tensor([2.0, 3.0])` | `(2,)` | 两个数，未指定行或列方向 |
| 列形状 | `torch.tensor([[2.0], [3.0]])` | `(2, 1)` | 每条样本一个值，保留特征轴 |
| 矩阵 | 上面的房屋表 | `(2, 3)` | 样本 × 特征 |

`(2,)` 与 `(2,1)` 都有两个元素，却会触发不同的广播。形状相同也不代表语义相同：把样本轴误当特征轴，程序可能照样运行。

创建时同时记录 `shape / dtype / device`。`torch.arange(6)` 默认是整数；需要平均值、连续数值计算时可明确 `dtype=torch.float32`。CPU足够完成本讲，不必先配置GPU。

## 2. reshape：换分组，不是转置，更不是保证复制

把 `[0,1,2,3,4,5]` 排成两行，会得到 `[[0,1,2],[3,4,5]]`；排成三行，则是 `[[0,1],[2,3],[4,5]]`。`reshape` 的首要约束是**元素总数不变**：$6=2\times3=3\times2$。

```python
import torch
flat = torch.arange(6)
rows = flat.reshape(2, 3)
columns = flat.reshape(3, -1)  # 唯一的 -1 由 6 / 3 推出为2
```

这些是讲解片段，不是实验答案。`reshape(4, -1)` 无法把6个元素分成等长4组；同时写两个 `-1` 也不能唯一确定形状。

`rows.T` 是 `[[0,3],[1,4],[2,5]]`，而 `rows.reshape(3,2)` 是 `[[0,1],[2,3],[4,5]]`。两者形状一样、位置关系不同：**转置交换轴，reshape按当前逻辑元素次序重新分组**。

### 内存共享需要单独思考

这个连续的 `flat` 经上述 `reshape` 得到的 `rows` 是共享存储的视图。对这个无梯度示例改 `rows[0,0]`，`flat[0]` 也会变。但不要推广成“所有reshape都不复制”：官方API明确说明，布局允许时返回视图，否则复制；业务正确性不能依赖它选哪条路径。转置后的张量可能不连续，重排形状时尤其要注意。

| 写法 | 要表达的意图 | 易混淆处 |
|---|---|---|
| `alias = X` | 同一个张量对象的另一个名字 | 不是备份 |
| `view = X.reshape(...)` | 改形状，可能共享存储 | 不保证独立副本 |
| `backup = X.clone()` | 独立存储的副本 | 后续改X不应改backup |
| `X = X + 1` | 计算新结果，再重新绑定名字 | 旧别名仍指向旧对象 |
| `X += 1` | 原地改内容 | 共享视图也会看到变化；涉及自动求导时有限制 |

`id(X)` 识别Python对象，不是通用的底层存储共享检测。`Z[:] = X + Y` 保留目标对象，但右侧相加仍可能分配临时结果；不能据此宣称“零分配”。不要为省内存提前到处原地修改，后续LEC7自动求导还需要保存某些前向值。

**教材勘误式补充。** 教材“转换为其他Python对象”对共享内存的概括需要按API区分：普通可直接转NumPy的CPU张量，其 `.numpy()` 可共享底层内存；`torch.from_numpy(a)` 与数组共享；`torch.tensor(a)` 则复制输入。教材展示的 `B = torch.tensor(A)` 不能解释成B也共享A。这里依据已读官方API澄清，不归因于视频。

## 3. 广播：从最右端对齐轴，不是任意自动扩容

先做一件具体的事：给两个人分别加上 `[1,2,3]` 三项补贴。

$$
\begin{bmatrix}10\\20\end{bmatrix}
+\begin{bmatrix}1&2&3\end{bmatrix}
=\begin{bmatrix}11&12&13\\21&22&23\end{bmatrix}.
$$

左输入形状 `(2,1)`，右输入 `(1,3)`，结果 `(2,3)`。这里的“扩展”是理解计算的逻辑模型，不表示必须真的复制出两份大数组。

![广播与归约保留轴的关系](assets/broadcast-reduce.svg)

*图：编者依据教材广播机制与下一讲归约主题自绘；数值自拟，不是视频截图。*

一般规则：从形状最右边一列一列比；缺少的前导轴视为长度1。对应长度相等，或其中一个为1，才相容。例如 `(2,3)+(3,)` 相容，后者按 `(1,3)` 理解；`(2,3)+(2,)` 不相容，因为最右端3与2冲突。

特别危险的是 `(N,1)-(N,)`：第二个会按 `(1,N)` 对齐，产生 `(N,N)`，不是你想要的逐样本差。这常发生在“预测有一列、标签却被挤成一维”时。**先写预期结果形状，再检查实际形状；能运行不是语义正确。**

归约是配套问题：对 `(2,3)` 每行求和，`sum(dim=1)` 得到 `(2,)`；若要再除回原矩阵，应保留轴为 `(2,1)`，即 `sum(dim=1, keepdim=True)`。下一讲会把每个数的来龙去脉算清楚。

## 4. 索引、拼接、逐元素运算：只记必要区别

- `X[0]` 选一行，会去掉第0轴；`X[0:1]` 选一个行区间，会保留长度1的轴。切片结束位置不包含在内。
- 两个形状 `(2,3)` 的表 `torch.cat((X,Y), dim=0)` 得到 `(4,3)`，相当于增加样本；`dim=1` 得到 `(2,6)`，相当于增加特征。非拼接轴长度必须匹配；拼接前还要保证样本行的顺序真对应。
- `X + Y`、`X * Y` 是对齐位置后的逐元素运算；`X @ Y` 是矩阵乘法，内侧维度必须匹配，见下一讲。`*` 不是矩阵乘。
- `X > 0` 产生布尔张量，不是一个Python真假值；`X.sum()` 把所有元素加成一个标量张量。
- `.item()` 用于取只有一个元素的张量中的Python数值，不会把整张表变成单个数。

排错顺序：先写出每个轴的含义，再看形状，再看数值类型和设备，最后检查是否意外共享内存。不要靠反复加 `reshape` 消掉报错。

## 5. 表格到张量：哪些处理是“学出来”的？

教材的路线是 CSV → pandas → 分开输入和目标 → 处理缺失与类别 → 数值张量。它的微型房屋表是教学例子，不等于一套可直接用于评估模型的生产流水线。

编者示例：训练数据的房间数是 `[2, 缺失, 4]`，已知值平均为 $(2+4)/2=3$，缺失项填3。类别“铺装/未提供”不能直接作为字符串送进普通数值矩阵；可以编码成指示列，例如“铺装”为 `[1,0]`、“缺失”为 `[0,1]`。这些是类别标记，不表示“缺失的等级更高”。

### 编者工程补充：先划分，再拟合，只在训练集学习统计量

此段是工程建议，不是已核实的课堂内容，也不是该教材小节展示的训练/验证流程。

1. **先分训练集与验证/测试集。** 时序、用户分组等任务要按任务约束划分，而不是随意混合相邻记录。
2. **只用训练集拟合。** 上例填充值固定为3；如果验证集出现100，不能把它加入均值。标准化的均值/标准差、类别词表同理。
3. **冻结变换后应用到所有集合。** 验证和测试只接受变换，不重新计算自己的统计量。否则评估信息进入训练管道，线上也无法复现。
4. **固定列名、顺序与未知类别策略。** 分别对两份数据 `get_dummies` 可能得到不同列；需用训练列模式对齐，并预先明确未知类别是独立“未知”类还是其他策略。未知与缺失不自动等价。
5. **检查输出数值契约。** 输入矩阵应是 `(样本数, 特征数)`，没有未处理的NaN/无穷值；明确转换为统一浮点类型。目标 `y` 不应混入输入特征。

训练列如果全缺失，均值仍然缺失，需要显式选择删列或另定可解释策略，不能期待 `fillna(mean)` 自动解决。均值填充还会改变数据分布，是否合适要由任务决定。

**版本边界。** 固定教材中有 `inputs.fillna(inputs.mean())`，其中输入含字符串类别列。当前pandas对混合类型求均值的行为可能不同，不应机械照抄；明确选数值列求均值，类别单独处理。转换时明确 `to_numpy(dtype=...)`，避免混合列形成 `object` 数组。此处讲机制，不提供完整实验流水线答案。

## 6. 自测：先说形状，再解释原因

下面都是编者概念自测，不是官方练习或实验的代写答案。

<details>
<summary>1. 一个张量shape是(4, 1)，另一个是(4,)，相加结果是(4,)吗？</summary>

不是，是(4,4)。从右边对齐后是(4,1)与(1,4)，两个长度1的轴分别广播。若语义是逐样本相加，应先把双方表示统一，而不是接受这个结果。

</details>

<details>
<summary>2. 把6个元素reshape成(3,2)，是否等价于把原(2,3)矩阵转置？是否保证复制？</summary>

都不是。reshape保留逻辑遍历次序并重新分组，转置交换行列位置；reshape可能返回视图，也可能复制。需要独立存储时表达清楚clone的意图。

</details>

<details>
<summary>3. 训练集已知值为2和4，验证集有100。训练缺失项为什么不能填(2+4+100)/3？</summary>

预处理也是从数据学习参数的一部分；验证集应模拟未见数据，不能参与拟合填充值。训练均值是3，验证数据也使用这个冻结的训练均值。

</details>

<details>
<summary>4. 为什么“Python对象不同”不能证明“修改互不影响”？</summary>

不同张量对象可能是同一存储的视图。对象身份与底层数据的所有权是两回事；先弄清操作的共享契约，而非只比较id。

</details>
