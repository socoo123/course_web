## 00:05–03:24　第三次开课：理解来自亲手构建

Percy Liang 与共同授课教师、助教依次介绍自己。团队成员提到架构、训练、高阶梯度、理论和数据效率等研究兴趣，也强调课程实现工作量大。自我介绍是本届课堂的一部分，不应搬用上一年的开场。

## 03:24–11:37　小模型教得了什么，教不了什么？

讲者从研究者与底层技术逐渐脱节谈起：从自己实现与训练，到下载预训练权重微调，再到主要调用模型接口。抽象提高生产力，但也限制可修改的设计空间；如果研究问题需要改变模型内部，仅靠提示并不够。

现实限制是前沿模型昂贵且细节不完全公开。课堂提及的训练成本中包含传闻与推测，并非本页独立核实的预算。即使自己能训练小模型，也不能假定它代表大模型：不同尺度的计算占比会变化，某些能力的表现也可能随尺度变化。因此，小规模结论要说明适用范围。

课堂把可学习的知识分成三类：

- **机制**：组件怎样工作，计算与并行怎样组织。
- **思维方式**：认真核算资源，测量、剖析并尽可能提高利用率。
- **经验直觉**：某种数据或建模选择在具体尺度上是否有效。

前两类更容易迁移；第三类经常依赖实验，不能仅凭优雅解释决定。讲者借 SwiGLU 的讨论说明，有些成功设计并无充分理论解释。

随后，“bitter lesson”被解释为重视**可以扩展的算法**，而不是宣称算法不重要。课堂用“效果来自效率与资源的共同作用”组织思路：固定数据和计算预算下，问的是怎样获得更好的模型。该表述是启发式框架，不是可直接代数计算准确率的定律。

## 11:37–19:26　历史与开放生态：界面变了，基础仍在

这一段依次回顾用语言模型描述英文统计规律、N-gram 在翻译与语音系统中的作用，再到神经网络、序列到序列、注意力、Transformer、优化与模型并行。接着转向预训练和微调、规模扩展，以及更大模型出现的使用方式变化。

讲者区分“开放权重”和进一步提供代码、数据、训练细节的项目。后者让研究者更有机会理解模型如何构建；但有论文或权重也不意味着所有数据混合与工程细节都可复现。课堂列举的模型生态是授课时的观察，不是今天的完整排名。

语言模型的典型接口从微调、提示、对话走向自主执行任务。课堂尝试打开 agent 轨迹时提到网络不可用，本页不补写未能展示的网页内容。讲者强调，长上下文和推理效率的要求更高了，但 GPU、kernel、优化和注意力等基础仍值得学习。

## 27:16–35:53　基础单元：三块组件，共同权衡

课程五部分与五份作业相呼应。基础单元首先要让学生训练一个语言模型：把原始输入变成 token，定义模型，再选择训练与优化方式。

分词被介绍为模型“基本单位”的选择。BPE 把高频片段变成较少 token，既缩短序列，也让不同输入片段获得不同数量的计算步骤。讲者提到直接从字节建模的研究方向，但表示本届仍需讲现行 tokenizer。

架构预告涉及激活、位置表示、归一化、注意力变体、状态空间或线性注意力方向、MoE 和模型形状。训练预告涉及损失、优化器、初始化、学习率、正则化与 batch size。它们并非只是在配置文件里随便填的数值：稳定性和资源效率会受其影响。

A1 的课堂介绍包括 BPE、Transformer、损失、优化器、训练闭环与资源核算，并提到 TinyStories 和 OpenWebText。讲者最后归纳出三项共同要求：**表达能力、训练稳定性、运行效率**。本段是课程导览，正式任务细节应进入[A1 指导](#/c/stanford-cs336-2026/lab/a1-basics?v=guide)读取固定版要求。

## 35:53–45:10　系统单元：不只数运算，还要数数据搬运

系统部分要解决的是如何利用硬件。课堂先预告参数、激活、FLOPs 与内存核算，并提到密集模型训练常用的近似量级 $6ND$，其中 $N$ 是参数量，$D$ 是训练 token 数。这里还没有展开完整推导。

硬件上的计算与存储分离，数据必须搬到执行运算的位置。讲者介绍 roofline、benchmarking 与 profiling，随后用连续两个操作说明融合：与其把中间结果反复写回、读出，不如在适当条件下读入一次、完成更多计算再写回。扩展到多 GPU 后，仍要考虑参数、激活、梯度和优化器状态放在哪里，以及集合通信的成本。

推理又分 prefill 和 decode：前者处理已知提示，后者逐个产生后继 token。课堂以此说明推理为什么常有不同于训练的瓶颈，并预告量化、蒸馏、推测解码和服务批处理等方向。这里是学习路线，不把“某一阶段一定受内存限制”当成任何配置下都成立的结论。

## 45:10–53:29　缩放规律：训练一个模型之前先预测它

如果预算只够在目标尺度训练一次，就不能把所有超参数搜索都留到最大规模。课堂提出“scaling recipe”：把计算预算映射到一套模型和训练配置，用较小规模实验拟合结果，再外推目标尺度。

这要求超参数能随尺度按稳定规律迁移。讲者强调，可预测性至少与局部最优一样重要；缩放曲线并不是不加设计就自然出现的法则。对固定计算预算，模型更大与训练 token 更多之间的折中，可以通过多条等计算量曲线寻找。

课堂提到训练 token 数约为参数数目的20倍这一粗略经验，并同时指出数据、架构与推理成本会改变选择。它不是通用采购公式，也不是所有现代模型都应该遵守的固定比例。

讲者以正在进行的 Marin 预测为例，强调先登记预期、再看实际结果，而不是只在训练后解释成功。A3 的开场预告描述了通过 API 返回已缓存训练结果的练习。**版本提醒：**这是当日课堂预告，不是最终2026作业的完整要求；P1 已核实最终 A3 还包含真实训练探索与预测，不能据此声称整份作业是纯离线模拟。

## 53:29–60:21　数据单元：先定义能力，再决定训练什么

模型要会什么，会影响需要什么数据。课堂先区分两种评测目的：内部评测用于指导开发，关心跨尺度的平滑性与相对表现；外部评测用于说明实际用途中的质量，关心场景有效性。单个平均分容易掩盖能力差异，通用模型需要多样的评测。

数据不是天然准备好的纯文本。网页、PDF、代码目录需要提取与转换，还涉及许可、质量、重复内容与混合比例。课堂依次介绍转换、过滤、去重、混合和改写 / 合成数据，再区分预训练、中期训练与后训练数据的不同角色。

A4 的预告强调从粗糙原料开始处理，而不是默认拿到已经清洁的数据集。本页保留这个学习目的，不把第一讲中的简述当作后续固定作业的输入格式和规模规范。

## 60:21–65:06　后训练与课程共同主线

在已经能够进行下一 token 预测的模型上，有时判断一个回答好不好，比写出理想回答容易。课堂据此引出一种模板：生成回答，由人、验证器或模型评委打分，再更新模型，使其偏向更好的回答。

讲者提到 PPO、GRPO 以及用于偏好数据的 DPO，随后强调强化学习的稳定性与系统组织问题。生成服务、训练服务和外部环境若不同步，就会在吞吐量与策略新鲜程度之间形成折中。A5 的具体题目在当日仍在决定，本页不以预告替代最终讲义。

课程导览最后回到同一个问题：给定数据、计算、内存与通信带宽，怎样获得更好的模型？分词缩短序列，架构控制成本，过滤避免浪费更新，缩放实验减少高成本试错。若未来变成数据受限，具体取舍会改变，但核算资源的思维仍适用。

## 65:06–68:29　正式进入分词：接口与压缩率

讲者推荐参考一段分词教学视频后，从 Unicode 文本与 token 索引序列的区别讲起：需要 `encode` 把文本变为 token，也需要 `decode` 还原。课堂尝试的交互网站没有成功展示，不补写网站输出。

随后讨论现成 tokenizer 的一些现象：前导空格可能与后面的词合为一个 token；一个词在句首和带前导空格时可能有不同 ID；数字可能按若干位分块。这些行为依赖具体分词规则，不是所有 tokenizer 的统一定律。

演示字符串 `Hello, 🌍! 你好!` 编码后再解码，强调往返一致。字幕给出的20字节、8个 token，对应 $20/8=2.5$ bytes/token，与固定 trace 中的该演示数值相符。扩大词表可能缩短序列，但也增加稀疏性。

**编者注：**课堂称所用示例为“GPT-5 tokenizer”，固定源码实际调用 `tiktoken.get_encoding("o200k_base")`。本页只确认这一教学示例的代码，不把产品称呼扩展成所有模型版本的官方分词器对照表。

## 68:29–69:45　码点级方案：能往返，却不一定划算

最直接的尝试是用 Python 的 `ord` / `chr` 在 Unicode 码点与整数之间转换。它容易理解，也能在例子上往返；但若希望覆盖广泛文字，符号空间大，很多条目出现很少，常见内容又需要较多 token。

课堂用“约150K个 Unicode 字符”说明规模问题。这是授课中的近似量级，不作为当前 Unicode 标准的精确字符计数；码点、已分配字符与视觉上的字形也不能混为一谈。

## 69:45–70:45　字节级方案：词表小，但序列长

UTF-8 把字符串变为字节序列。一些字符用一个字节，另一些需要多个字节。若直接把每个字节当一个 token，词表固定256个值，压缩率按本讲定义恒为1。

这样避免了巨大基础词表，却把更多工作交给模型的序列维度。课堂据此指出，在常见的上下文长度和注意力计算约束下，纯字节序列不够经济。70:40.830–70:44.630没有字幕，不补写这段内容。

## 70:45–71:58　词级方案：语义直观，却遇到未知词

另一种经典方式是按空格或正则把文本分成词等片段，再把片段映射为 ID。常见词的表示紧凑，但词表可能极大；测试时还可能出现训练中没有的词。

如果把这些词统一变为 `UNK`，就丢失区别，也会影响困惑度的解释。这一问题把课堂引向下一种方案：常见片段可以合并，罕见片段仍应能拆回更小单位，而不是消失在一个统一未知标记里。

## 71:58–75:22　BPE 训练：序列缩短，词表增长

课堂先说明 BPE 起源于压缩，后来进入自然语言处理并被 GPT-2 等模型使用。基本思想是从训练文本学习适合该分布的词表：常见字节序列用较少 token，罕见序列保留较细分段。

演示以 `the cat in the hat` 开始，把它变为字节，再反复统计当前的相邻 token 对，选择高频对并新增条目。第一轮 `(116,104)` 对应 `th`，新 ID 为256；随后出现 `the` 和带尾随空格的 `the `。

字幕在第一轮明确说存在同频选择，演示取首先遇到的对。固定 trace 给出的三轮新增项分别是 `th`、`the`、`the `；最后压缩率为1.5。这里是读到的既有演示状态，不是本轮重新执行得到的输出，也不是官方作业 tie-break 规则的替代说明。

每一轮都把当前序列中的对应相邻对替换成新的 ID，词表随之增长。课堂借这个极小例子说明机制，没有声称它已经解决真实语料上的效率问题。

## 75:22–77:29　应用固定规则，以及课堂小程序与 A1 的距离

训练出合并规则后，新文本不再重新训练 tokenizer，而是按这些规则编码。课堂用 `the quick brown fox` 说明编码后再解码仍回到同一文本；因时间关系，没有把全部编码过程再逐步展开。

讲者明确说这一演示很慢。A1 还要处理真正相关的合并、特殊 token、预分词与效率；课堂提及也可以考虑更适合高性能实现的语言。这不是要求读者立刻重写，也不是准许改变测试契约以换取速度。

若要继续学习，回到[A1 实验指导](#/c/stanford-cs336-2026/lab/a1-basics?v=guide)，先区分当前样板的任务拆解与完整作业实现。

## 77:29–79:17　结束：需要的是有用的抽象与可变计算粒度

分词器在字符串与 token 索引之间转换。课堂比较的三种直接方案各有明显不足，而 BPE 是数据驱动、效果实用的启发式方法。

即使未来改用端到端字节模型，讲者仍认为模型需要形成比原始单位更高层的表示，并让不同片段占用不同计算量。最后预告下一次课进入资源核算，之后再回到架构。本片字幕在79:17.220结束，余下4.780秒未有字幕，不额外补造结语。
