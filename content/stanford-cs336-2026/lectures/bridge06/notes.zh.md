# 自回归模型训练闭环：同一份预测，三种使用方式

## 学习门槛与出口

先会读 `[batch, time, vocabulary]`，理解“真实 token 的负对数概率”；概率定义与困惑度推导在 [bridge02](#/c/stanford-cs336-2026/lec/bridge02?v=notes)，求导语义在 [bridge03](#/c/stanford-cs336-2026/lec/bridge03?v=notes)。

一个语言模型不只是一组层。还需要回答：**预测谁、允许看见谁、哪些位置计分、什么时候更新、怎样恢复、怎样把下一次输入接上。** 本页把这些接口连接起来，不重讲 Transformer 层，也不提供可提交的训练循环、数据加载器或解码器代码。

## 1. 先画一条预测箭头，再写 token shift

设手中有一段长度 $T+1$ 的 token 序列

$$
z_0,z_1,\ldots,z_T.
$$

将输入与目标定义为

$$
\begin{aligned}
X_t&=z_t,\\
Y_t&=z_{t+1},\qquad 0\le t<T.
\end{aligned}
$$

因此输入和目标都长 $T$。位置 $t$ 的输出用来预测**下一个 token**，不是复制当前位置已经给出的 token。`shift` 是两份数据的对齐关系，不是要求网络在内部把所有隐藏状态再平移一次。

自拟例子中的方括号表示已经确定的 token，不是声称真实 tokenizer 必然把每个汉字切成一个 token：

| 位置 $t$ | 输入 $X_t$ | 此位置可见的前缀 | 目标 $Y_t$ |
| --- | --- | --- | --- |
| 0 | `[起始]` | `[起始]` | `[春]` |
| 1 | `[春]` | `[起始][春]` | `[雨]` |
| 2 | `[雨]` | `[起始][春][雨]` | `[落]` |
| 3 | `[落]` | `[起始][春][雨][落]` | `[结束]` |

这个例子人为加入起始符以展示第一项预测。真实数据管线是否插入起始符、怎样处理结束符，要服从其固定约定；**不能把教学符号当成 A1 必须新增的特殊 token**。若只给没有起始上下文的片段 `[春][雨][落]`，用 `[春][雨]` 预测 `[雨][落]` 就只计分后两个目标，不会凭空得到 `[春]` 的条件概率。

对批次：

$$
\begin{aligned}
X,Y&:[B,T],\\
O&:[B,T,V].
\end{aligned}
$$

$O_{btv}$ 是样本 $b$、位置 $t$ 对候选 token $v$ 的 logit。输入/目标是整数 ID；logits 是浮点分数。词表轴 $V$ 不参与 token shift，也不能拿整个 logits 张量的均值当作语言建模损失。

## 2. Teacher forcing 为什么能并行，又为什么仍要 causal mask？

训练时，位置 $t$ 的输入前缀来自真实数据，而不是先采样模型的前一个预测再接上去。这种使用真实历史的做法称为 **teacher forcing**。

它不意味着“把答案直接告诉要回答这一题的位置”。在上表中，目标 `[雨]` 确实也存在于同一大输入张量的更后位置；但是正在预测它的位置1只能看见位置0、1。必须由因果性约束阻止它偷看位置2。

### 两个接口，一个也不能少

1. **目标右移一位**：规定输出在回答哪一个问题。
2. **因果掩码**：规定回答该问题时允许使用哪些信息。

对自注意力分数，令行 $t$ 是 query 位置，列 $s$ 是 key 位置：

$$
M_{ts}=\begin{cases}
0,&s\le t,\\
-\infty,&s>t.
\end{cases}
$$

这是加到分数上的**加性掩码**约定，不是某个库的布尔掩码约定。布尔 `True` 究竟表示允许还是屏蔽，要检查具体 API，不能把一种接口的含义照搬到另一种。

长度4时的“允许看见”关系如下；1表示允许，0表示禁止：

$$
\begin{bmatrix}
1&0&0&0\\
1&1&0&0\\
1&1&1&0\\
1&1&1&1
\end{bmatrix}.
$$

对角线允许，是因为 $X_t$ 属于已经提供的前缀，而此处预测的是 $Y_t=z_{t+1}$。如果目标没有 shift，却仍允许对角线，模型可能只学会读取答案；如果 shift 正确但取消因果约束，目标仍可能从未来位置泄漏。

所有位置的真实前缀已知，因此可以在一次前向里并行计算所有 $T$ 个条件分布。**并行计算不等于假设各位置独立**：每个条件分布仍依赖自己的前缀，只是不同位置的依赖被同一个有约束的张量计算表达出来。

### 最有效的因果性检查不是看三角形画得像不像

在评估模式下、固定同一参数与随机条件，把位置 $k$ 及以后的输入换掉。对于普通因果模型，所有 $t<k$ 的输出分布应保持不变（数值比较采用明确容差）；位置 $k$ 及以后可以改变。

这检验的是**整个模型的信息通路**，不只是一张掩码。某个跨时间归约、错误的归一化轴或预处理也可能泄漏未来。只在训练 loss 上看见很低的数字，无法证明因果性正确。

## 3. 掩码至少有三种，不要把“没有算 loss”当成“没有看见”

| 约束 | 控制什么 | 不自动保证什么 |
| --- | --- | --- |
| 因果注意力掩码 | 一个位置能读取哪些时间位置 | 不决定哪些目标计入损失 |
| padding/文档可见性约束 | 哪些输入位置有效、哪些文档允许互见 | 不自动把对应目标从损失分母排除 |
| 损失计分掩码 | 哪些目标贡献 NLL 与 token 计数 | 不阻止网络读取未计分位置 |

例如提示词不计 loss，却仍是预测回答时必要的上下文。相反，padding 不应被误当真实上下文，也不应被统计成真实目标。把损失乘零不能代替前向可见性约束，更不能修复已经产生的非法数值。

文档拼接还需要额外约定：插入结束标记，只是向模型提供一个边界 token，**不自动阻止后一个文档看到前一个文档**。若实验要求文档隔离，数据与注意力规则必须实现那个语义；若允许跨文档上下文，也要在训练、验证时保持口径一致。A1 固定长度连续片段的基线通常不需要 padding，不应为了本页讲解而擅自改写官方数据方案。

## 4. 一个训练步有两个时钟：取了多少数据，更新了几次参数

一次有效批次的概念流程是：

| 阶段 | 输入与输出 | 应保持的不变量 |
| --- | --- | --- |
| 取数据 | 原始片段 → 输入、目标、计分集合 | shift、边界、词表身份明确 |
| 开始本次更新 | 旧参数与优化器状态 | 清除上一有效批次的梯度，而非重置参数 |
| 前向与计分 | logits → 标量目标 | 使用同一套有效 token 分母 |
| 反向 | 标量目标 → 梯度贡献 | 参数尚未更新；微批间允许正确累积 |
| 检查与必要处理 | 原始梯度 → 本次更新使用的梯度 | 诊断、去缩放、裁剪顺序明确 |
| 参数更新 | 参数、梯度、优化器状态 → 新状态 | 每有效批次按约定更新一次 |
| 记录/评估/保存 | 已完成的状态 → 证据或检查点 | 日志编号与保存状态对应 |

这里是状态关系，不是完整代码模板。动量、权重衰减和调度器怎样影响更新归 [ext02](#/c/stanford-cs336-2026/lec/ext02?v=notes)；微批权重与混合精度的先后顺序归 [ext01](#/c/stanford-cs336-2026/lec/ext01?v=notes)。

必须区分：

- **microstep**：处理了一个微批，可能只做前向和反向。
- **optimizer step**：真正执行了一次参数更新。
- **processed tokens**：实际处理的 token 次数；重复读同一文本仍再次计数。
- **scored target tokens**：参与当前指标/目标分母的目标数量，可能小于输入位置数。

“训练了100步”若不说明是哪一种步数，就不能比较数据量或学习率进度。开启梯度累积后，一个有效批次可能跨多个 microstep；使用动态 loss scaling 时，检测到非有限梯度还可能跳过一次更新。学习率与日志应按预先声明的时钟推进，而不是从循环变量名字猜测。

## 5. 训练、验证、生成：同一模型，三份不同契约

| 模式 | 历史从哪里来 | 是否使用真实后继计分 | 是否更新参数 |
| --- | --- | --- | --- |
| 训练 | 真实输入前缀 | 是 | 是，按有效批次更新 |
| 验证 NLL | 验证集的真实前缀 | 是 | 否 |
| 自由生成 | 提示词 + 已生成 token | 通常没有固定真实后继 | 否 |

**验证 NLL 一般仍使用 teacher forcing。** 它检验模型对保留数据真实后继的概率，不要求先生成一整段再与参考文本逐字匹配。生成则把模型自己的选择送回输入；一旦产生不同 token，接下来访问的上下文就变了。两者回答不同问题，不能用一段看起来流畅的样文替代保留集指标。

### 评估行为开关与求导开关互相独立

`model.eval()` 切换具有模式依赖的模块行为，例如关闭 Dropout 的随机丢弃；它不自动禁用 autograd。`no_grad()` 禁止相应前向操作被记录到反向图，但不会替你调用 `eval()`。返回训练时还需要恢复 `train()`。

独立 CPU API 微例：故意使用丢弃概率1，让结果不依赖随机抽样；这不是建议真实模型使用该概率，也不是 A1 模块实现。

```python
import torch

layer = torch.nn.Dropout(p=1.0)
x = torch.ones(3, requires_grad=True)
layer.train()
a = layer(x)
layer.eval()
b = layer(x) * 2
with torch.no_grad():
    c = layer(x) * 2
print(a.tolist(), b.tolist(), c.tolist())
print(b.requires_grad, c.requires_grad)
```

预期第一行依次是全0、全2、全2的三个列表；第二行是 `True False`。这里显式乘2以创建一次新运算：评估模式的 Dropout 本身可以直接返回原输入，`no_grad()` 不会追溯修改输入的 `requires_grad`，它控制的是区域内新运算的记录。这只说明开关语义，不证明模型已正确评估或训练。`inference_mode()` 还有更严格的张量使用限制，不能不加判断地替换所有需要日后继续求导的 `no_grad()` 区域。

### 指标要合并分子、分母，而不是均值的均值

对预先定义的有效目标集合 $\mathcal I$：

$$
\begin{aligned}
S&=\sum_{(b,t)\in\mathcal I}\ell_{bt},\\
N&=|\mathcal I|>0,\\
L_{\mathrm{val}}&=S/N.
\end{aligned}
$$

跨批次累加 $S$ 和 $N$，最后相除；不要直接平均各批 loss，除非有效目标数确实相等。PPL 的换算与可比条件回看 bridge02。验证集分母为零时，指标是未定义，不应输出伪装正常的0。

一次可解释的评估还应固定 tokenizer、数据划分、上下文长度、窗口重叠的计分方式及边界规则。选择模型可以看验证集；若反复据测试集调整超参数，它就不再是独立的最终检验。

## 6. 检查点不是“一个权重文件”这么简单

先问想恢复什么能力，再决定保存什么：

| 恢复目标 | 必要信息的例子 | 单有权重为什么可能不足 |
| --- | --- | --- |
| 重新生成/评估 | 权重、模型结构配置、词表/tokenizer与特殊符号约定 | 相同 shape 不保证 token ID 含义相同 |
| 接着优化 | 上述信息 + 优化器状态、已完成更新数与调度进度 | 动量、二阶状态和学习率位置不在权重里 |
| 尽量接续同一轨迹 | 再记录数据位置/采样器状态、有关 RNG 状态、启用时的 scaler 状态等 | 换了下一批或随机状态，就不是原来的后续计算 |

A1 §5.2 的固定基本要求是模型、优化器与迭代编号。第三行是**编者给真实实验补充的复现条件**，不是暗中增加官方计分项；即便保存这些，也不能承诺跨设备/版本逐位一致。

最容易讲清的保存边界是：一次有效批次的更新及相关状态推进已经完成、下一有效批次尚未开始。若在微批累积中间保存，还必须定义如何恢复尚未应用的梯度与累积进度；初学时不要把这个复杂边界假装等价于普通步间恢复。

“保存成功”也不是“可以恢复”。一个独立的恢复检查应在相同配置下确认：

1. 模型和 tokenizer 身份匹配，参数与必要状态确实装回。
2. 已完成的更新编号和下一个学习率/数据位置符合约定。
3. 若要检验续训，在同一下一批和随机条件下，对照连续执行与恢复执行的下一步；明确比较容差与平台限制。

这是验证方案，不提供序列化函数或续训实现。只加载可信来源的检查点；把文件名写成 `.pt` 不会使反序列化自动安全。独立数值快照与共享内存的区别回看 [bridge05](#/c/stanford-cs336-2026/lec/bridge05?v=notes)。

## 7. 生成闭环：只取最后一个有效位置，接回自己的选择

给定提示前缀，模型对每个位置产生后继分布。但要继续写一个 token，应使用**当前最后一个有效输入位置**的输出。若批次包含 padding，“最后有效位置”未必等于张量的最后一列。

概念上的一次生成转移是：

1. 用当前可见上下文得到最后位置的 logits。
2. 根据已声明的解码规则得到下一 token：例如 greedy 取最大分数，或从一个指定分布抽样。
3. 把所选 token 追加到历史，作为下一轮已知输入。
4. 检查结束符或最大新生成 token 数等停止条件。

训练时“同一轮给出所有真实前缀”在这里不可照搬：尚未选出的 token 还不是可见输入，所以自由生成具有逐 token 的依赖链。缓存可以复用已有前缀的中间结果，但不会取消这个逻辑依赖；缓存实现不在本页范围。

温度改变采样分布的尖锐程度，top-p 限定一个高概率候选集合，greedy 则不是随机抽样。这些规则影响样文，却不应悄悄改变标准验证 NLL 使用的原始模型分布。固定提示词、解码参数、随机种子和停止条件，样文才有可解释的比较条件；单个种子仍不能代表完整生成分布。

上下文超过模型/实验允许长度时，也必须明确截断或其他策略。简单滑动窗口会改变可见历史，因而改变条件分布；不能把它称为与无限上下文完全等价。

## 8. 用五个问题闭合实验，而不是只问 loss 降了没有

- **对齐正确吗？** 任取一个位置，能写出输入前缀和它的真实目标。
- **因果正确吗？** 改未来输入不会改变较早位置的预测。
- **计量正确吗？** 损失分母、数据量和更新次数各有明确单位。
- **状态正确吗？** 验证不更新参数，回到训练时模式正确，检查点能接上预期状态。
- **使用正确吗？** 生成读取最后有效位置，接回模型选择，并按规则停止。

这些机制检查都很有用，但都不等于官方规模训练完成。官方任务、数据预算、AI 辅助边界和评分口径应回到 [A1 指导](#/c/stanford-cs336-2026/lab/a1-basics?v=guide)；不要让机制示例代替自己实现作业。

## 9. 自测

<details>
<summary>1. 有5个连续 token，不添加其他上下文，最多能组成多少个相邻的一步预测对？</summary>

4个：用前4个作输入、后4个作目标。若想给第一个 token 也计分，需要额外定义起始上下文与那个条件概率，不能只把分母从4改成5。

</details>

<details>
<summary>2. 有正确 token shift，却没有因果掩码，会怎样？</summary>

正在预测 $z_{t+1}$ 的位置可能直接读取输入中位置 $t+1$ 的内容，造成标签泄漏。低训练/验证 loss 不再证明模型具备生成时所需的前缀预测能力。

</details>

<details>
<summary>3. 提示词不计 loss，是否意味着回答不能注意到提示词？</summary>

不意味着。计分掩码控制哪些目标贡献损失；注意力可见性控制网络可以读取哪些输入。提示词通常正是回答预测所需的上下文。

</details>

<details>
<summary>4. model.eval() 后 loss.requires_grad 仍为 True，是框架坏了吗？</summary>

不是。eval 与求导开关独立。评估通常既切换模块模式，又在不需要求导时禁用梯度记录；之后返回训练要恢复训练模式。

</details>

<details>
<summary>5. 两次加载相同权重，为什么下一步更新或生成仍可能不同？</summary>

更新可能有不同的优化器状态、学习率、数据批次、随机状态或精度条件；生成可能有不同 tokenizer、提示、解码规则或随机抽样。权重一致只固定了其中一部分条件。

</details>
