# 稳定计算与梯度诊断：找到第一个失去意义的量

## 1. 先建立证据顺序，不要先调一个“更稳”的超参数

看到 loss 突然变大、梯度为零或 `NaN`，立刻降低学习率、加裁剪、换 dtype，可能让症状暂时消失，却没有回答错误从哪里开始。

本页采用一条诊断链：

> 输入与计分契约 → 前向数值 → 输出分布 → 反向梯度 → 实际参数更新。

每一站先判断定义是否成立，再判断尺度是否异常。浮点位宽、范围、稳定 softmax 与 logsumexp 的推导见 [bridge07](#/c/stanford-cs336-2026/lec/bridge07?v=notes)，这里不重新讲一遍；反向传播和叶子语义见 [bridge03](#/c/stanford-cs336-2026/lec/bridge03?v=notes)。

一份最小故障记录应能回答：发生在哪个有效更新编号、哪一批数据/有效目标集合、哪个张量角色、shape/dtype/device、哪个梯度累积阶段；若启用 loss scaling，还要记录 scale 和本次更新是否被跳过。不要只留下“第100步炸了”。

## 2. 第一站：先确认检查的是有意义的输入

| 检查对象 | 先问什么 | 常见误判 |
| --- | --- | --- |
| token ID | 是否为整数，是否落在词表范围，词表身份是否匹配 | ID 合法就以为 tokenizer 一定匹配 |
| 输入与目标 | shift、位置、文档边界是否正确 | loss 很低就以为没有标签泄漏 |
| 计分集合 | 有效目标数量是否大于0，分母是否一致 | 空集合强行输出0 loss |
| 张量形状 | batch/time/feature/vocabulary 轴是否对应 | 能广播、能运行就以为语义正确 |
| 参数与普通激活 | 进入计算前是否已有 `NaN`/`inf` | 只检查最终 loss |

只有检查完这个接口，数值诊断才有可靠对象。目标错一位、把 token 总损失与 token 平均损失混用，都能制造异常梯度尺度；这不是更高精度能修复的错误。

### “有限值检查”也要尊重角色

`torch.isfinite` 用于区分有限值与 `NaN/±inf`，但不能机械要求每个中间张量所有元素有限。例如，加性 attention mask 中的 `-inf` 可以是明确约定的禁止标记；**掩码前的正常分数**与**掩码后的受限分数**必须分开检查。

若某一需要归一化的行没有任何允许的位置，数学上没有正常的概率分布。先修复数据/掩码契约，而不是把 `NaN` 替换成0后继续训练。是否跳过 padding 查询行也必须有明确语义，不能靠 softmax 的偶然后端行为决定。

## 3. 第二站：找第一处异常，而不只盯着最大绝对值

缩小到可重复触发问题的输入后，在较粗的模块边界观察；发现前一站正常、后一站异常，再缩小到这个区间里的运算。这样比长期记录所有激活更清楚，也避免诊断自身制造巨大内存/同步开销。

对一个普通浮点张量，可以先记录：

- 非有限元素的数量与第一个位置；
- 有限部分的最小/最大值、均值与 RMS；
- 适合该算子的分位数、零值比例或离群值比例；
- 统计口径：全张量，还是逐 token、逐特征、逐层。

不要只报告全局均值。两个 batch 的数值相反可能抵消；一个极端位置可能被百万个正常位置淹没。RMS 对尺寸的归一化定义为

$$
\begin{aligned}
\operatorname{RMS}(a)
&=\sqrt{\frac{1}{n}\sum_{i=1}^{n}a_i^2},\\
&\qquad n>0.
\end{aligned}
$$

它仍会受归约精度与极端中间平方影响。有限元素的范数也可能因计算中间量溢出而变成 `inf`；必要时在很小的诊断样本上先转更高精度再比较，而不是事后把已溢出的范数转为 FP64。高精度对照是定位手段，不是“所有训练张量一律转 double”的建议。

### 输出分布的检查比“logits 很大”更有信息

同一位置的 logits 整体加上一个有限常数，数学上的 softmax 分布不变。因此只看到 logits 均值为1000，不能断言分布已经异常；应同时观察相对差距、归一化结果、真实目标概率和熵。

对位置 $(b,t)$，熵是在**词表轴**上求和：

$$
H_{bt}=-\sum_{v=1}^{V}p_{btv}\ln p_{btv}.
$$

概率为零的项按 $0\ln0=0$ 的连续极限理解。均匀分布的熵是 $\ln V$，不是 $\ln(BT)$；若候选集合被另外限制，要按那套明确分布解释。低熵可能表示自信，也可能是塌缩；高熵可能表示不确定，也可能是健康的困难样本。**不存在脱离数据、训练阶段和分布定义的统一“健康熵阈值”。**

可以把初始 loss 与均匀词表预测的 $\ln V$ 作量级参照，但真实随机初始化不保证严格等于它。异常低 loss 首先排查标签泄漏；异常高 loss 同时看目标概率和计分分母，而不是只看一条平均曲线。

## 4. 有限的 loss 不保证有限的梯度

原因有两类：

1. 终点值合法，但局部导数有奇点。
2. 非法中间运算虽然没进入最终可见值，仍留在反向图里。

最小的第一类例子是 $L=\sqrt{x}$ 在 $x=0$：$L=0$ 有限，但右侧导数 $1/(2\sqrt{x})$ 无界。这不是“loss 已经最优，所以梯度必须是零”。

独立 CPU 反例 A，不包含模型或训练：

```python
import torch

x = torch.tensor(0.0, dtype=torch.float64, requires_grad=True)
loss = x.sqrt()
loss.backward()
print(loss.item(), x.grad.item())
print(torch.isfinite(loss).item(), torch.isfinite(x.grad).item())
```

根据该 API 的导数约定，预期为 `0.0 inf` 和 `True False`。此处应该先反思目标定义在该点是否适用，不是盲目裁剪一个非有限梯度。

第二类常见于“先除零，后把结果屏蔽掉”：最终 loss 可能有限，但 autograd 仍对已经记录的除法求导，产生非有限贡献。正确思路是让不合法的运算根本不在那条计算路径中发生，并保留你真正想表达的有效元素集合；不是用输出掩码、`nan_to_num` 或 `detach()` 掩盖原因。即使使用条件选择 API，也要弄清两个分支的表达式是否已在选择前被计算。

## 5. 第三站：把梯度的三种状态分开，再看尺度

先对应该训练的参数区分：

| 状态 | 诊断方向 |
| --- | --- |
| `.grad is None` | 未反向、当前路径未使用、清零时机、冻结或意外断图；若看的是非叶子，先核对保留规则 |
| 零梯度 | 真正零导数、分支/掩码、抵消、饱和、低精度下溢等；不是自动说明断图 |
| 非有限梯度 | 前向非法操作、反向奇点、范围溢出或归约问题；先找发生位置 |

只统计一个总范数会把这些差别压扁。模型有条件分支时，某些参数在当前批次没有梯度可能符合设计；稠密路径中本该使用的参数突然全为 `None` 则值得追踪。不能用“把所有 None 变成零”来消除警报。

### 每层至少把尺寸与尺度分开

对第 $k$ 组参数，定义

$$
\begin{aligned}
G_k&=\|g_k\|_2,\\
R_k&=G_k/\sqrt{n_k},\\
U_k&=\frac{\|\Delta\theta_k\|_2}
{\|\theta_k\|_2+\varepsilon}.
\end{aligned}
$$

$n_k$ 是该组参数元素数；$R_k$ 是梯度 RMS，便于避免仅因大矩阵元素多就把它判为“梯度更不稳”。$\Delta\theta_k$ 则是更新前后参数差，不是原始梯度。比较 $U_k$ 时，零初始化或极小参数范数会让分母敏感，应单列解释，不设普遍阈值。

这三者回答不同问题：$G_k$ 看该组总梯度量级，$R_k$ 看每元素尺度，$U_k$ 看实际参数变化相对现有参数的大小。自适应优化器、历史状态、衰减与学习率都会让“梯度大”和“更新大”不完全同步；详细动态见 [ext02](#/c/stanford-cs336-2026/lec/ext02?v=notes)。

观测时要注明是 **scaled/unscaled、裁剪前/裁剪后、微批/有效批次** 的梯度。把这些阶段混到同一曲线上，曲线跳变本身就没有可解释性。共享参数也只能作为同一份参数统计一次，不按引用次数重复计入范数。

### 何时使用 anomaly detection？

当问题已缩小但具体反向节点不明时，可临时启用 `torch.autograd.detect_anomaly()`，并让相关**前向和反向都处于检测上下文**，以保留失败反向对应的前向调用线索。默认 `check_nan=True` 针对反向产生的 `NaN` 报错；不要把它当成捕获所有 `inf`、语义错误或不良训练动态的万能检查器。

它有明显额外开销，适合缩小后的故障片段，不适合未经说明地常开后再报告训练吞吐。有限值检查、形状/轴检查仍各有职责。

## 6. 用方向导数核对梯度，而不是逐个扰动百万参数

对很小、平滑、确定的函数 $f$，选单位方向 $d$。自动微分给出的梯度应满足

$$
\begin{aligned}
q_{\mathrm{AD}}&=\nabla f(x)^\top d,\\
q_{\mathrm{FD}}&=\frac{f(x+hd)-f(x-hd)}{2h}.
\end{aligned}
$$

中心差分在足够平滑时具有 $O(h^2)$ 截断误差；$h$ 太小又会放大减法消去和舍入。应在合理的几个步长上观察趋势，而不是选一个极小 $h$ 就认为它是精确真值。不可微点、随机 Dropout、不同分支或离散采样都会破坏简单比较的前提。

独立 CPU 微例 B，只验证一个自拟四次多项式的导数，不实现任何作业算子：

```python
import torch

x = torch.tensor([1.0, 2.0], dtype=torch.float64, requires_grad=True)
d = torch.tensor([0.6, -0.8], dtype=torch.float64)
f = lambda q: q.square().sum().square()
(g,) = torch.autograd.grad(f(x), x)
with torch.no_grad():
    h = 1e-4
    finite_difference = (f(x + h * d) - f(x - h * d)) / (2 * h)
print(g.tolist())
print(f"{torch.dot(g, d).item():.6f} {finite_difference.item():.6f}")
```

解析值：$f(x)=25$、$\nabla f(x)=(20,40)$、方向导数为−20。预期第一行是 `[20.0, 40.0]`，第二行打印两个 `-20.000000`；核对数值可用绝对误差 $10^{-5}$，不要求所有浮点位相同。通过一次方向检查也只提供这个点和这个方向的证据，不证明整个实现处处正确。

## 7. 梯度裁剪：限制有限梯度，不是修复 `NaN`

把所有待更新参数的梯度逻辑上连接为一个向量 $g$，全局二范数为

$$
\begin{aligned}
G&=\sqrt{\sum_k\sum_i g_{k,i}^2},\\
\widetilde g&=\alpha g.
\end{aligned}
$$

理想的范数裁剪规定：$G\le M$ 时 $\alpha=1$；$G>M$ 时 $\alpha=M/G$，其中 $M>0$ 是阈值。这对非零梯度做统一缩放，保留整体方向。实现可在分母加入小 $\varepsilon$ 防止除零，使裁剪后范数略小于阈值；不要把微小差异当作另一个优化算法。

例如 $g=(3,4)$，$G=5$，阈值 $M=2$，理想结果为 $(1.2,1.6)$。逐元素截断到 $[-2,2]$ 会得到 $(2,2)$，既不是同一个范数限制，也改变了方向。

应记录**裁剪前**的范数与发生裁剪的比例；只看裁剪后每次都接近 $M$，会掩盖原梯度正在逐渐失控。总是触发裁剪可能来自任务尺度、分母、异常数据或超参数，不能只得出“阈值需要再小一点”。

PyTorch 的 `clip_grad_norm_` 在原地修改梯度，并返回所计算的总范数；可启用 `error_if_nonfinite=True` 在总范数非有限时明确报错。这个 API 说明用于理解行为，**不是允许在要求从零实现的 A1 组件中直接调用它**。`inf` 或 `NaN` 不是一个正常的“大梯度”，裁剪也不能恢复已经丢失的数学信息。

## 8. 梯度累积：先让目标函数相同，再谈“大批次等价”

第 $i$ 个微批有 $n_i$ 个有效目标，平均损失为

$$
L_i=\frac{1}{n_i}\sum_{j=1}^{n_i}\ell_{ij}.
$$

希望优化这一整个有效批次的 token 平均损失时，必须有

$$
\begin{aligned}
N&=\sum_i n_i>0,\\
L&=\sum_i\frac{n_i}{N}L_i,\\
\nabla L&=\sum_i\frac{n_i}{N}\nabla L_i.
\end{aligned}
$$

因此“每个微批 loss 除以微批数 $K$”只在 $n_i$ 全相同时对应这个目标。不等长、padding、选择性计分或最后一个不完整窗口，都可能使它不成立。

自拟标量检查：两个微批有效数为2、6，平均损失的某个梯度分量为1、3。正确贡献是 $2/8\times1+6/8\times3=2.5$；简单平均是2，已经优化了另一套权重。分母错误不会被自动微分发现，因为框架会忠实求出你写下的错误目标的导数。

“大批次等价”还要求参数在这些微批之间不更新、目标可加，并正确处理批次依赖与随机性。像依赖当前批次统计的模块，拆分微批可能改变前向函数；即使数学目标相同，浮点归约路径和随机实现也不承诺逐位一致。

### 为什么要先累积，再裁剪一次？

裁剪是非线性操作，通常有

$$
\begin{aligned}
&\operatorname{clip}(g_1+g_2)\\
&\quad\ne\operatorname{clip}(g_1)
+\operatorname{clip}(g_2).
\end{aligned}
$$

把已经按目标正确加权的两份贡献设为 $(6,0)$ 和 $(0,8)$，阈值为5：

- 先相加得 $(6,8)$，范数10，再裁剪得 $(3,4)$。
- 各自裁剪得 $(5,0)$ 与 $(0,5)$，相加为 $(5,5)$，范数还大于5。

所以若目标是限制**一次参数更新所用的全局梯度**，应在该有效批次累积完之后裁剪，而不是每个微批各裁一次。每个微批清梯度或更新优化器，也分别改变了累积结果或优化轨迹。

## 9. 混合精度：两个机制、一个不可乱的顺序

`autocast` 与 loss scaling 解决不同问题：

- **autocast** 根据算子选择计算 dtype；不等于把所有参数、状态与运算统一变成16位。
- **loss scaling** 将标量目标乘上 $s>0$，使反向信号在低精度中更不易下溢。在实数算术中，$\nabla(sL)=s\nabla L$，更新前需去掉这个尺度。

Scaling 不能修复已经溢出的前向，也不会提升低精度尾数精度。使用 BF16、FP16 或其他方案时，是否需要 scaler 取决于实际范围与实现，不能仅由“混合精度”四个字断言。

在普通**单优化器**、带梯度累积和范数裁剪的流程中，关键顺序如下：

| 次序 | 操作语义 | 不能提前做什么 |
| --- | --- | --- |
| 1 | 为整个有效批次清梯度；确定分母 | 不在每个微批清掉旧贡献 |
| 2 | 每个微批前向并形成正确加权的目标 | 不把各微批都当成完整平均目标 |
| 3 | 用同一个 scale 反向，累积 scaled 梯度 | 不在中途改变 scale 或去缩放 |
| 4 | 所有贡献到齐后，对该优化器去缩放一次 | 不重复 `unscale_`，也不再混入 scaled 梯度 |
| 5 | 检查/记录未缩放、裁剪前的梯度，再作裁剪 | 不对带 scale 的值套原阈值 |
| 6 | 由 scaler 的 step 机制决定调用或跳过优化器更新 | 不绕过检测后直接无条件更新 |
| 7 | 更新 scale，记录真实更新状态，进入下一窗口 | 调度/步数推进必须遵守声明的时钟 |

PyTorch 文档建议 autocast 包围前向与损失计算，不推荐把 backward 也置于 autocast 区域。反向会按相关前向所选的 dtype 运行；不能期待在反向外层临时开 autocast 就重写已有前向的数值信息。

### 两个可手算的顺序错误

**在去缩放前裁剪。** 真正梯度 $g=(3,4)$，$s=100$，阈值5。对 scaled 梯度 $(300,400)$ 裁成 $(3,4)$，再除100，得到 $(0.03,0.04)$；本来无需明显缩小的梯度被缩小了100倍。

**累积到一半去缩放。** 第一微批已去缩放得到 $g_1$，第二微批又加入 $s g_2$，缓冲区变为 $g_1+s g_2$。最后再除 $s$ 得到 $g_1/s+g_2$，不等于目标 $g_1+g_2$。所以 scale 与是否去缩放必须在同一有效窗口内一致。

检测到非有限梯度后跳过更新，是 scaler 的数值保护，不证明根因已解决。应保留该批次与失败阶段信息；持续跳步、scale 持续下降或 loss 异常，都应返回前面的证据链定位。

## 10. 一个可执行的诊断决策顺序

这是一套检查问题的顺序，不是新的训练框架：

1. **目标或轴不明？** 先手写一个位置的前缀、目标和分母；停止讨论学习率。
2. **输入已有非有限值？** 追到数据或参数来源；不要让后续替换值隐藏问题。
3. **前向首次异常？** 缩小到该算子，检查定义域、掩码、极端值和计算 dtype。
4. **前向正常、反向异常？** 查局部导数奇点、非法路径与图的连接；必要时用 anomaly detection 和小型高精度方向对照。
5. **梯度存在且有限，但尺度异常？** 核对有效目标权重、累积阶段、scale 和裁剪阶段，再看逐层分布。
6. **梯度正常、更新异常？** 对照实际参数差，转到优化器状态、学习率和调度器分析，而不是重新归罪于 autograd。

在固定的小反例上只改变一个因素，记录前后证据。这个流程不要求先购买 GPU 或下载完整训练集；它也不把 CPU 微例通过包装成官方模型训练成功。

<details>
<summary>1. loss 有限，但一个参数梯度为 inf，能排除数学定义问题吗？</summary>

不能。$\sqrt{x}$ 在0的例子就是有限前向值和无界导数。还要考虑被最终掩码遮住、却已记录在反向图里的非法中间运算。

</details>

<details>
<summary>2. 两层总梯度范数相差十倍，较大的一层一定更不稳定吗？</summary>

不一定。元素数、参数尺度和任务角色都可能不同。应至少比较每元素 RMS、非有限/零比例和实际相对更新，并保持缩放/裁剪阶段一致；不能仅按总范数排序判定故障。

</details>

<details>
<summary>3. 两个微批有效目标数为1和3，平均损失梯度分量分别为8和0，合并梯度是多少？</summary>

按有效 token 平均目标，应为 $1/4\times8+3/4\times0=2$。微批均值再平均会得到4，相当于给第一个微批中的每个 token 更高权重。

</details>

<details>
<summary>4. 先裁剪每个微批，再累加，能保证最终范数小于阈值吗？</summary>

不能。本页 $(6,0)$ 和 $(0,8)$ 的例子各裁到范数5后，相加范数为 $\sqrt{50}>5$。若约束的是本次更新的梯度，应在贡献正确累积后对总梯度裁剪。

</details>

<details>
<summary>5. GradScaler 跳过一次更新后，loss scale 变了，能直接说训练已经恢复健康吗？</summary>

不能。跳过只是避免将那次非有限梯度用于参数更新；要核对后续是否恢复正常、数据/前向是否仍有问题，并记录更新时钟与调度策略。scale 数值本身不是训练质量指标。

</details>
