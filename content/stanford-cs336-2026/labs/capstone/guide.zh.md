# 综合项目指导：从问题卡走到可信的负结果

研究最容易浪费预算的时刻，不是训练很慢，而是**尚未确定实验能回答什么就开始训练**。本页按“下一步做什么、留下什么证据、何时不能继续”组织；完整交付合同见[项目说明](#/c/stanford-cs336-2026/lab/capstone?v=zh)。这是编者自拟 LAB 0，不是官方 Assignment 6。

所有运行步骤都指**学习者在取得数据、模型与计算授权后独立完成的操作**，不是本站已经执行的记录。没有授权时仍可完成问题卡、静态来源审查和预算推演，但状态只能写“设计完成／实验未运行”。下面不提供训练循环、官方函数实现、计分题答案或可代交的研究报告。

## 阶段 0．先让问题缩到能回答

拿出一张纸，用五个句子描述项目：

1. 我研究的对象是哪个固定模型与哪种任务。
2. 我只把基线中的哪一项，从什么设置改成什么设置。
3. 在什么资源约束下，我预测主指标向哪个方向改变至少多少。
4. 哪个机制可能造成改变，哪个竞争解释也会造成同样表象。
5. 观察到什么时，我会写“不支持预测”或“现有证据不足”。

如果第二句同时含“更大模型、更好数据、新优化器”，先删到一个因素；如果第三句只有“更高分”，先定义分母、采样预算和最低有意义差值；如果第五句写不出来，问题还没有可证伪性。

### 一个从宽问题缩到窄问题的过程

“去重有没有用？”没有说明在哪个训练分布、以什么成本、对谁有用。把它缩为：

> 在同一小模型、共享 tokenizer、同一跨集合隔离规则与固定训练 token 预算下，仅对训练池内完全重复文档执行每簇保留一份，能否降低固定新文档集的 token 平均 NLL？

然后由你补齐模型、预算、$\delta$ 和判断方法。竞争解释至少有两个：减少重复改变了有效数据多样性；同样 token 数也可能让较小训练池被重复采样更多次。记录簇大小、唯一文档／token 覆盖与重复次数，比只记录“去重后文件更小”更有解释力。

这是**问题形状示范，不是预写结论**。它不保证去重改善结果；若原数据几乎没有重复，这个干预可能弱到无法检验。此时在正式实验前收缩问题或换一个可测因素，不要人为制造一个对基线不公平的污染集。

**本阶段留下：** 问题卡第一版与一张配置差异表。差异表除主变量及其必然派生结果外应为空；新增连带差异必须进入结论边界。

## 阶段 1．做一次不用训练的资格审查

### 1.1 路线 A 的入口

确认你能解释自己模型的输入、shifted labels、有效目标 mask、loss 归约、一次 optimizer 更新、保存与恢复。若这些仍不清楚，回到[A1 指导](#/c/stanford-cs336-2026/lab/a1-basics?v=guide)完成概念和本人实现，不把“研究预算”花在未知的基础错误上。

选择已合法拥有、许可清楚、规模可控的文本。没有合适公共数据时，自写无敏感信息的小语料可用于端到端机制演练，但要把结论限制在该人工分布。不要为凑大规模直接爬取未知权利网页。

为默认去重题型按下列顺序建立数据身份：

1. 固定规范化方法和文档边界，保留原始 ID 到规范化哈希的映射。
2. 在不看模型成绩的前提下，用固定规则识别重复／近重复组；把同组内容分配到同一集合。文本审计服务于隔离，不用封存测试的难度或答案调整规则。
3. 冻结训练、开发、封存测试的组 ID；分词器只在训练部分拟合，然后供两组共享。
4. 从相同训练池派生“保留池内重复”和“每个完全重复簇保留一份”两版；开发与测试保持不动。
5. 登记文档数、唯一簇数、字节数、token 数及预计重采样次数。最终计算训练预算使用实际处理的 token，不能把唯一 token 数当已处理 token 数。

若完整数据只够很少文档，优先按来源／文档分组，宁愿承认统计不确定性大，也不要把一个长文档切成随机片段让前半进入训练、后半进入测试后声称完全独立。近重复方法会有漏报和误报；没有查到重复不等于证明无污染。算法背景只在[A4 指导](#/c/stanford-cs336-2026/lab/a4-data?v=guide)展开。

### 1.2 路线 B 的入口

先记录基座的**精确 revision 与阶段**。Base、SFT、Instruct 名字相似，但起始策略和训练历史不同；不能给实验组换成 Instruct，却给对照组保留 Base。

默认 SFT 题型需要合法的输入—回答训练对，以及不进入训练的任务评价集。选择课程已学的目标形式，明确监督位置、EOS／截断规则、参数是否全部可训练。若用低秩适配、量化或冻结层，须在两个学习率组中保持一致；这些不是随手打开的加速开关。

完成纸面权限审查后，才在**已批准的小额先导预算**内做不更新权重的开发集评价：

- 固定一版 prompt 和解码协议，保留实际输入、原始输出、停止原因与解析结果。
- 分开看“可解析但答错”“被格式／截断拒绝”“解析器误判”；不要只看一个 accuracy。
- 预先定义与项目相关的能力门槛和退化监测项；没有适用于所有模型的通用合格分数。若基线接近零或天花板，先判断任务是否有可研究的变化空间。
- 若拟做稀疏奖励 RL，还要检查有限先导样本中的非零奖励与组内变化。连续全零既可能是能力不足，也可能是错误 parser 或截断；排除测量错误仍无信号时，停止该 RL 方案，而不是承诺靠更长训练必然成功。

**只有研究对象与测量链都合格，才进入正式后训练比较。** 能力不合适时，可在未触碰最终测试前重选任务／基座并新建问题卡；不能继续沿用旧预注册，也不能把 A 的故事模型直接叫作数学基座。A5 已核原件对此的边界见[唯一任务正文](#/c/stanford-cs336-2026/lab/a5-reasoning?v=zh)。

**本阶段留下：** 权利台账、不可变划分清单、基座／tokenizer 身份，以及“允许继续／停止”的带理由决定。没有下载或运行就不填实测输出。

## 阶段 2．先算最坏情形，再分配试验

预算至少有三本账，不能互相替代：

- **训练账：** 所有尝试的处理 token、更新数、模型规模；
- **推理与评价账：** prompt token、生成 token、评价次数、评委调用；
- **实际资源账：** 设备时、墙钟时、峰值显存／内存、磁盘和费用。

先给正式比较留够四对运行的额度，再分配先导、开发、失败恢复和复现额度。先导可以决定可行性；不能先用掉大半预算寻找幸运配置，再把没有重复试验解释成“研究已经足够清楚”。

### 2.1 原创纸面预算：八次正式训练不是一次

**以下全部是假设，不是硬件实测或推荐配置。** 假设稠密模型计入 $N=12{,}000{,}000$ 个参数；基线／实验组各四个 seed，每 run 处理 $40{,}000{,}000$ 训练 token；另允许两次先导，每次最多 $4{,}000{,}000$ token，且不再允许额外重试。

$$
\begin{aligned}
D_{\mathrm{all}}&=2\times4\times40{,}000{,}000\\
&\quad+2\times4{,}000{,}000\\
&=328{,}000{,}000.
\end{aligned}
$$

采用粗略训练记账近似：

$$
C_{\mathrm{proxy}}=6ND_{\mathrm{all}}
=2.3616\times10^{16}\ \text{FLOPs}.
$$

这是**累计训练量估计**，不是任何机器的预计耗时。评价、存盘、预处理、注意力细节和实际效率不由这个数保证；还必须为其设置单独上限。正式运行若失败，已处理 token 从总额扣除，不能把它当作从未发生。恢复还会重算哪些 token，也要入账。

一次参数更新要分别记录样本数、**实际计算的 token 位置**与**参与目标的有效监督 token**，不能统称一个 batch 数。梯度累积增加 microbatch 数，不自动增加 optimizer step 数；padding、被 mask 掉的 prompt 标签与有效监督位置应分列。mask 取消监督不等于取消前向计算，因而 loss 分母不能直接当作 FLOPs 账本的 $D$。上述纸面例子假定所有处理 token 均按同一稠密计算约定计数；真实后训练还须记录这些差异。

### 2.2 评价本身也能耗尽预算

另设一个**纯计数假设**：两个训练组、各四个 seed，每 run 五次开发集评测；每次 200 道题，每题采一条，最多生成 256 tokens。开发评价的输出 token 上界为：

$$
2\times4\times5\times200\times1\times256
=2{,}048{,}000.
$$

它**不包括** prompt 前向、未更新基座基线、封存测试、先导评价和任何训练 rollout。将五次开发评价的数误写成“全项目推理预算”，是预算遗漏，不是优化。若把每题采样数从1改成8，这一部分上界也扩大8倍，而且评价指标的含义随之改变。

### 2.3 让停止条件真的能执行

在自己的运行入口中设计额度检查，而不是只在报告里写“控制预算”。需要回答：

- 当前账本已消耗多少？下一次最大可能消耗多少？
- 距离墙钟／设备时／磁盘上限还有多少？是否预留写终止记录的余量？
- 超时、非有限数、权限失效、污染发现和退化阈值触发时，留下什么终止状态？
- 重试是否已经用完？中断恢复算原 run 的延续还是新尝试，怎样避免重复记账或漏账？

本页不提供调度器或训练脚本。你须独立实现并在已授权的小先导中确认停止行为。预算不容许验证完整训练时，可以先做静态预算审查；不能把未测试的停止机制写成“已验证”。

**本阶段留下：** 含数字硬上限的总预算、每 run 配额、最坏情形算式和终止状态定义。费用为0也要写0；不能用“按需增加”代替上限。

## 阶段 3．把测量系统先做对

### 3.1 A：指标下降之前，先问分母对不对

用自己手算得出的微型输入检查数据边界、目标对齐与归约；再在授权范围内做极小先导，确认损失有限、梯度路径存在、一次更新语义与记录一致。检查保存／恢复时，不只问“权重能读回来”，还要看优化器、调度器、随机数和数据游标是否一致。定位问题可回链[A1 排错指导](#/c/stanford-cs336-2026/lab/a1-basics?v=guide)，不要直接搬来官方测试答案。

**原创归约算例，非模型结果：** 两段文本分别有2和8个有效目标 token，总负对数似然分别假设为6和8 nats。token 平均应为：

$$
\begin{aligned}
L&=\frac{6+8}{2+8}=1.4\ \text{nats/token},\\
\mathrm{PPL}&=e^{1.4}\approx4.0552.
\end{aligned}
$$

若先算每段均值再平均，得到 $(6/2+8/8)/2=2$；这是**文档等权**指标，不是上面声明的 token 等权指标。两者都能定义，但不能算了一个却报告另一个。跨 checkpoint 评价要使用同样的文档边界与上下文策略，避免改变“给了多少前文”后仍当成模型能力差。

### 3.2 B：训练指标与任务成功分开

固定一份不参与调参的解析器规则说明，并用**自己构造的非题库诊断输入**检查空输出、截断、多答案、单位、符号和无效格式。诊断输入是程序边界检查，不是 benchmark 成绩。

对默认 SFT 学习率比较，两组须使用同一监督样本、同一 response／whole-document 目标定义、同一有效 token 归约和相同可训练参数集合。你选择的目标合同须明确，不能把不同课程实验的 mask 约定混在一起。监督 loss 下降并不保证自由生成下的答案正确率提升，因此训练曲线与冻结协议的任务评价应分开保存。

如果选择 RL，只用训练 reward 作为证据会产生闭环：同一个 parser 的漏洞既奖励模型，又给模型打高分。留出任务评价、解析失败审计和少量预定的人工复核共同帮助识别这种情况；人工复核不应事后只挑对自己有利的例子。算法细节只在[A5 指导](#/c/stanford-cs336-2026/lab/a5-reasoning?v=guide)与[后训练目标专题](#/c/stanford-cs336-2026/lec/ext14?v=notes)展开。

### 3.3 先导可以改变计划，但不能擦掉历史

发现明显错误后停止受影响运行，登记错误、修正 commit、废弃范围和花费；再决定剩余额度是否足以重启。变更主指标、样本划分或主变量时，给问题卡升版，旧运行标为探索／失效，不与新确认性结果混画成一条连续成功曲线。

**本阶段留下：** 测量检查记录、先导日志与修订记录。小批量能过拟合只能说明部分训练链可工作，不能证明泛化或正式实验已经完成。

## 阶段 4．执行冻结的比较，而不是追逐最好 seed

先导合格后，冻结配置、seed 列表、执行顺序、评价时点和最终 checkpoint 规则。可将成对运行交错或按预注册顺序随机安排，减少“所有基线在设备空闲时、所有实验组在拥堵时”的系统差异。相同 seed 只是配对约定，不能保证数据改变后随机数调用序列仍一一对应；记录可共享与不可共享的随机性。

![四对运行才是四个训练层面的比较单位；同一模型多采样不能增加独立seed数](assets/paired-evidence.svg)

每次运行保留独立目录与唯一 ID，不覆盖旧结果。逐步记录训练 token／更新数／实际时间；评价保存样本 ID、原始输出或逐文档 NLL、解析状态及版本。运行没完成时仍保留已完成区间；图中中止点明确断开，不用插值把缺失部分补成一条曲线。

**checkpoint 规则必须前置。** 固定预算终点最易比较；若按开发指标选最好 checkpoint，两个训练组用相同规则、同样评价机会，并记录选择产生的额外成本。测试集不参与选择。因安全／资源提前停止的模型不再满足完整终点预算，应按预注册失败处理，或另报明确标注的公共训练区间分析；不能悄悄与完整预算模型等价比较。

**本阶段留下：** 全部尝试账本和不可变原始日志。即使一组表现很差，也不能临时增加其学习率搜索，再假装主比较从未变过。

## 阶段 5．区分三种不同的不确定性

### 5.1 训练重复：先算配对差，再做汇总

把改善方向统一成“越大越好”：对 A 的 NLL，令 $d_s=L_{\mathrm{base},s}-L_{\mathrm{new},s}$；对 B 的正确率，令 $d_s=a_{\mathrm{new},s}-a_{\mathrm{base},s}$。对 $S$ 个**有效且按合同完成的独立配对**：

$$
\bar d=\frac1S\sum_{s=1}^{S}d_s,\qquad
s_d=\sqrt{\frac{\sum_s(d_s-\bar d)^2}{S-1}}.
$$

展示每个 $d_s$、均值和样本标准差；只有一个配对时样本标准差未定义，不能填0。失败配对另报且不得通过只取成功者来声称原四对实验整体成功；若比较被失败打断，完整案例分析只能作带选择偏差警告的补充。

如果独立配对差近似正态，可以给出均值差的 Student-$t$ 区间：

$$
\bar d\ \pm\ t_{S-1,\,0.975}\frac{s_d}{\sqrt S}.
$$

这是**有假设的均值区间，不是 seed 的覆盖区间**，也不是“真实均值有95%概率在这一次区间里”的无条件保证。四对样本很少，无法可靠检验正态性；应展示原始差值并承认脆弱性，不能因套了公式就把结论写得确定。这里是编者的统计建议，不是在改写官方评分合同。

**原创手算示例，绝非运行成绩：** 假定四个配对差是 $[0,1,2,1]$ 个百分点。则 $\bar d=1$、$s_d=\sqrt{2/3}\approx0.8165$ 个百分点，均值标准误约0.4082。采用 $t_{3,0.975}\approx3.182$ 时，区间约为 $[-0.30,2.30]$ 个百分点。即使均值为正，也不能据此确认存在改善，更不能确认超过预设的1.5个百分点门槛。反过来，区间含0也**没有证明效果严格为0**。

### 5.2 有限评价集：问题／文档才是重采样单位

同一组模型在同一测试集上的差值可以作**成对样本分析**：两组同一道题的结果一起进入重采样；若题目来自模板簇，整簇一起抽。路线 A 也按文档／来源簇处理，而不是把上下文相关的 token 当独立观测。

这类区间描述“固定模型在有限测试样本上的变化”；它与训练 seed 不确定性不是同一回事。不要把 $S$ 个模型乘 $n$ 道题直接当成 $Sn$ 个独立实验。若做分层重采样，须说明先抽 seed 配对、再抽样本簇的方案与适用假设；样本太少时宁愿同时给两个层面的描述，也不要输出一个看似精确、实际忽略相关性的误差条。

### 5.3 解码采样：重复回答不等于重训

固定一个 checkpoint，对同一道题生成8次，会改变采样方差与生成成本，但训练 seed 数仍为1。如果研究目标是 pass@1，不能通过“8次中选对的”提高分数后沿用 pass@1 标签。若研究 pass@k，提前定义其估计口径及是否允许答案选择器；选择器本身也有信息和成本。

**本阶段留下：** 逐 seed／逐样本汇总、区间方法、支持集和分母说明。主结论只围绕预注册主指标；额外分组、checkpoint 或提示发现标为探索，不进行无记录的多重挑选。

## 阶段 6．按证据层级排错，不把失败写成算法故事

| 观察到的现象 | 先核哪一层 | 可支持的有限判断 |
|---|---|---|
| A 训练 loss 降、留出 NLL 升 | 数据隔离、重复覆盖、选择规则、相同评价上下文 | 可能过拟合或分布差异；还不能归因某架构“无效” |
| A 两组速度／token 不同 | 实际 batch、padding、数据等待、序列长度与存盘 | 先校准成本；不能以相同 step 宣称等算力 |
| B reward 全零 | 原始输出、停止原因、答案提取、基座阶段 | 测量错误与能力不足尚需分开 |
| B loss 更好但任务分数不变 | 监督目标、mask、自由生成协议和长度分布 | 优化了 surrogate 不等于改进主任务 |
| B reward 提升但独立评价不升 | 评分漏洞、污染、prompt／parser 差异 | 可能学会利用测量链；不是已证实能力提升 |
| 只有最好 seed 明显提升 | 全部 seed、开发搜索投入、失败是否遗漏 | 单次幸运与稳定改善不同 |
| 重启后曲线跳变 | 优化器／调度器／随机数／游标恢复 | 权重可加载不等于运行连续 |
| 只有某一组频繁 OOM | 最大长度、batch、可训练参数与内存账 | 这是可行性结果；失败不能从成本和分母消失 |

诊断顺序通常是：**身份与权限 → 数据／评价 → 实现与数值 → 成本公平性 → 统计证据 → 机制解释。** 前一层不成立时，后一层的故事再漂亮也不能补救。

负结果段落不需要为方法“辩护”。先写原预测，再写观察支持到哪里，列出仍混淆的因素。只有在本次预算中实际做了区分实验，才能说排除了某解释；否则写“尚不能区分”。没有运行时，“预期会收敛”“应该能达到”均不能进入结果栏。

## 阶段 7．交给别人复算，而不只是交一张图

组织工件时，从报告中的一个数倒推：它来自哪个汇总过程、哪些逐样本记录、哪次 run、哪个 checkpoint、哪版配置与数据。若有一步只能靠你记忆解释，证据链还没闭合。阅读方法可回看[技术报告与源码阅读](#/c/stanford-cs336-2026/lec/ext16?v=notes)。

在已预留的预算内分层检查：

1. **数字复算：** 用保存预测／NLL与固定 evaluator 重建表格，核失败计数和分母。它不需要重训，但解析器变化会产生新评价版本。
2. **恢复检查：** 若已授权，用极小先导确认中断恢复与不中断路径在声明容差内一致；不要为这个检查自动启动完整新训练。
3. **独立重复：** 只有真的换干净环境重跑过，才报告该层已完成。缺硬件或权限时列出依赖、步骤与未做原因。

报告中把“支持改善”“观察到退化”“证据不足”“运行失效”“未运行”作为不同状态。一个记录完整、可复现的负结果比一张无法追溯的高分图更符合本项目目标。报告正文所需章节与最低工件清单只在[说明页](#/c/stanford-cs336-2026/lab/capstone?v=zh)列出，这里不提供可直接代交的成文答案。

## 自测：你能拒绝一个看起来更好的结果吗？

### 基础：共同去污染后，基线还能保留训练池内部重复吗？

<details><summary>展开提示与答案</summary>

先区分跨集合泄漏和训练分布。若研究主变量正是训练池内去重，基线可以保留池内重复；但训练与开发／测试之间的同簇内容必须共同隔离。实验组独享去污染、基线保留测试泄漏，不是公平对照。

</details>

### 基础：一台设备跑两小时，和两台设备各跑一小时，成本一样吗？

<details><summary>展开提示与答案</summary>

累计设备时都为2小时，墙钟时不同；设备型号、功率、价格、利用率和通信开销还可能不同。设备时相同不是 FLOPs 相同或费用相同，不能只报最快的一项。

</details>

### 进阶：基线失败一个 seed，能否删掉它再对比另外三个？

<details><summary>展开提示与答案</summary>

不能静默删除。先区分预注册允许的基础设施重试与方法本身失败，保留花费和失败率。三个完成配对可作为明确标注的补充分析，但只看成功者会产生选择偏差，不满足原四对正式比较；完整失败审计本身可以交付。

</details>

### 进阶：换了 tokenizer，perplexity 下降，是否足以说模型更好？

<details><summary>展开提示与答案</summary>

不够。token 粒度、序列长度、参数和训练／评价成本可能都改变。须固定同一原始文本，重新注册可比较的文本概率归约与预算口径；不能把不同 token 单位的平均 loss 直接相减。初次研究固定 tokenizer 更容易辨认主变量。

</details>

### 研究：区间包含0，但所有日志、失败和成本都真实，项目是否失败？

<details><summary>展开提示与答案</summary>

预测可能未获支持，研究交付却可以合格。结论应说明在当前规模、预算与不确定性下未确认改善，并区分“可排除的效应范围”和“仍不确定的效应”。不追加未授权算力、不换主指标，也不把未显著误写成等效性证明。

</details>
