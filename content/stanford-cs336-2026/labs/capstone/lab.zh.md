# 自拟综合项目：让一个小结论经得起复核

**这是编者自拟研究项目，不是 Stanford 官方作业，也不是 Assignment 6。页头 LAB 0 仅为本站编号。** 你要完成的不是“训练出最大的模型”，而是提出一个可能被实验推翻的问题，让别人能检查你究竟改变了什么、花了多少资源、结论支持到哪里。

**在两条独立路线中选一条即可；不要求先做 A 再做 B。** 本页规定交付与验收；[实验指导](#/c/stanford-cs336-2026/lab/capstone?v=guide)讲怎样逐阶段做决定、排错和解释证据，不提供训练实现或现成结论。

## 1．选择研究对象，不跨越能力边界

### 路线 A：自己训练的小模型预训练研究

从随机初始化训练自己实现的小型语言模型，研究数据、架构或优化中的**一个主变化**。主指标通常是固定留出文本上的 next-token 负对数似然，而不是数学解题能力。先具备[A1 的模型、训练与保存恢复能力](#/c/stanford-cs336-2026/lab/a1-basics?v=guide)；需要时回看[A4 数据处理](#/c/stanford-cs336-2026/lab/a4-data?v=guide)。这不要求重跑官方全部实验，也不把缩小规模称作官方作业等价完成。

一个可选题型：在固定模型、分词器、训练 token 数及评测文本时，**训练池内完全重复文档每簇只保留一份**，是否改善未见文档的平均 NLL？主变化仅为训练池去重策略；跨训练／验证／测试的污染隔离对两组都必须实施，不能让基线故意泄漏。

也可研究一个预先指定的优化参数或架构开关。若修改分词器，便不能直接用不同 token 单位的 perplexity 比大小；须另注册可比较的文本级指标与预算口径。第一次项目优先固定分词器。

### 路线 B：有适当基础能力的开放基座后训练研究

选择许可允许、访问合法且在目标任务上具备相关能力的固定开放权重基座，研究 SFT、偏好学习或可验证奖励训练中的**一种方法、一个主变化**。先做不更新权重的基线和能力／解析审计，再决定是否训练。概念前置见[后训练目标专题](#/c/stanford-cs336-2026/lec/ext14?v=notes)，任务级排错见[A5 指导](#/c/stanford-cs336-2026/lab/a5-reasoning?v=guide)。

较易控制的题型：对固定基座、监督训练对、loss mask、更新步数和监督 token 预算，比较两个预先选定的 SFT 学习率。问题可以是“在冻结评测协议下，较高学习率能否带来至少 $\delta$ 的任务提升，同时不超过预先声明的能力退化上限？”这里的 $\delta$、两个学习率及退化指标必须由你在看结果前具体确定。它是原创项目设计，不是官方选做题的指定设置或答案。

若改选 RL，必须能说明奖励如何得到、哪些输出被判零，以及训练预算内是否存在可用学习信号；若改选偏好学习，须能审核成对数据的含义与固定参考模型。**SFT、DPO、RL 不能一齐更换后再声称检验了一个因素。**

A5 的真实例子是 OLMo-2-0425-1B base 与 GSM8K；其固定讲义明确区分了充分预训练的基座和课堂自己训练的弱小模型。**TinyStories 上会续写故事的小模型不等于 GSM8K 的适当基座。** 模型卡成绩也不能替代你在相同提示、解码、解析器和预算下的本地基线。B 的权重或资源不可获得时，可以停在设计审查，或另立项目选择 A；不得偷换对象后保留原结论。

## 2．交付一：一页预注册问题卡

在启动正式比较前，保存带日期与版本号的问题卡。必须回答：

1. **对象与范围：** 哪个模型／初始化方式、哪类数据、哪种硬件和哪项任务？结论最多推广到哪里？
2. **可证伪预测：** 主指标如何定义、越大还是越小越好？有实际意义的改善阈值 $\delta$ 是多少？什么观察会使你拒绝或暂不支持预测？
3. **唯一主变化：** 实验组和基线的配置差异是什么？列出其余固定项，包含训练与评测两端。
4. **机制预期：** 为什么可能有效？至少给出一个竞争解释，以及能区分两种解释的诊断量。诊断量不是事后替换主指标的借口。
5. **停止与判读：** 如何选 checkpoint、何时停止、怎样处理失败 seed、多重探索和最终测试？写明允许的修改流程。

**验收：** 读者只看这张卡就能判断一组未来结果是否支持预测。“试试更好的方法”“看看效果”不算问题；只给一个期待的高分不算可证伪预测。允许先做少量开发试验再预注册正式比较，但试验次数、成本与已看过的指标必须全部登记。

## 3．交付二：数据、模型和防污染台账

### 3.1 权利与身份

为每个数据源、模型、分词器及外部工具记录：发布者、固定 URL／版本、取得日期、文件哈希、许可正文或卡片声明、允许用途、是否允许再分发、访问方式和未确认事项。许可不明或审批未完成的内容不进入实际训练。

- **代码许可不覆盖数据；权重许可不覆盖整套训练语料。** 能读模型卡不表示已经取得权重，公开 URL 不表示可以无条件发布数据副本。
- 自写文本须确实拥有使用权且不含真实个人敏感信息；小样本机制研究不自动代表真实网络分布。TinyStories、网页语料或他人指令数据的具体版本都须单独核权，本项目不替它们统一发放许可。
- 固定 OLMo 模型卡声明 Apache-2.0，GSM8K 数据卡声明 MIT；它们只能支持相应对象的许可判断，不能覆盖 A5 讲义。数据卡仍有隐私／局限信息缺项，应在台账保留，而不是把缺项解读为无风险。
- 审批权重、课程共享卷、私有目录和账户不是公开下载地址；不索取他人凭据、不绕过门禁。默认不调用外部评委、云平台或收费服务。

### 3.2 划分与污染

先确定文档／题目来源簇，再固定训练、开发和封存测试划分。记录划分 seed、样本 ID／哈希、每组文档数与 token 数、去重规则和丢弃原因。近重复、同模板改写、同一原题的不同推理版本应按组处理，不能只随机打散文本行。

- 分词器训练、筛选阈值选择、超参数搜索和 few-shot 示例都只能使用允许的训练／开发部分。
- 路线 A 在所有组共同的隔离规则之后，只对**训练池内部**施加主变化。验证与测试不随实验组重新挑选。
- 路线 B 不把参考答案、标注推理或包含答案的题目变体泄漏到评测 prompt；保存最终实际输入，不能仅保存 prompt 模板名。
- 若已经把某个公开 benchmark 的 test 用作开发集，就如实命名为开发集。A5 正篇确有用 GSM8K 的 `test.jsonl` 作 validation 的约定；本项目若继承这种用法，不能再称它是未触碰的最终测试。
- 开放基座可能在预训练时见过公开题库。你能核查的是本项目可见的数据和操作，不是证明整个预训练历史无污染；最终报告须保留这一限制。

**验收：** 从任一评价样本能追溯到分组和使用历史；能说明“本项目未泄漏”与“基座从未见过”是两个不同主张。无法合法分享原文时，提供来源、合法重建步骤、ID／哈希和统计，不打包受限文本。

## 4．交付三：公平基线与不可透支的预算

### 4.1 基线要回答同一个问题

路线 A 至少比较“原设置”与“只改一项的设置”；路线 B 还保留**未更新基座**作能力参照。后者不是同训练成本的算法对照，正式训练效果仍需比较两个受同一合同约束的训练组。

| 固定项 | 必须写明的内容 |
|---|---|
| 初始状态 | 架构、权重／分词器版本；A 每对 seed 共享初始化，B 共享起始 checkpoint |
| 训练过程 | 数据版本、顺序／采样规则、有效 batch、loss 支持集与分母、优化器、精度 |
| 搜索投入 | 每组允许的开发试验数与搜索预算；不能精调实验组却故意保留弱基线 |
| 比较横轴 | 相同训练 token、更新数或实测计算预算中哪一个是主要约束；记录其他成本差异 |
| 评测过程 | 同一数据、prompt、截断、解码、解析器、指标定义及 checkpoint 选择规则 |

“同样一小时”“同样十个 epoch”“同样参数量”不是可以互换的公平定义。数据去重后相同 epoch 对应不同 token 数；架构／上下文变化后相同 token 数也不一定同 FLOPs。必须明确你检验的是**等数据预算效果**还是**等计算预算效果**，不能事后选有利的横轴。

### 4.2 预算是多个同时成立的上限

在计划里填入具体数值，空白上限不允许进入执行：

- 正式组数、每组 seed 数、开发试验次数和允许的重试次数；
- 训练 token、更新步数；B 还包括 prompt／response 长度、生成条数及总生成 token；
- 每 run 与全项目的累计设备时、墙钟时和磁盘占用；设备数量乘运行时计入设备时；
- 数据准备、预评测、定期评测、最终评测、失败运行、恢复和复现检查的开销；
- 货币总上限及授权者。默认外部收费额度为 **0**；套餐或账号存在不等于获得计算授权。

可用 $6ND$ 为稠密 Transformer 的训练计算量做粗略账本，其中 $N$ 是按同一约定计入的参数量、$D$ 是实际处理的训练 token 数。它忽略若干架构、注意力、硬件与实现开销，**不是时间、显存或账单保证**；后训练生成更不能直接塞进这个式子。

**停止合同：** 每次新任务／更新／生成／保存前检查剩余额度；预计下一步会越界时不启动。任一硬上限达到即停；出现非有限数、污染、权限问题或越过预注册退化阈值也停。超时 OOM 不无限重试，失败成本照记。提前停止规则应对两组一致；若完成的训练预算不再相同，不能仍标“等预算终点比较”。

**验收：** 最坏情形在纸上能算出总额；失败余量已预留；中止后仍能导出账本和可用日志。预算不够时，在正式比较前缩小模型／数据／问题或重新注册，不靠删 seed、隐瞒失败或追加未授权费用完成。

## 5．交付四：冻结评测协议与不确定性

### 5.1 主指标和诊断分开

**A：** 固定 tokenizer、上下文拼接／边界规则和有效目标 token mask。主指标可设为全评价集有效目标 token 的总 NLL 除以其数量，明确使用自然对数；perplexity 为该均值的指数。不要把不同长度 batch 的均值不加权平均，也不要把 padding 算入分母。文本生成示例可用于查错，不能替代留出集指标。

**B：** 明确一次任务成功的判定、分母、每题采样数 $k$、解码参数、最大生成长度、stop 和解析版本。若主指标是单次生成正确率，格式失败／截断／未解析都保留在分母，另报分类计数；基础设施失败须记为缺失／失败并按预注册规则处理，不能悄悄删除。pass@1、至少一次成功的 pass@k、多数投票和挑最好答案不是同一指标。人工或模型评委须另有盲法、顺序、版本和成本合同；没有合法资源时不要选择依赖付费评委的课题。

两条路线都预先指定一个或多个退化监测项；“主指标提升”不自动推出通用能力提升或更安全。图表必须能由原始记录生成，横轴标真实步数／token／设备时；没有运行就不画训练曲线。

### 5.2 多 seed，而非最好 seed

本项目的正式对照默认预注册 **四对独立运行 seed**。一对包含基线与实验组，尽可能共享初始化、数据划分和外生随机因素；不同对独立。数据划分固定时，结论是对该划分的条件结论。B 同一基座不代表四次后训练完全相同，仍应记录采样、顺序和执行非确定性。

逐 seed 报告主指标、配对差值、实际成本、终止原因及是否完成；至少给均值与**样本标准差**。置信区间必须写明重采样单位或分布假设，不能把同一模型的几千个 token、每题多个回答或相邻 checkpoint 当成几千个独立训练实验。有限测试样本带来的不确定性与 seed 间波动分别讨论，具体方法见指导页。

只负担得起一至三对时，可以诚实交付可行性／探索记录，但不冒充本合同的正式多 seed 比较；若所有 seed 都失败，完整失败报告也可以验收为失败审计。不要只报告幸存者的平均成绩。

**验收：** 已冻结的选择规则只看开发集；最终测试在方法与分析冻结后用于预先登记的最终评测，不再据此调参。无法做到时，收缩“独立泛化”主张，而不是重命名文件掩盖使用历史。

## 6．交付五：负结果、工件和最终报告

### 6.1 每次尝试都有归宿

| 观察状态 | 合理交付 | 不能声称什么 |
|---|---|---|
| 许可／能力／预算门未过 | 设计审查、证据与停止理由 | 已完成训练比较 |
| 实现或测量合同错误 | 失效定位、受影响 run 清单、修正版本 | 原结果支持算法结论 |
| 完成对照但差值不确定 | 所有 seed、区间、效应大小与局限 | “没显著”就证明完全无效 |
| 稳定退化或失败 | 失败模式、成本和可复现条件 | 必须藏掉才能算完成 |
| 有支持的改善 | 条件化结论与完整证据链 | 已在所有模型／数据上成立 |

**验收的是研究过程与证据，不是必须赢过基线。** 失败和负结果不免除版本、预算、污染与工件要求；设计审查也不冒充实验结论。

### 6.2 最低可复现工件

提交一个索引，能从报告的每张表定位到：

1. 问题卡及修订历史、许可与数据划分台账；
2. 本人编写的研究代码版本、环境锁定文件、硬件／驱动、实际启动参数和 seed；
3. 每次尝试的唯一 run ID、配置哈希、开始／结束时间、资源用量、状态与异常；
4. 原始逐步日志、逐样本评价记录、解析失败记录、汇总和绘图步骤；
5. checkpoint／分词器身份，以及必要的优化器、调度器、随机数、数据游标状态；允许公开的工件才公开；
6. 从干净环境重建输入、恢复中断、重算指标的操作说明和依赖；
7. 实际复现了哪一层、在哪台设备、允许何种容差，哪些层尚未复现。

“有一个 seed”“给了权重”“脚本能启动”都不是全部复现。区分**由保存预测重算数字**、**恢复同一次运行**与**独立重跑训练结论**；不保证跨设备 bitwise 一致。完整重训无预算时明确记录，不能声称已经完成。

### 6.3 最终报告结构

按以下顺序写，而不是把实验日志原样粘贴：

1. 一句话问题、主预测和研究边界；
2. 为什么选择 A 或 B，基线和唯一主变化；
3. 数据／模型身份、权限、防污染与已知访问限制；
4. 预注册评测、seed、成本和停止规则，以及全部偏离；
5. 真实结果表、逐 seed 差值与不确定性，或未运行／失败状态表；
6. 机制诊断、竞争解释、负结果与不能推出的结论；
7. 复现索引、实际检查记录、未覆盖的复现层级；
8. 在**已有预算内**最值得区分的下一问题；它是讨论，不是自动授权新实验。

**最终通过条件：** 一位未参与研究的人能指出你的主变量、重建样本分母与预算、定位所有失败 run、用合法工件复算报告；结论强度不超过证据。没有完整官方实现、代写实验答案、虚构成绩或未经授权计算。
