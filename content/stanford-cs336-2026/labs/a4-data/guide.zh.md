# 指导页的边界

[完整实验说明](#/c/stanford-cs336-2026/lab/a4-data) 保留全部 **13 个任务、27 个字母子问和 71 分**。本页不替学生决定过滤阈值、标注文档、选择正负例、训练分类器、实现去重、写实验代码或完成报告。官方 AI 政策只允许概念与 API 帮助；**没有 Python、伪代码、现成数据流水线或可粘贴的作业答案**。

下面的问题帮助你区分“要求是什么”和“我的证据支持什么”。自拟的集合、账本和二进制数值只是概念练习，不是 Common Crawl 的真实观察，也不能提交成作业实测。

## 1．先分清四个对象

![输入、决策、输出与训练证据](assets/evidence-boundaries.svg)

*编者原创示意：数据处理影响分布，训练结果又取决于固定评估协议；任何一段不能凭下一段的漂亮数字自动成立。图不是实现顺序或最佳配方。*

### 1.1 原始记录、抽取文本、过滤文档、训练 token

WARC 记录中有 URL、时间、响应头和 payload；HTML payload 又有编码、结构与文本。WET 已抽取文本，但仍保留归档记录的元数据。过滤单位通常是文档；精确行去重的单位是行；分词输出才是 token ID。这些层级没有一一对应的数量关系。

例如，一篇多行网页既可能因删除菜单而减少字节，也可能因去重后成为空文档；它是否仍计作“保留一篇”，取决于你清楚声明的输出合同。**不能只报告 `.gz` 文件数变化，就说文档保留率提升了。**同样，2,500 原始 WET 按四份合并产生 625 个文件组，是文件组织，不是只剩 625 篇网页。

可问自己：我正在计数的是压缩文件、记录、conversion 正文、文档、行、字符、字节还是 token？有没有把 HTTP／WARC 头算进正文长度？WARC／WET 比较时，配对依据是记录身份还是仅靠出现顺序？

### 1.2 “质量”至少有六个不同维度

- **语言匹配**：主要语言是否符合目标。
- **正文完整性**：是否抽到了内容，而不只是菜单或乱码。
- **内容适用性**：是否适合特定学习任务／领域。
- **隐私与有害风险**：是否存在不应传播的信息或内容。
- **重复程度**：内容是否已经在语料中大量出现。
- **法律与许可**：抓取、保存、使用和再发布是否有权利依据。

某一维度分数高不能证明其他维度合格。语言识别器不是法律审查器；NSFW 分类器不是隐私检测器；一个罕见但有价值的文档也可能不符合英语 prose 的启发式规则。**MIT 授权的是这份第一方作业文本，不是任何网页的训练权利证明。**

## 2．观察不是装饰：抽样决定结论范围

### 2.1 为什么“20 例”不能当普适准确率

A4 的多项 20 例任务是让你看到真实错误与阈值含义，不是要求用极小样本证明产品级安全。错误率还依赖抽样总体：所有 WARC 抽取文档、只含英文的文档、发生过替换的文档，与最后保留的数据是不同分布。

**自拟概率练习：**若某类错误的真实发生率为 5%，在独立同分布的 20 次观察中一次都看不到的概率为：

$$
P(0\text{ errors})=(1-0.05)^{20}
\approx0.3585.
$$

所以“20 条都没看到问题”仍可能发生在并不罕见的错误率下。这个计算依赖独立同分布；同一站点的相邻网页高度相关时，20 条的有效覆盖可能更差。它不是对本作业任何分类器实际错误率的估计。

A4 对 PII 特别指定 **20 个发生替换的随机例子**。这种条件采样适合观察替换是否正确，但不能代表没有任何命中的文档里是否存在漏检。相反，最后检查的 **5 条保留＋5 条删除／修改**要求查看两侧，避免只看“喜欢的结果”。这些小样本都不能替代全量计数。

### 2.2 不复制真实伤害，也能保存审计价值

报告需保留足够的上下文来判断错误机制，但不必公开真实联系方式或大段攻击内容。对外展示可用匿名化片段，说明做过编辑；内部记录用受控文档 ID 指向自己合法取得的原始证据。不把“未展示全文”写成“原文没有问题”，也不把编者自拟例子伪装成随机抽样。

官方允许跳过不愿阅读的网页。若因此改变了采样，应如实说明，而不是以继续阅读令人不适内容作为完成任务的必要条件。

## 3．抽取与语言：先理解接口里的承诺

### 3.1 bytes 与 str 是两道问题

编码决定原始字节怎样变成字符；HTML 抽取决定哪些字符是正文。UTF-8 解码成功不意味着正文正确，乱码消失也不意味着菜单被排除。Resiliparse 的 `extract_plain_text` 需要字符串，而本题 adapter 接收 bytes；其 `detect_encoding` API 解决的是编码推断，不负责识别语言或网页质量。

可以用概念问题自查：一份纯导航页能否完全正确地解码？同一网页在两个提取器下，哪种差异属于内容选择，哪种属于空白布局？如果唯一可见内容是登录提示，这意味着提取失败，还是网页本身没有可访问正文？这些问题应回到你观察的真实例子作答，本页不预写结论。

固定提取测试对一个 fixture 做字符串相等检查。通过它至多表明该例输出相符，不能涵盖所有编码、HTML 破损与网页布局。

### 3.2 分类置信度不是领域内正确率

fastText 输出一个标签和分数。分数是模型在其训练和计算约定下的预测量，不自动等于“在当前 crawl 中，该预测有同样百分比正确”。对短文本、混合语言、导航文字、转写和专业术语，是否可信仍需证据。

另外，**预测标签的分数**和**某一指定标签的概率**不能混称。若接口返回非英语及其高置信度，把这个数直接解释成 P(English) 就改变了变量含义。A4 前期语言观察要求你讨论合适阈值；最终 English-WET 预处理的规则则已经固定为 P(English) ≥0.7。这是不同阶段，不能用前者观察去重新定义后者输入。

接口导航：`run_identify_language` 的正常测试标签为 `en`／`zh`；API 文档中的标签前缀、模型内部 ID 与作业接口 ID 可能不同。理解映射不等于得到具体实现。

## 4．掩码与有害内容：局部正确不等于整体安全

### 4.1 为什么必须返回“替换次数”

修改后的文本告诉你结果，替换次数告诉你此次操作的规模。输入原本就含 `|||EMAIL_ADDRESS|||` 时，已有占位符不是这次新增替换，不能把占位符总数直接当新检测数。文档级“是否有替换”和实例级“替换几处”也不是同一个统计量。

这只是接口语义，不提供 email／phone／IPv4 的正则。三个指定掩码类别没有穷尽姓名、住址、账户等敏感信息，测试通过不能被改写为“PII 已彻底清除”。美国电话号码的格式兼容性也不能推出全球电话号码召回。

**检查问题：**误报和漏报各以什么为真值？一处疑似联系方式在合法技术说明里与在个人联系页里，为什么需要不同语境解释？掩码后是否改变了文档结构、分类分数或近似重复关系？这些都是你需要据实际数据分析的风险，不是预先替你写好的 `mask_pii(d)` 回答。

### 4.2 两个安全分数不是一个“道德分数”

NSFW 与 toxicity 的标签空间不同；含专业讨论的文档、引用他人言论的文档和直接攻击性的文档，不能只靠词面作同一种判断。A4 使用的 Dolma 分类器训练来源是 Jigsaw 评论数据；将其应用到各类网页存在领域迁移问题。

固定测试沿用 Jigsaw 数据里的少量例子，是接口 sanity check，不是“训练之外的盲测”。不能从这些测试中推导精确率、召回率、群体公平性，或论证过滤后的模型不会产生有害输出。本页不提供最佳安全阈值，也不为计分风险子问代拟结论。

## 5．规则与学习型质量：分清约束和弱标签

### 5.1 Gopher 子集测的是可解释的文本特征

词数、平均词长、以省略号结尾的行占比、含字母词占比，是四种可核对的统计量。其阈值可以明确复述，但“通过这些规则”不等于内容事实正确。不同分词定义也可能影响同一文本的计数。

边界自查应关注 **单位、分母、等号**：行比例的分母不是词数；含字母的词占比不是字母字符占比；“超过 30%”与“达到 30%”是不同条件。作业指定的是规则子集；不因 Gopher Appendix A 有更多规则就把全部规则当官方强制项，也不悄悄少实现这四项。

### 5.2 质量分类器学习的首先是样本区分

Wikipedia 外链作为正例、随机 CC 作为负例，是一种**弱监督定义**。它观察的是被某种来源引用／收录的关联信号，而不是获得了逐篇人工“好／坏”的绝对真值。分类器可能区分文风、站点与主题分布，也可能学到与任务质量有关的信号；需要由学生自己的实验辨别。

因此在概念上应分清：

- “来源标签”与“目标质量判断”。
- “参考 URL”与“采集到的实际页面”。
- “训练分类器”与“调用一个预训练模型”。
- “两个 sanity-check 例子正确”与“对整个 CC 泛化”。

本站没有指定抽样规模、划分、特征、训练参数或阈值，也没有给替代模型。A4 `quality_classifier(a)` 的实质交付是**学生自己训练的 fastText 分类器**；把函数签名填成固定标签、或用规则返回值假装分类概率，不是实现该任务。

## 6．去重的三个层次不能合并

### 6.1 精确行去重：“唯一”不是“留一次”

集合去重常说“保留每种元素一份”，但 A4 的行级合同说“仅保留全语料出现一次的行”。二者目标不同。若某一菜单行在很多网页出现，后者删除它在所有位置的出现，而不让随机一篇网页继续携带那份菜单。

哈希减小计数键的体积，但不神奇地消除哈希碰撞，也不把行级相等变成语义相等。行末空白、换行约定和文档边界会影响“哪两行相同”的含义；学生应理解自己的合同并自行检查，而不是只看最终文件更小。

### 6.2 MinHash 的估计与 LSH 的候选

文档的词 n-gram 集合是比对对象；MinHash 签名是压缩表示；LSH 是候选生成机制。三者回答不同问题。为理解 band 概率，可用独立哈希的理想化模型：设真实 Jaccard 为 $s$，每 band 有 $r$ 个位置、共 $b$ 个 band。

$$
P(\text{one band matches})=s^r,
$$

$$
P(\text{at least one matches})
=1-(1-s^r)^b.
$$

这是**进入候选集合的概率**，不是最终阈值，也不是输出“重复”的可信概率。真实哈希家族只近似这些理想假设。

**自拟小例：**仅为理解曲线，令 $s=0.5$、$b=3$、$r=2$，候选概率是 $1-(1-0.25)^3=0.578125$。此数不是 A4 推荐设置，不是重复率，也不是把 57.8% 当作阈值。即使生成候选，A4 仍明确要求计算**真实 n-gram Jaccard**；没有碰到同桶的文档也可能是漏掉的高相似对象。

“同一个 band 匹配”中的 band 身份不能省略。两个片段恰好数值相同但来自不同位置，不等于同一 band 的匹配事件。归一化又会改变 n-gram 集合，因此相似度必须说明采用的表示，不能混用一个归一化版本的候选与另一个未经声明的判定含义。

### 6.3 连通簇不是任意两两相似

**自拟集合练习，非文档测试 fixture：**

- $A=\{1,2,3,4\}$。
- $B=\{1,2,3,4,5\}$。
- $C=\{2,3,4,5\}$。

有 $J(A,B)=J(B,C)=4/5$，但 $J(A,C)=3/5$。假设用于讲解的阈值为 0.7，则 A–B、B–C 可构成边，A–C 不构成边；若都成为经过验证的候选边，三者仍属于同一个连通簇。**簇的传递连接不会让所有 pair 的真实相似度自动提高。**

这解释为什么作业要求“跨桶聚类、簇内随机保留一个”与“只删除成对重复中的后一项”不是同一个规范。这里只说明语义，不提供图算法、数据结构或作业实现。最终文本还应区别于比对用的小写／去重音表示；固定测试期望保留的原文内容，不是全部归一化后的文件。

## 7．流水线统计：先问分母，再谈改善

### 7.1 三个有用但不相等的比例

设原始文档数为 $N_0$，第 $i$ 步入站为 $N_{i-1}$、出站为 $N_i$，最终为 $N_f$。在每篇文档只被首次删除步骤归因、且各步只讨论删除的简单账本中：

$$
D_i=N_{i-1}-N_i.
$$

- 该步的条件删除率：$D_i/N_{i-1}$。
- 相对原始输入的删除比例：$D_i/N_0$。
- 对**全部被丢弃例子**的归因比例：$D_i/(N_0-N_f)$。

A4 明确要求每步保留数，以及最后一种丢弃分解；不能只交其中一种比值而不注明。若没有丢弃文档，归因分母为零，应说明“不适用”，不要虚构一个百分比。

**自拟账本：**100 篇经过某步骤剩 80，再经另一项剩 50。删除数是 20 与 30；条件删除率分别是 20% 与 37.5%；相对全部被丢弃的 50 篇，贡献是 40% 与 60%。这些数字是讲解算术，不是 A4 实测。

掩码等“修改但不丢弃”的操作应另列修改文档数、实例数或字符变化。若一篇同时命中多种过滤器，独立命中率可以重叠；而顺序执行的首次删除归因只能记一次。换过滤顺序可能改变归因，也可能改变后续分数，故逐步比例不应被无条件解释为每个过滤器的“独立贡献”。

### 7.2 时间外推的自变量是什么

WET 文件大小不同、保留率不同、压缩解码和模型加载成本也不同，所以“一个文件多久×文件数”只是有条件估计。外推到整 crawl 需说清是基于文件、未压缩字节、文档还是 token 的吞吐，并说明并发、I/O、启动成本与数据倾斜。

真实报告应把**观察**与**推断**分开：处理给定输入的 wall-clock 是测量；完整 crawl 耗时是依赖假设的外推。128 `max_containers` 和 524,288 MB 临时盘是源码配置，不是实际吞吐和占用证据。几行本地字符串的概念检查不能验证分布式吞吐、存储容量或网络可靠性。

## 8．token 文件是一个二进制合同

GPT-2 vocab size 50,257 的 ID 能放入 `uint16` 的 0–65,535 范围，但 dtype 必须与 reader 一致。`tofile` 写的是数组裸字节，`.npy` 会带容器头；把后者改名 `.bin` 仍不符合 staff `np.memmap(..., dtype=np.uint16)` 合同。字节序也是跨平台交换时的约定，不由扩展名编码；固定脚本并没有在文件内写自描述 schema。

**自拟储存练习：**文档甲有 3 个内容 token、乙有 2 个，均追加一个 EOS，合计 7 个 ID；按 `uint16` 裸存是 14 字节。此处没有调用 GPT-2 tokenizer，也没有声称这些是假定字符串的真实 tokenization；只在说明**每文档边界和 dtype 会影响计数**。

要区分四个量：文档数、EOS 数、磁盘数据 token 数、训练采样 token 数。staff 的 `get_batch` 随机取长度为 512 的输入与右移目标片段，训练可能重复覆盖同一段；因此一个文件不必存有 8.6B 个不重复 token，训练“看过 8.6B”也不说明数据集有那么大。

手册逐行 tokenizer 示例假设输入按文档组织；真实多行文本不能未经判断变成“一行一个文档”。原始 WET 元数据、文档内换行和 EOS 是三类不同边界，需由学生自己的数据表示保证一致。

## 9．数据-only 比较与验证的边界

### 9.1 什么必须固定

A4 比较的是数据方案，所以约 430M 模型、GPT-2 tokenizer、上下文 512、八张 B200、每卡 batch 128、16,384 步、优化器和 staff training procedure 都不应被改成其他预算。把模型缩小、训练变长、切到不同 tokenizer 或修改验证集，可能降低 loss，却不再回答同一道作业问题。

输入数据变了，磁盘 token 数和重复使用程度可能随之变化；这正是需要解释的数据效应。不要将“训练步数相同”等同于“看过同样多的不同文本”，也不要把所有变化都归因为质量分数。

### 9.2 看过验证集不等于可以训练它

A4 明许观察 Paloma C4 100 来构造过滤器；该许可**不允许将验证正文放入语言模型训练**。针对验证目标优化数据分布，与复制验证答案／文本是不同事情。大量迭代之后，这份验证集也不再是完全未参与开发的独立测试；结论应限于已声明的协议。

有关跨 split 比对与污染审计的更完整背景见 [L12 评测协议](#/c/stanford-cs336-2026/lec/lec12) 和 [ext13](#/c/stanford-cs336-2026/lec/ext13)。文档内／跨文档去重并不会自动完成训练—验证去污染；未检测到重合也不证明所有泄漏不存在。

### 9.3 最佳观测、最终模型、最佳 checkpoint

这三个对象在固定代码中**不等价**：

- best validation loss 是日志中记录到的最佳验证观测，须连同学习曲线报告。
- `save_checkpoints=False` 是默认值；周期验证分支只有在启用保存时才写中间权重。
- 最终 `model.pt` 会保存，但它是最终训练状态，不自动就是发生最佳验证观测那一步的权重。

因此不应把“最佳日志值”写成“已保存最佳 checkpoint 的成绩”。本页不建议改 staff 脚本来补这种表述；正确做法是诚实描述所提供流程实际记录与保存了什么。评估还会抽样 batch，最佳观测可能受到采样波动影响；报告数值精度不应被当作统计确定性。

perplexity 与交叉熵 loss 相关，但不是同一个数字。若 loss 使用自然对数，perplexity 为 $\exp(\text{loss})$；比较前需统一 tokenizer、数据和指标定义。生成几个通顺样例不替代验证曲线。

## 10．在运行之前，先辨认访问层级

以下是源码静态阅读结论，不是通过试跑得到的故障记录。

| 看上去的承诺 | 代码中必须先面对的条件 |
|---|---|
| “offline-only” | 仍下载验证集、示例 WARC／WET 与三个分类器；且先导入有 SUNET guard 的模块 |

## 11．自测：只检查概念，不替答作业

### 问题

1. 某步删掉入站 80 篇中的 30 篇，它在所有 50 篇丢弃中的贡献是多少？这两个比例为什么不同？
2. 在理想独立模型中，真实错误率 5%，观察 20 次未见错误，能否证明错误率为零？
3. 两文档共享一个 LSH band，是否可以在本作业里直接认定重复并删除？
4. A–B、B–C 都超过某阈值，是否推出 A–C 也超过阈值？
5. 两文档分别有 3、2 个内容 ID，每篇加一个 EOS，按 `uint16` 裸存，ID 数与字节数是什么？
6. “最佳验证日志值”是否必然对应一个保存好的 checkpoint？
7. README 的 offline-only 是否证明不访问网络、不会触发配置检查？
8. 所有作业 sanity checks 都通过，是否就完成了 25 条／20 例／5＋5 的人工观察和正式训练？

### 参考理解

1. 入站删除率是 30/80＝37.5%；全部丢弃归因是 30/50＝60%。分母描述的是不同总体。这是自拟账本，不是实验统计。
2. 不能；零错误观察的概率约 35.85%，而且真实采样未必独立同分布。
3. 不能；它只是候选。A4 还要求真实 n-gram Jaccard 判定与跨桶聚类。
4. 不推出；连通性具有传递闭包，超过相似度阈值的两两关系一般没有传递性。
5. 7 个 ID、14 字节；没有实际调用 tokenizer，只做整数储存概念计算。
6. 不必然；固定默认不保存周期 checkpoint，最终权重也不自动等于最佳观测权重。
7. 不能；它仍有下载行为和顶层 SUNET 检查。
8. 没有。接口检查、人工调查、流水线计时、token 统计与训练曲线是不同交付，不能互相冒充。
