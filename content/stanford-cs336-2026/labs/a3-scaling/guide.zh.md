# 不要让一条平滑曲线掩盖实验问题

缩放律的难点不只是“选择一个拟合函数”。你首先要知道每个点代表什么：它是否完成训练、用了什么预算、沿什么调度走到终点、消耗了多少 token、loss 属于哪个数据集。没有这些条件，一条看起来很顺的曲线也可能回答错问题。

本页帮助你提出这些检查问题，不替你选择实验配置、求回归系数、计算题目预测值或撰写提交报告。完整题目、所有字段与交付物见 [A3 实验说明](#/c/stanford-cs336-2026/lab/a3-scaling?v=zh)。官方 AI 政策要求所有作业与排行榜实现、实验脚本、图和报告由学生自己完成；关闭 AI 自动补全，不让 AI 写 Python／伪代码或计分答案。

## 1．先区分两条证据链

![A3 的两条证据链与最终提交边界](./assets/budget-evidence.svg)

图为编者原创协议示意，不是实验结果或基准图。上半对应给定的合成 FLOPs 数据，下半对应真实 wall-clock 预算；它们不能合并成一套“已完成实验”。

**Part 1 问的是给定数据上的方法复现。**模型数量与 loss 已经给出；学生自己解释、拟合、绘图、外推。无需自行训练 72 次，也不意味着这些合成结果经过 B200 API 实测。

**Part 2 问的是受预算限制的实验推断。**你还要面对队列、失败、超参数、训练终点、吞吐差异和外推风险。12 小时是真实探索预算，48 小时是最终预测目标，而不是可以多次尝试的第二个免费查询池。

因此，“CPU 上画出了曲线”“完成 5 分题”“有真实训练证据”“最终配置已提交”“官方最终评测完成”是五个不同状态。

## 2．五个量不要混成一个“规模”

| 量 | 应明确的含义 | 常见误读 |
|---|---|---|
| 参数量 $N$ | 总参数还是非 embedding 参数；哪个架构族 | 把模型宽度当参数量；把同参数量当同吞吐 |
| 训练 token 数 $D$ | 实际训练多少 token；固定数据顺序 | 把 corpus 大小、字节数、epoch 当已见 token 数 |
| 计算量 $C$ | FLOPs 的计数约定与近似条件 | 把 FLOPs 当 FLOP/s；把算术量当耗时 |
| 时间 $T$ | 单 B200 的哪一段 wall-clock、如何结算 | 把排队日历时间当 API 计费时间 |
| loss $L$ | training 或 validation；终点还是局部值 | 把 failed 的最后一条曲线点当完成结果 |

### 2.1 为什么固定 FLOPs 不等于固定时间

handout 的 $C\approx6ND$ 是训练计算量近似，不是硬件速度模型。将计算量变成时间，还需知道实际有效吞吐；后者会随模型形状、batch、精度、kernel、内存和调度变化。

所以同一 $N$ 与 $D$ 未必得到同一耗时；同一耗时也未必处理同样多的 token。不能用 B200 的某个峰值 FLOP/s，未经实际证据就把整份 12 小时／48 小时作业改写成恒定 FLOPs 预算。完整的资源口径见 [ext04 资源账本](#/c/stanford-cs336-2026/lec/ext04)，计时边界见 [ext06 性能测量](#/c/stanford-cs336-2026/lec/ext06)。

### 2.2 参数近似是工具，不是模型身份

题目提供 $12n_{\mathrm{layer}}d_{\mathrm{model}}^2$ 估算非 embedding 参数。它便于交流量级，却不能完整描述门控 FFN 的宽度、embedding 是否共享、投影 bias、额外 Q/K norm 等差异。

如果两个配置写着相似的参数量，仍要追问：它们的深宽比、激活内存、训练步耗时和优化难度是否相同？“模型大小相同”只控制了一个摘要变量，没有自动控制整个实验。

## 3．观察到的最低点，不是已证明的连续最优点

Part 1 的每档预算只含有限个候选模型。题目建议取其中观察 loss 最低的 run；这个选择的含义是**在已观察候选中最好**。它不证明所有可能参数量中没有更好的点。

理解这一区别时，可以想象沿一座山谷仅测了几个位置的高度：最低的测量点属于数据；真实谷底的位置还受测点间距、观测噪声和谷形假设影响。加入一条二次曲线等于增加模型假设，不是从已有数据中无代价地获得精度。

因此，Part 1 不应把论文的连续最低点处理默默塞进题目的观察最低点流程；方法可以讨论，但必须透明说明自己实际采用的规则。观察极小值若落在采样边界，意味着什么？曲线在相邻点差别很小，又意味着什么？这些是解释可信度的问题，不是这里给出所需最优点的理由。

### 3.1 两幅图承担不同的证据任务

- 模型规模图说明每档预算下采用了哪个模型规模点，以及你如何描述其跨预算变化。
- 数据规模图说明相同预算约束下，对应训练 token 规模如何变化。

原始 run 的 loss 图可以帮助理解 profile，但**不能替代**题目指定的这两幅规模—预算图。若绘图只显示拟合曲线而不显示所用点，读者无法判断模型是否在观察区间内就偏离数据；若只画到最大已观测预算，又没有完成题目的外推范围。

这里不列数据中的最低点、不算回归、不提供 $10^{23}$／$10^{24}$ 的答案；请由你独立完成。

## 4．拟合之前，先问“误差在哪里”

在双对数坐标中，幂律看起来像直线，这只是函数表示的性质，不自动决定最佳估计方式。以原始量的误差为准，与以对数后的误差为准，对不同尺度的数据赋予的实际影响不同。

概念上需要区分：

1. **数据误差**：有限验证集、初始化、训练不稳定或离散候选选择造成的变化。
2. **模型误差**：选择的函数族无法描述真实关系，例如不同区间出现不同趋势。
3. **协议误差**：混入未完成 run、不同终止调度或不同 loss 定义。这类错误不是多加一个拟合参数就能修复。
4. **外推误差**：观察范围之外，原有关系是否仍然成立；拟合区间内残差小并不提供保证。

### 4.1 为什么 loss 下限值得注意

语言建模 loss 不会因为预算无限增大就自动降到零。若使用有下限的模型族，下限与“还能够通过增加模型／数据改善的部分”需要分开理解。观察区间很窄时，多组下限与增长规律可能在区间内几乎重合，却在远处预测不同。

这叫**可识别性**问题：不是优化器没有努力，而是现有观测没有足够信息区分这些解释。换优化器、添加小数位、报一个更漂亮的拟合分数都不能凭空增加证据。具体统计背景见 [ext12](#/c/stanford-cs336-2026/lec/ext12)；这里不替你选公式或拟合方法。

### 4.2 好看的拟合图还缺什么

自己审视报告时，可以问：残差是否随预算、模型规模或训练时长呈系统性变化？某一类配置总在曲线同一侧吗？如果去掉一个极端点，结论是否大幅改变？预测目标距离已观测范围有多远？

这些问题用于说明证据强弱，不是新增官方“必须交多少张图”的规定。Part 2 要求解释拟合质量，但没有指定统一图数、统计阈值或回归器。你需要自行选择适当证据并承担其假设。

## 5．12 小时预算是一个预留账本

预算限制发生在**提交／排队时**，不是只在运行完成之后。一个仍在队列中的长任务也会占用余额，因此“GPU 看起来没有开始做事”不代表你还能继续预留全部 12 小时。

### 5.1 独立算术例：预留与结算

这是编者的虚构记账例，不使用官方数据，不调用 API，也不是实验分配建议：

- 假设某学习服务总预算为 **100 秒**。
- 一个任务预留 **40 秒**，等待或运行期间可用余额为 **60 秒**。
- 若任务以 **25 秒**完成，结算后可用余额是 **75 秒**。
- 若任务超时，仍按 **40 秒**结算，余额仍为 **60 秒**。

这个例子只说明“预留额度”和“最终用量”不同；它不包含任何缩放律拟合或性能结论。A3 实际总预算是 43,200 秒，且完成／失败的实际用量截在该 run 的 $[1,\text{上限}]$ 范围内。

### 5.2 做决策前值得回答的问题

在你自己设计 run 时，先问这次观测要区分哪些解释：模型容量不够、训练 token 不够、学习率不合适，还是时间被系统开销占据？如果同时改变许多因素，即使 loss 改善，也未必知道原因。

还要想清楚：预留时限与计划 token 数能否描述同一个可完成实验？局部失败之后，剩余预算是否足以回答原问题？是否把某一类特别短的任务误当作大规模任务的等比例缩小？

这些是实验设计问题，而不是本站替你制定的搜索计划。这里不提供预算分配比例、参数网格、学习率建议或自动提交流程；也不为了“补足观察”要求启动额外实验。

## 6．训练终点与曲线上的中间点不同

固定代码按 `n_evals` 将总 token 数分为等长 chunk，每段后验证一次。优化器调度长度根据计划总步数确定。

设两个实验经过了相同的 token 数，其中一个计划在此结束，另一个计划继续训练很久。即使架构、数据和种子相同，它们此时的学习率历程也可能不同。因此，“长实验的中间点”未必等价于“以这个 token 数为终点单独训练”的结果。

这是缩放实验中很容易漏掉的控制变量：**训练了多久**和**原计划训练多久**都可能影响当前状态。不能只截取曲线的一段，就默认它是一个独立的、完整短训练样本。

### 6.1 timeout 不是廉价 early stopping 结果

完成任务的最终 loss 是 `status.val_losses` 的最后一个；timeout 可能留下 `status.reason.partial_val_losses`。后者提供诊断信息，但计划终点、学习率终点与总训练 token 数都没有按原计划实现。

如果把失败 run 的局部值直接投入“完成训练的最终 loss”列，改变的不是缺失值处理，而是数据的含义。你可以讨论失败与局部曲线，但必须保留其状态，不把它们冒充完成样本。

### 6.2 为什么 n_evals 也影响测量口径

`n_evals` 不只是报告多画几个点。每一轮都要在固定验证集上评估，而 worker 的训练计时包含这些 chunk 与验证。提高评估频率会改变时间账本；这不等于它改变了每个 token 的理论训练 FLOPs。

同时，A3 的验证样本是固定的。多评估几次不等于多获得几份独立验证集；多个曲线点还共享训练轨迹。把这些点当作独立重复实验，会高估证据量。

## 7．固定数据顺序与不确定性

固定数据顺序让配置之间更容易比较：差异不是随意换了一份训练语料造成的。但“固定”不等于“没有随机性”：模型初始化可变，数值路径和实验环境也应有清楚记录。

`model_seed` 不会更换训练／验证数据。在这个协议下，重复初始化能帮助理解初始化敏感性，却不能直接说明换一份语料、换一个 tokenizer 或换分布之后结果怎样。

另外，探索阶段每次验证用 $2^{18}$ token；最终 leaderboard 使用更多 token。更大的验证样本通常改变估计精度，但这并不授权你在没有证据时宣称最终 loss 必定降低。报告应区分**模型本身的预测**与**用于估计它的验证协议**。

### 7.1 只保留最好的结果会丢失什么

搜索过程本身会制造选择效应：你看到的最小值不仅来自模型能力，也受到候选数量与观测变化影响。只记录“目前最好”而丢掉其他 run，会使读者无法理解搜索成本、失败模式与选择依据。

这也解释了为什么原题要求完整方法和设计决策，而不只是一个最终数值。证据记录应让你能区分实际观测、拟合结果与最后选择，不能把三者改名为同一个“最优模型”。

## 8．从预测参数量回到合法配置

一个连续的规模预测还不是可提交的训练配置。真实配置有整数层数、整数头数、偶数每头维度、MLP 宽度、固定 tokenizer，以及训练／验证 batch 的整除要求。

需要理解的不是“把数字四舍五入就行”，而是**统计模型的自变量**与**API 允许的配置空间**之间有一层映射：

- 宽度必须等于 attention 头数乘每头维度。
- KV 头数必须与 attention 头数相等；这个版本不能靠 GQA 绕过资源问题。
- 总 token 数、每步 token 数与评估次数共同决定合法的整步训练。
- `vocab_size` 字段存在不代表可以自由换掉固定 Llama-2 tokenization。
- dtype、架构形状与 batch 会影响实际时间；相同参数量不保证相同 48 小时可行性。

这些是约束解释，不是给你一个合法且“最优”的组合。完整条件在 [实验说明 §2](#/c/stanford-cs336-2026/lab/a3-scaling?v=zh)。你应在自己的报告中说明选用的配置如何对应所讨论的参数量口径，而不是把近似预测当精确构造证明。

## 9．证据记录与诊断问题

下面是记录**类别**，不是可提交报告模板或自动实验脚本。自己的分析至少需要能分清：

| 类别 | 要避免丢失的信息 | 它回答什么 |
|---|---|---|
| 实验身份 | 固定代码版本、自己的配置、实验 ID | 这个点究竟来自哪次请求？ |
| 预算 | 请求上限、预留／实际结算、时间单位 | 是否把排队时间当训练成本？ |
| 状态 | 完成／失败／超时、对应原因 | 该点有完整终点吗？ |
| 训练协议 | token 数、batch、n_evals、种子、调度 | 是否在比较同一类实验？ |
| 测量 | loss 序列及 training／validation 定义 | 这是观测还是预测？ |
| 推断 | 自己采用的方法、范围、假设和不确定性 | 结论依赖什么？ |

**不要记录到公开材料里的内容：**Stanford ID、API key、身份请求头、数据库口令、第三方 token、私人学生名册。官方打包脚本会排除 JSON／文本／日志等格式，但这不是完整的保密检查，也不能替你确认分析证据是否齐全。

### 9.1 常见现象：先检查含义，再改拟合

| 现象 | 优先追问的问题 |
|---|---|
| 看似还有很多时间却无法提交 | 余额是否已被 queued／running 任务完整预留？ |
| 状态 running 比时限更久 | 是否混淆派发、启动／抢占与 worker 训练计时？ |
| 大模型 loss 异常差 | 训练是否完成？总 token、调度终点、优化器与显存条件一致吗？ |
| 曲线很平滑但远处预测激进 | 预测是否远超观测范围？近似与下限是否可识别？ |
| 同参数量配置耗时不同 | 形状、batch、精度、kernel 和评估开销是否不同？ |
| final submission 成功，却没有新训练结果 | 是否把保存预测记录误认为提交探索任务？ |
| 非学生按 README 本地运行受阻 | 是否忽略 Modal call ID、staff namespace、数据与内部服务依赖？ |

没有上述诊断的实际日志时，不应认定某个原因已经发生。本页给的是可核查问题，不是伪造的故障复现记录。

## 10．自测：只检查概念，不回答计分题

### 问题

1. 两个模型理论 FLOPs 相同，能否断言它们在单 B200 上耗时相同？
2. 一次任务预留 40 秒、实际 25 秒完成，虚构 100 秒预算还剩多少？若超时又如何？
3. `model_seed` 改变后，是否获得独立重排的 DCLM 数据和新验证集？
4. 某 run 失败前最后一次验证 loss 很低，它是否自动成为最好的完成 run？
5. 最终配置已被 `/final_submission` 保存，是否说明已经免费跑了一次 48 小时模型？
6. 数据生成器的 $2^{29}$ validation pool 是否意味着探索评估每次读完这个池？
7. 只把 72 条合成 run 拟合得很好，能否称 50 分任务已完成？
8. TrainingConfig 有 KV 头数字段，是否允许当前 API 使用 GQA？

### 概念答案

1. **不能。**理论算术量没有包含实际吞吐随配置变化的效应，也没有完整描述时间边界。
2. 完成后剩 **75 秒**；超时按 40 秒结算，剩 **60 秒**。这只是独立记账例，不是官方服务结果。
3. **不会。**该字段只控制模型初始化，数据顺序与验证协议固定。
4. **不是。**失败的局部曲线必须保留失败语义，不能冒充完整计划终点。
5. **不是。**该端点保存预测；探索训练与官方最终评测另有流程。
6. **不是。**探索配置固定用 $2^{18}$ token；存储池与实际评估用量是两个层次。
7. **不能。**那是 Part 1 的合成方法练习；Part 2 需要真实 API 实验与 48 小时目标预测。
8. **不允许。**固定版本明确要求 KV 头数等于 attention 头数。
