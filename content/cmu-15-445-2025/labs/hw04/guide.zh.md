# HW4：从页访问推到行数估计｜无答案指导

在纸上画一棵连接树。**边上写流过多少行，节点旁写为处理这些行付了什么成本。** 千万不要把二者写进同一个格子：连接只输出少数几行，也可能把两侧输入扫了许多遍。把[原卷要求与页码](#/c/cmu-15-445-2025/lab/hw04?v=zh)放在旁边，需要数据时从那里找到英文题面。

## Q1(a)–(c)｜哪一次循环会把内表重新读一遍？

画两个游标，一个指外表，一个指内表。先在纸上把内表游标拨回开头一次，问：**刚才耗尽的是外表的一行、一页，还是装在内存里的一批页？** 本题按页收费，不按比较次数收费。

1. **(a) 逐行。** 外表页数乘每页行数，量纲才是“行”；内表读一遍的量纲仍是“页”。账本分两列：读外表本身，以及重启内表扫描。不要把两个表的行数相乘直接报成 I/O。
2. **(b) 逐块。** 画出 $B$ 个缓冲槽，先给当前内页和输出各留一槽。用余量把外表页分批；最后一批哪怕没有装满，也是一次独立扫描。把账本写成“外表读取 + 外表批数 × 内表页数”。
3. **(c) 换边。** 复制一张空账本再填。交换两侧会同时改变**批数的分子**与**每次扫描的长度**；不能只交换公式里的一个字母。两个方向处理的是同一个等值连接，逻辑配对数与访问次序是两回事。

自查：如果恰好只差一页就能把整批放进内存，会多哪一笔读？如果外表行数不变、只是每页装得更紧，(a) 与 (b) 哪些栏可能改变？能回答这两个问题，再用原题数据。

## Q1(d)｜排序的归并，与连接的归并，是哪两份账？

**(i)、(ii)：给每个输入单独画一棵 run 树。** 初始一轮把最多 $B$ 页读入内存排序，写成一个有序段（run），所以页数为 $S$ 的输入有 $\lceil S/B\rceil$ 个初始段。一轮多路归并要留一页给输出，其余槽各喂一个输入段。逐轮写下“本轮开始时的段数 → 本轮结束时的段数”，直到只剩一个段。一轮读完并写回所有页，就各记一次读、一次写。小心区分**段的个数、段的页数、全表趟数**；不要为本题私自融掉末轮排序写回，再同时按独立排序阶段计费。

**(iii)、(iv)：两列有序的键现在已在面前。** 分别画出一种同键匹配段跨多页的序列和一种键无重复的序列。在每条序列上标“推进左游标、推进右游标、回到匹配段起点”。先问需要重扫哪些页，再计数。在最坏估算中，沿用课堂按页重读匹配段的模型；不要把输出配对的数目、CPU 比较次数当作页读次数，也不要悄悄假定重复组都能驻内存。两问都已过排序阶段。

**(v)：剪去树的下半截。** 用一个新的输入框代替已经产生的 $Y\bowtie Z$，在框上写其**给定**大小与单位。圈出根节点，写出它现在读的两份输入，再问有哪些费用属于树的下面而不属于这次 merge。自查：若有人改了原始两表的大小，但维持中间结果大小、与根有关的输入顺序和重复条件不变，你的最后阶段账本会无缘无故改变吗？

## Q1(e)–(g)｜哈希分区的代价取决于什么？

**(e) 分三列做流水账：** 第一次从哪读 → 分区时向哪写 → 哪些分区页要重新读来建表或探测。跟踪两侧各一页，从头走到尾。忽略尾页未满，只是不另加浪费；忽略递归，只是不再开下一层分区账；两种省略都不是“临时分区免费”。

**(f) 比较方案前，先固定碰撞的原因。** 画一对不同键，规定它们在第一轮去了同一个桶。对原题每个方案依次问：第二次做出的分组决定是否有新信息？左右两侧相等的键还能相遇吗？最大建表分区是否可能变小？需要连续扫页，还是要为探测频繁换页？然后再换成“同一热键重复很多次”试一遍，检查自己是否偷换了题设。两种偏斜不同；回答前一种，不要拿后一种直接作证。

**(g) 逐项只记录检验手段，不先排一串真假：**

| 小项 | 在草稿上怎样检验 |
|---|---|
| (i) | 把内存限制画出来；对相邻两条外行，分别追踪逐行和按块算法能否复用同一批读进来的页。 |
| (ii) | 将两表同时驻留的情况拆成首次载入、随后重复比较。分别统计磁盘读和 CPU 工作量，再用题目指定的度量比较两个方向。 |
| (iii) | 画一次外行驱动的索引查找，标哪一侧产生查找键、哪一侧接受查找。已有索引和运行时创建临时索引，不是同一份成本账。 |
| (iv) | 选两组条件：两输入已按连接键排序；两输入无序且某侧可建表。分别列预处理与后续工作，用来检查原句的量词。 |
| (v) | 在图上只写 **build**（持有哈希表）、**probe**（流过并查找）。对内存哈希、外部分区哈希各画一幅，再把原题 *inner* 的叫法映射过来。课堂 L12 的 basic hash join 把 *outer* 叫 build；物理角色和左右位置不是同义词。 |
| (vi) | 分五栏：循环重扫、已有次序的价值、何时需要排出次序、批数随缓冲变化、索引探测的前置条件。每栏各自检验后再处理组合候选；特别区分“进入 merge 时有序”与“基表必须预先排好”。 |

## Q2(a)–(f)｜把关于执行的命题变成小实验

用 [L13 的订单／库存执行轨迹](#/c/cmu-15-445-2025/lec/lec13?v=notes)做草图：`Orders(id, sku, qty)` 扫描后筛选，再与 `Stock(sku, depot, on_hand)` 匹配。以下每次只改变一个条件，不把这个自拟场景当作 HW4 的数据。

| 小项 | 推演与自查 |
|---|---|
| (a) zone map | 为两页分别写一对可信的最小／最大值。试画一个只能排除部分页的筛选，再画一个由所有页摘要就能确定的查询；说明是否还缺可见性、NULL 信息或具体元组。同样叫“跳过读堆”，能证明某页无候选和能给出精确查询结果并非同一个要求。 |
| (b) 多索引 | 对 OR 的各分支先画索引返回的行标识集合，再画并集、去重和回表。试让命中的行集中在少数页，或散布在很多页；把索引访问、堆页访问同顺扫的总代价比较。行数很大不是代价公式，且“少量命中”指输出比例小。 |
| (c) 迭代器 | 分别追踪 `扫描 → 过滤 → 投影`、`扫描 → 完整排序 → 投影` 的第一次 `Next`。用向下箭头标请求，用向上箭头标产出；圈出只能攒够输入才有首行的位置。模型允许的流水与每条计划能否全程流水分开判断。 |
| (d) worker | 画进程边界，把一次非法内存访问、一次任务重新分配分别放进去。前者考察失败可能波及的地址空间，后者区分 DBMS 的任务调度与内核给线程或进程分派 CPU。两个比较词须分别有依据。 |
| (e) 查询内并行 | 把一条全表分析拆成片段，再把结果汇集。账本只记这条查询的关键路径：最慢的片段、同步、交换；另开一行记系统吞吐量。换成单盘饱和或分区倾斜时，问哪个瓶颈仍串行。可复用 [L14 的并行时间线](#/c/cmu-15-445-2025/lec/lec14?v=notes)。 |
| (f) 向量化 | 固定所扫列与页集，只改每次交接是一行还是一批。横向比较 `Next` 调用次数、循环分支、缓存利用与 SIMD 机会；另列磁盘页数。用这个受控变化检查“主要原因”，而不把所有提速归到 I/O。 |

## Q2(g)–(k)｜模型、统计和观测怎样分开？

- **(g) 枚举与执行。** 先固定同一批候选计划；给每棵树留两栏：优化器的估计成本、在指定数据和环境下的实际资源消耗或耗时。仅改变统计与真实数据的偏差，问两个排序是否有理由相同。不要拿“有的计划没枚举”回避题目限定的比较集合。
- **(h) 下推。** 在树上标出谓词用到的列、连接键与最终输出列。先证改写不丢列、不改语义，再比较上下游行数、行宽、谓词单次代价和调用次数。试把一个昂贵的谓词放在一个强过滤前后；不要把语义等价当作性能证明。
- **(i) 抽样。** 分别列“建样本时触及什么”“估计时在哪些行上评价谓词”“如何外推到全表”。区分对样本的精确计数与对全表的估计；已有持久样本和查询时临时采样的读取时间也不同。
- **(j) 直方图。** 自画一个热点特别密、尾部很稀的数据分布，先按相同值域宽度切桶，再尝试按相近行数切桶。每次都给桶标上两个数：覆盖区间、容纳行数。只有一个数相同不能证明另一个数也相同。
- **(k) 四个比较维度。** 对偏斜，试把热点放在桶边和桶内，并考虑小样本恰好漏掉它；对任意谓词，问现有桶保存的信息够不够、保留的样本列够不够；对时间，区分建统计的成本与使用已有统计的成本；对类型，让整数列和浮点列具有相同频数形状，检查仅换类型能否支撑结论。逐条依据条件判断，不从一个例子推出普遍排名。

## Q3(a)｜同一对边际比例，可以来自不同的联合分布吗？

给“州命中”记事件 $S$，“城市命中”记 $T$。**(i)** 先把百分数换成比例，独立时用边际概率估计交集，乘表行数，按本小问题意在最后向上取整。自查：交集不能比任一集合更大；取整前的量纲已经是“行”，不是百分比。

**(ii)** 把精确的概率分解写成 $P(S\cap T)=P(T)P(S\mid T)$。只要比较其中的条件概率和你的模型实际使用的概率，就能判断误差会往哪边走。可以画两张边际和相同但交集大小不同的列联表；问州名和城市名之间有没有领域知识能支持“更可能”的判断。两列边际统计本身没有记录实际交集，不能把预期方向写成精确实测值。

## Q3(b)｜逐个算子更新基数，而不是逐项更新数据库

先在私有草稿上做一张统计卡：`关系 → 行数 N → 列及其 NDV → 键约束 → 值域关系`。在均匀模型下，某个**在域内**的普通值的平均频数是 $N/V$，而选择率没有“行”这个单位。同样的两个等式，若落在同一张表，是过滤；若连接两表，是配对。两种操作的分母不是按“看见几个等号”来决定。

| 小项 | 草稿上应留下的推理 |
|---|---|
| (i) | 给 `R4.D` 标出主键。区分唯一性所约束的匹配上界、指定常量是否存在、用均匀模型时作的域内假定。不能用一个 NDV 推出具体取值列表。 |
| (ii) | 顺着外键方向，画子行到父键的箭头；检查主键唯一性对每条箭头的约束、引用完整性对无匹配的限制。反向许多箭头可以落到同一个父键。课堂模型未另给 NULL 统计；不要把“外键”一般化成 SQL 中一律 `NOT NULL`。 |
| (iii) | 回到原始 `R1`，只拿筛选列自己的 NDV 估平均频数；同一表上另一列的 NDV 不能替它当分母。 |
| (iv) | 在 `R3` 的列上把记录分成等于、不等于；若另行考虑 SQL NULL，还需要未知这一组。按原题统计模型做互补检查，别把对面集合的规模交上去。 |
| (v) | 先给两列各估一个边际比例；若用乘法合成，明确写上**额外的列间独立假设**。本小题上方明列均匀与完美重叠，没有提供联合频数；均匀边际本身不足以唯一确定交集。算的是期望行数，不要把小数概率当作行数或自动套用 (a)(i) 的取整规定。 |
| (vi) | 写共有列 $K$ 上的精确配对思路：同一值在两侧分别出现多少次，就贡献两频数的乘积。再用题设均匀和重叠把“逐值求和”化为基数估计；不是在结果中只保留一个不同值。 |
| (vii) | 给第一步结果另起名字，在树边写它的估计行数，以及供下一次连接使用的 $C$ 的 NDV。带着这两个量进入第二步，按本小题对 $C$ 的单独规定检查分母。不要把某个基础表行数重新当作中间行数，也不要把结果名当作列。 |

**关于“完美重叠”。** 第 7 页对 $B,C$ 给的是两侧相同的不同值集合。对 $D$，印出的两侧 NDV 并不相等，还有明确的外键方向。因此不要照着“等等”强行把两侧 $D$ 的 NDV 改成一样；按列分别检查，区分**子集包含**与**集合全等**。这是读输入的要求，不是另加一条外键，也不是某道选择题的判定。

## 不计分的迁移：你会到计划树的哪一个节点查证？

沿用订单例，另加 `Depots(depot, region)`，只取某地区仓库中的大宗订单。假设是内连接，比较“先将筛过 `qty` 的订单与库存连接，再接地区”与“先将筛过 `region` 的仓库与库存连接，再接订单”。在两棵树上先画出连接键和必须保留的列；同一 `sku` 有多个仓库时，不能把一行订单当成只会配出一行。

对每个候选节点写三栏：**估计输入／输出行数、所选物理方法可能读写的页、若能实际执行应观察什么**。先改变某地区的库存占比，再改变大宗订单是否集中在同一批 `sku`；看第一处误差会沿哪条树边传下去。在带执行统计的计划里查那一节点的实际行数，并留心行数是否按每次循环报告。单看普通 `EXPLAIN` 的估计行数不能说“已证实”，代价单位也不能直接读成毫秒。这项是个人延伸练习，不是 HW4 的第四题；本站没有运行这两个候选计划。可接着看[规划 I](#/c/cmu-15-445-2025/lec/lec15?v=notes)、[规划 II](#/c/cmu-15-445-2025/lec/lec16?v=notes)与[公共资料中的计划练习](#/c/cmu-15-445-2025)。
