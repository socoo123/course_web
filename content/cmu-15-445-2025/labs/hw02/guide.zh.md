# HW2：从字节、页集合到编码性质

导航：[全部要求与小题映射](#/c/cmu-15-445-2025/lab/hw02?v=zh) · [L5笔记](#/c/cmu-15-445-2025/lec/lec05?v=notes) · [L6笔记](#/c/cmu-15-445-2025/lec/lec06?v=notes)。本页给检查方法，不给选择项、官方数值或完整解题过程。

## 1. 先分开布局、架构与编码

**页内布局**问字节怎样放：slot数组如何定位tuple、如何处理删除留下的空洞。**存储架构**问修改怎样成为持久数据：原地改页，还是追加新版本后整理。**NSM／DSM模型**问多个属性如何聚合在页上。最后，**压缩**才问这些属性怎样编码。

把这几层混为一谈，会产生“列存必然不支持更新”“slotted page必须保存完整schema”等未经证明的结论。题目限制了哪些层，就只在那些层上比较；不能顺手补一个索引、过滤器或缓冲命中率。

## 2. Q1：用生命周期，不用口号

给草稿画四个阶段：前台修改 → 内存缓冲 → 写出磁盘 → 后台维护。另画一条独立的读取路径。对每个候选判断，定位成本出现在哪一阶段。

### 2.1 两种不同的放大

- **读放大**：为了取得逻辑上想要的数据，实际检查／读取了多少额外内容。
- **写放大**：一次逻辑修改最终导致多少物理写入，包括以后为整理数据而发生的写入。

两者不是同一个指标；顺序／随机是另一条轴，也不是放大倍数。吞吐量、延迟、空间占用不能相互代替。若一个选项提到“更少空间”，先问比较的是尚未整理的状态、整理期间峰值，还是整理后的有效数据。

### 2.2 原创思考场景：Orders的一行变长

只考虑一页中的一条订单备注从短变长，不代入HW2选项。画出原空间、增长部分、slot指向的位置，分别考察“还能原地容纳”和“已经容不下”。然后把同一逻辑更新改成追加记录，标出读取时怎样识别最新值、旧记录何时有机会回收。

练习不是让你实现这两种引擎；它要求你为“写到哪里”“读多少”“何时整理”给出可检查的因果链。

### 2.3 对应Q1三问的草稿模板

| 小问 | 应填写的证据，不填结论 |
|---|---|
| (a)日志结构问题 | 每一候选的前台路径、读路径和后台合并路径；哪种负载触发它 |
| (b)slotted-page问题 | 修改一个tuple涉及哪一页，变长／删除如何改变可用空间；不要漏页粒度I/O |
| (c)比较命题 | 每条命题的量词、忽略项、反例条件或成立前提；仅追加与长期增删改分别讨论 |

对于“只有某方法受益”“总是更小”这类命题，单个支持例不能证明它。反过来，也不要把真实产品的特殊实现当作课程抽象模型的默认实现。

## 3. Q2：先算容量关系，再数不同的页

下面用符号表达通用方法，不代入官方20,000／200的结果。

设表有 $N$ 行、$k$ 个等宽属性，每个属性 $w$ 字节，每页可用 $B$ 字节。忽略额外开销时：

$$
\begin{aligned}
\text{NSM每页行数}&=\left\lfloor\frac{B}{kw}\right\rfloor,\\
\text{DSM每列页值数}&=\left\lfloor\frac{B}{w}\right\rfloor.
\end{aligned}
$$

先检查整除／尾页，而不是把tuple数量当页数。对采用隐式偏移的DSM，若一列每页放 $C$ 个值，零起始行号 $r$ 对应该列的页号为 $\lfloor r/C\rfloor$。**这是行号到页号，不是主键到页号。**

### 3.1 为什么页集合比“行数×列数”更可靠

为某个查询定义：

- $S$：为了决定哪些行匹配，必须读到的页集合；
- $O$：为返回／聚合结果而要取得的其他页集合。

若冷启动、内存足够保留全部读过的页，磁盘读取数量应按需要读入的不同页计数：

$$
|S\cup O|,
$$

而不是默认 $|S|+|O|$，更不是“输出行数×输出列数”。对DSM，页的身份必须包括列名；两个不同列的“第0页”不是同一页。

例如自拟的Stock表，两个候选行号为4和5，每个列页容纳4个值。二者在同一列中可能共享一页；若投影另一列，该列有独立的页。这个例子仅示范集合去重，不对应官方答案。

### 3.2 把三个问题写在不同草稿栏

1. **还不知道哪些行命中**：定位这些行，需要扫描什么？何时有充分证据停止？
2. **已经知道命中行号**：按NSM／DSM布局取哪些属性页？这些页是否已在缓存？
3. **最终输出形成**：聚合是否需要所有候选？是否还要检查并列极值？

主键唯一性是一条逻辑约束，可用于说明是否已经找到全部目标；它不是随机跳转到位置的能力。题面没有额外元数据，因此不能靠一个未给出的最大值边界宣布扫描结束。

### 3.3 内容最坏与排列最小不是矛盾

在纸上画两个框：外框写“必须遵守的内容条件”，内框写“在这些条件下允许的tuple排列”。比较minimum／maximum时移动内框中的顺序，不要改掉外框。

常见错误是看到minimum就选一张“刚好所有结果都在第一页”的表，却没有证明它同时满足内容最坏情况；另一个错误是看到worst case就直接忽略题目明确要求的minimum。

### 3.4 七个小问分别怎么检查

| 小问 | 独立完成时应回答的中间问题 |
|---|---|
| Q2(a)(i) NSM | 谓词和聚合值是否在同一tuple页？没有索引／统计时怎样证明聚合已经完整？ |
| Q2(a)(ii) DSM | 哪一列用于筛选，哪一列用于聚合？如何由命中行号得到后者页集合？内容最坏条件如何限制选择性？ |
| Q2(b)(i)α NSM最小 | 哪种允许排列使定位过程较早结束？为什么停止时不会遗漏另一个目标？ |
| Q2(b)(i)β NSM最大 | 哪种允许排列延迟得到足够信息？读取顺序是否仍满足题目模型？ |
| Q2(b)(ii)α DSM最小 | 定位列与两个投影列如何分账？同列里两个目标是否共享页？ |
| Q2(b)(ii)β DSM最大 | 分散行位置会改变哪一部分页集合？别把每个目标都算成完整扫描一列。 |
| Q2(c)(i) DSM最小 | 子查询得到极值后，哪些列页已经在内存？外层筛选、并列极值及最终MIN还分别需要什么信息？ |

最后才把自算的页数落进该小问的选项区间。若觉得“无法确定”，先检查是否漏用了等宽、无额外开销、隐式偏移等明确条件，而不是因为题面没有给页字节数就停止。

## 4. Q3：检查编码保存了哪些关系

### 4.1 Q3(a)：不要混淆可逆和保序

字典把原值 $v$ 映射成代码 $c(v)$，需要能区分原值并找到解码关系。若希望**直接在代码上做与原值一致的范围比较**，还要检查原值顺序与代码顺序是否一致。uint32只规定表示范围，不规定从0开始、连续编号或没有间隙。

为原PDF每组候选建立三列草稿：原字符串、原始位置、该位置对应的代码。先排原字符串，再观察对应代码，不公布任何一组的判定。课堂的保序字典模型与“先解码后做范围查询”的一般实现是不同问题，不用后者绕开题意。

### 4.2 Q3(b)：排序到底改变什么

不要先背“适合压缩”列表。先分别画出各方案的编码对象，再问排序是否改变它：

| 方案 | 应检查的表示因素 |
|---|---|
| Bit-packing | 需要的位宽，编码块边界，以及是否暗中改变了块划分 |
| RLE | 连续相同值形成的run；一个run的表示开销 |
| Mostly／patching | 主体位宽、异常标记与异常表；不要擅自改变异常阈值 |
| Bitmap | 独特值数量、每张位图长度；题目是否给出了额外的位图压缩 |
| Dictionary | 不同值集合、代码宽度、字典开销；不要把扫描局部性当字典变小 |
| Delta | 基准值与相邻差值、差值的表示方式；不要额外假定数据类型和分布 |

“有时可改进”“对任意输入都严格缩小”“没有变大”不是同一个逻辑命题。按原题提示及课堂模型说明你采用的含义，别用另一个算法的实现细节替代它。

### 4.3 Q3(c)：把绝对词单独圈出

每条陈述先写它涉及的对象：文本／数值、低／高基数、点查／范围、插入／更新。然后分别检查“必要条件”和“常见有利条件”。

- 需要比较哪些关系，才能决定某个性质是否**必需**？
- 一次更新改变一个值、一个run、一个字典项还是整个段？是否有不同实现策略？
- “低基数”描述独特值数量，“连续”描述位置关系；二者不能直接互换。
- 判断“没有开销”时应看维护工作，不只看一次查询的速度。

本节没有给出任何命题的真假；请对照原题全部候选，包括“以上皆非”，独立作答。
